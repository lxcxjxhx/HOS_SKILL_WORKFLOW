# 通用 4D 全流程管线

> 完整 4D 工作流编排：从发现到文档化的端到端内容生产管线。

---

## 1. 执行序列

```
D1 Discover → D2 Dissect → D3 Develop (条件触发) → D4 Document
```

| 阶段 | 名称 | 职责 | 预估耗时 |
|------|------|------|----------|
| D1 | Discover 发现 | 信息采集、趋势扫描、目标筛选 | 30–60 min |
| D2 | Dissect 解剖 | 深度分析、源码阅读、架构拆解 | 60–120 min |
| D3 | Develop 开发 | 代码实现、PR 提交、Demo 构建 | 120–480 min（条件触发） |
| D4 | Document 文档化 | 视频脚本、博客、元数据、封面简报 | 60–90 min |

---

## 2. 各阶段详细说明

### 2.1 D1 — Discover 发现

- **调用**: `hos-discover` 技能集
- **输入**: 用户指令 / 定时触发 / RSS 源
- **输出**: 结构化素材包（标题、摘要、链接、分类标签）
- **质量门**:
  - [ ] 素材数量 ≥ 5 条（周报场景 ≥ 20 条）
  - [ ] 每条素材包含：标题 + 摘要 + 来源链接
  - [ ] 分类标签已标注（pillar 1-6）

### 2.2 D2 — Dissect 解剖

- **调用**: `hos-dissect` 技能集
- **输入**: D1 输出的结构化素材包
- **输出**: 深度分析报告（架构、设计决策、安全模式、性能特征）
- **质量门**:
  - [ ] 包含模块结构图
  - [ ] 包含依赖关系分析
  - [ ] 包含安全模式评估
  - [ ] 包含核心算法解读

### 2.3 D3 — Develop 开发（条件触发）

- **调用**: `hos-develop` 技能集
- **输入**: D2 深度分析报告 + 开发计划
- **输出**: 代码实现 / PR / Demo / 技术验证
- **触发条件（按支柱）**:

| 支柱 | 名称 | D3 是否必须 | 说明 |
|------|------|-------------|------|
| Pillar 1 | 世界AI安全周报 | ❌ 可选 | 仅在发现有趣 PR 机会时触发 |
| Pillar 2 | 源码深读 | ❌ 可选 | 仅在发现贡献机会时触发 |
| Pillar 3 | 纪录片式内容 | ✅ 必须 | 需要实际开发验证 |
| Pillar 4 | PR贡献故事 | ✅ 必须 | 核心就是 PR 工作流 |
| Pillar 5 | 挑战赛 | ✅ 必须 | 需要实际实现 |
| Pillar 6 | 深度解读 | ❌ 可选 | 仅在需要 Demo 验证时触发 |

- **质量门**:
  - [ ] 代码通过 lint / test
  - [ ] PR 已提交（如适用）
  - [ ] Demo 可运行（如适用）

### 2.4 D4 — Document 文档化

- **调用**: `hos-document` 技能集
- **输入**: 前序阶段所有产出物
- **输出**: 视频脚本 + 元数据 + 封面简报 + 博客文章 + GitHub 仓库（如适用）
- **质量门**:
  - [ ] 视频脚本符合 B站模板格式
  - [ ] 元数据字段完整（标题/简介/标签/分区/封面简报）
  - [ ] 博客文章通过平台适配检查
  - [ ] 所有输出与素材包一致性校验通过

## 3. 数据交接协议

### 3.1 交接格式

每个阶段输出统一使用 **4D 资产包** 格式：

```yaml
asset_pack:
  stage: D1 | D2 | D3 | D4
  pillar: 1-6
  timestamp: ISO8601
  source_materials: [...]    # D1 产出
  analysis_report: {...}     # D2 产出
  dev_artifacts: {...}       # D3 产出
  doc_outputs: {...}         # D4 产出
  quality_gate:
    passed: true/false
    checks: [...]
```

### 3.2 交接规则

1. **上游输出即下游输入**：每个阶段直接读取上游资产包，无需手动转换
2. **增量追加**：每个阶段在资产包中追加自己的产出，不修改上游数据
3. **质量门阻断**：若上游质量门未通过，下游有权拒绝接收并要求补充
4. **版本标记**：每次交接附带版本号，支持回溯

## 4. 错误处理与回滚策略

### 4.1 错误分类

| 级别 | 描述 | 处理策略 |
|------|------|----------|
| L1 轻微 | 单条素材质量不达标 | 跳过该条目，继续处理其余 |
| L2 中等 | 阶段质量门未通过 | 回退到上一阶段补充/修正 |
| L3 严重 | 整条管线方向错误 | 终止管线，回到 D1 重新规划 |
| L4 致命 | 外部依赖不可用 | 暂停管线，等待恢复后从断点续跑 |

### 4.2 回滚策略

```
D4 失败 → 回滚到 D3 输出（保留开发成果）
D3 失败 → 回滚到 D2 输出（保留分析报告）
D2 失败 → 回滚到 D1 输出（保留素材包）
D1 失败 → 终止并报告，保留原始输入
```

### 4.3 断点续跑

- 每个阶段完成后持久化资产包到磁盘
- 管线支持从任意阶段恢复执行
- 恢复时校验上游资产包完整性

## 5. 全流程时间估算

| 场景 | D1 | D2 | D3 | D4 | 总计 |
|------|----|----|----|----|------|
| 周报（Pillar 1） | 30 min | 30 min（可选） | — | 60 min | ~2 h |
| 源码深读（Pillar 2） | 30 min | 120 min | — | 90 min | ~4 h |
| PR贡献（Pillar 4） | 60 min | 120 min | 240 min | 90 min | ~8.5 h |
| 纪录片（Pillar 3） | 60 min | 120 min | 240 min | 90 min | ~8.5 h |
| 挑战赛（Pillar 5） | 30 min | 60 min | 480 min | 90 min | ~11 h |

## 6. 调用示例

```
# 完整流程
用户: 执行 4D 全流程，分析 Ollama 最新安全更新
系统: D1 → D2 → D3(跳过) → D4

# 仅文档化
用户: 对已有素材执行 D4 文档化
系统: 跳过 D1-D3，直接 D4

# 断点续跑
用户: 从 D2 恢复上次管线
系统: 加载 D1 资产包，从 D2 开始执行
```
