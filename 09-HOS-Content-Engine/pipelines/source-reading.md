# 源码深读管线

> Pillar 2 — 对开源项目进行深度源码分析，输出架构分析报告 + 视频脚本 + 博客。

---

## 1. 管线概览

| 属性 | 值 |
|------|-----|
| 触发词 | `深读XX项目` |
| 内容支柱 | Pillar 2 — 源码深读 |
| 预估总耗时 | 4–6 小时 |
| 最终产出 | 架构分析报告 + B站视频脚本 + 博客文章 + GitHub 笔记 |

---

## 2. 执行步骤

### Step 1: D1 选题与信息采集

- **调用**: `hos-discover`
- **动作**:
  1. 确认目标项目（名称、仓库地址、版本）
  2. 采集项目基本信息：Star 数、贡献者数、最近活跃度
  3. 采集项目文档：README、架构文档、设计文档
  4. 采集社区讨论：Issues、Discussions、相关博客
  5. 采集关联项目：依赖项、被依赖项、同类项目
- **输出**: 项目基础素材包
- **质量门**: 仓库可访问、文档已采集、关联项目已标注

### Step 2: D2 全面源码分析

- **调用**: `hos-dissect`
- **动作**: 执行深度分析检查清单（见下方）
- **输出**: 深度分析报告
- **质量门**: 检查清单所有项目已完成

#### 深度分析检查清单

- [ ] **模块结构**: 顶层目录结构、各模块职责、模块间关系
- [ ] **依赖图谱**: 核心依赖、可选依赖、依赖版本约束
- [ ] **核心算法**: 关键算法实现、复杂度分析、设计取舍
- [ ] **安全模式**: 认证/授权机制、输入校验、加密方式、安全边界
- [ ] **性能特征**: 内存管理、并发模型、缓存策略、瓶颈分析
- [ ] **设计决策**: 关键架构决策及其原因（ADR）
- [ ] **代码质量**: 测试覆盖率、CI/CD 流程、代码风格一致性
- [ ] **可扩展性**: 插件机制、API 设计、扩展点
- [ ] **文档完备性**: 文档与代码一致性、示例完整性

### Step 3: D3 可选 — 贡献机会评估

- **触发条件**: 分析过程中发现明确的贡献机会
- **判断标准**:
  - 发现 Bug 或安全漏洞
  - 发现文档缺失或错误
  - 发现性能优化空间
  - 发现 Feature Request 可实现
- **调用**: `hos-develop`
- **输出**: 贡献计划（转入 PR 贡献管线或独立执行）

### Step 4: D4 文档化 — B站视频脚本

- **调用**: `hos-document`
- **格式**: 10-15 分钟视频脚本
- **结构**:
  - Hook (0:00-0:30): 为什么这个项目值得深读
  - 项目背景 (0:30-2:00): 项目定位、社区数据、发展历程
  - 架构全景 (2:00-5:00): 模块结构、依赖图谱、设计哲学
  - 核心深入 (5:00-9:00): 2-3 个核心模块/算法详解
  - 安全与性能 (9:00-11:00): 安全模式分析 + 性能特征
  - 总结评价 (11:00-13:00): 优缺点、适用场景、竞品对比
  - CTA (13:00-15:00): 贡献指南 + 关注引导
- **输出**: 符合 B站模板的视频脚本

### Step 5: D4 文档化 — 博客 + GitHub 笔记

- **博客**: 长文技术博客（3000-5000 字）
- **GitHub 笔记**: 精简版分析笔记（可发布为 GitHub Issue 或 Discussion）

系统: 启动 Pillar 2 管线 → D1 → D2 → D3(触发) → D4
