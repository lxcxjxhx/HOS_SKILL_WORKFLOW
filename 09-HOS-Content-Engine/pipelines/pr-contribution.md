# PR贡献故事管线

> Pillar 4 — 记录给世界级开源项目贡献 PR 的完整过程，输出纪录片式内容。

---

## 1. 管线概览

| 属性 | 值 |
|------|-----|
| 触发词 | `给世界项目提PR` |
| 内容支柱 | Pillar 4 — PR贡献故事 |
| 预估总耗时 | 8–12 小时（含开发时间） |
| 最终产出 | PR 计划 + 开发日志 + 合并回顾 + B站视频脚本 + 博客 + GitHub 仓库 |

---

## 2. 执行步骤

### Step 1: D1 目标发现

- **调用**: `hos-discover`
- **动作**:
  1. 确定目标项目（基于 Pillar 1/2 积累或用户指定）
  2. 浏览目标项目的 Issues（good first issue / help wanted）
  3. 评估贡献难度与价值
  4. 确认贡献方向
- **输出**: 目标项目 + 目标 Issue + 贡献计划草案
- **质量门**: Issue 未被认领、与项目方向一致、难度可承受

### Step 2: D2 代码库分析

- **调用**: `hos-dissect`
- **动作**:
  1. Clone 目标仓库
  2. 分析项目结构、贡献指南（CONTRIBUTING.md）
  3. 理解相关模块的代码逻辑
  4. 确定修改范围和方案
  5. 搭建本地开发/测试环境
- **输出**: 代码库分析报告 + PR 实现方案
- **质量门**: 本地环境可运行、修改方案明确

### Step 3: D3 完整 PR 工作流

- **调用**: `hos-develop`
- **子步骤**:

#### 3.1 规划
- 创建开发计划（修改文件列表、预期行为变化）
- 创建分支（遵循项目分支命名规范）

#### 3.2 实现
- 编写代码
- 遵循项目代码风格（lint / format）
- 添加/更新测试

#### 3.3 测试
- 本地测试全部通过
- 运行项目 CI（如可本地运行）
- 手动验证功能正确性

#### 3.4 提交
- 撰写清晰的 Commit Message（遵循项目规范）
- 推送分支到个人 Fork

#### 3.5 发起 PR
- 撰写 PR 描述（问题描述、解决方案、测试方法、截图）
- 关联 Issue（`Closes #xxx`）
- 提交 PR

#### 3.6 Review 响应
- 监控 Review 评论
- 及时响应反馈
- 迭代修改代码
- 保持 PR 更新（rebase / merge main）

#### 3.7 合并
- PR 被合并
- 记录合并信息（合并时间、最终 commit SHA）

- **输出**: 完整 PR 记录 + 开发日志
- **质量门**: PR 已合并（或记录未合并原因）

### Step 4: D4 文档化

- **调用**: `hos-document`

#### 4.1 B站视频脚本（纪录片风格 10-15 分钟）

- **结构**:
  - Hook (0:00-0:30): "我给 XXX 项目提了一个 PR"
  - 缘起 (0:30-2:00): 为什么选择这个项目/Issue
  - 探索 (2:00-4:00): 阅读代码、理解架构的过程
  - 开发 (4:00-8:00): 实现过程（含踩坑记录）
  - 提交与 Review (8:00-11:00): PR 过程、维护者反馈
  - 合并回顾 (11:00-13:00): 经验教训、收获感悟
  - CTA (13:00-15:00): 鼓励观众参与开源
- **重点**: 真实记录开发过程，包括错误、调试、思考

#### 4.2 博客文章
- 技术博客：从发现问题到解决问题的完整叙事
- 开源贡献指南：给想参与开源的人的建议

#### 4.3 GitHub 仓库
- 创建独立的记录仓库
- 包含开发日志、代码变更、PR 链接

---

## 3. 开发日志模板

```markdown
# PR 开发日志

## 基本信息
- 目标项目: [项目名]
- 目标 Issue: #[编号]
- 分支名: [branch-name]
- PR 链接: [URL]

## Day 1 — 规划
- 阅读了哪些代码
- 确定的实现方案
- 遇到的问题

## Day 2 — 实现
- 编写了哪些代码
- 关键决策点
- 调试过程

## Day 3 — 提交与 Review
- PR 描述
- Review 反馈
- 修改内容

## 合并回顾
- 最终结果
- 经验教训
- 给后来者的建议
```

## 4. 产出物清单

| 产出物 | 格式 | 说明 |
|--------|------|------|
| PR 计划 | Markdown | 实现方案 + 修改范围 |
| 开发日志 | Markdown | 每日进展记录 |
| 合并回顾 | Markdown | 经验总结 |
| B站视频脚本 | Markdown（模板格式） | 纪录片风格 10-15 min |
| B站元数据 | Markdown（模板格式） | 标题/简介/标签 |
| 封面简报 | Markdown | 设计参考 |
| 技术博客 | Markdown | 完整叙事 |
| GitHub 仓库 | Git repo | 开发记录仓库 |

---

## 5. 调用示例

```
用户: 给 transformers 项目提 PR
系统: 启动 Pillar 4 管线 → D1 找 Issue → D2 分析代码 → D3 完整 PR → D4 文档化

用户: 把上次提 PR 的经历做成视频
系统: 从已有开发日志启动 D4 文档化
```
