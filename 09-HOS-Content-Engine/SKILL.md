## 二、核心概念

### 2.1 4D 内容模型

4D 是四个阶段的缩写，构成内容生产的完整闭环：

| 阶段 | 名称 | 核心动作 | 输入 | 输出 |
|------|------|----------|------|------|
| D1 | **Discover**（发现） | 选题挖掘、趋势洞察、受众分析 | 安全事件/技术趋势/用户需求 | 选题报告 + 受众画像 + 核心洞察 |
| D2 | **Dissect**（解剖） | 深度分析、安全审计、技术拆解 | D1 输出 + 00-SecEngine 数据 | 分析报告 + 漏洞详情 + 攻击链 |
| D3 | **Develop**（开发） | 方案制定、代码编写、Demo 构建 | D2 输出 | 技术方案 + 代码示例 + Demo 规格 |
| D4 | **Document**（记录） | 多格式输出、平台适配、资产编排 | D1+D2+D3 素材包 | B站脚本 + 博客 + GitHub + Demo |

**闭环机制**：D4 的发布反馈回流至 D1，驱动下一轮选题优化。

### 2.2 六大内容支柱

| 支柱名称 | D1 权重 | D2 权重 | D3 权重 | D4 权重 | 输出格式 | 发布频率 |
|----------|---------|---------|---------|---------|----------|----------|
| 漏洞复现 | 20% | 50% | 20% | 10% | 视频+文章+PoC仓库 | 2次/月 |
| 工具开发 | 15% | 10% | 55% | 20% | 视频+文章+开源工具 | 2次/月 |
| 攻防实战 | 20% | 40% | 30% | 10% | 视频+文章+靶场配置 | 1次/月 |
| 安全科普 | 50% | 20% | 10% | 20% | 视频+文章+图解 | 4次/月 |
| 代码审计 | 15% | 55% | 20% | 10% | 视频+文章+审计模板 | 2次/月 |
| 行业观察 | 60% | 15% | 5% | 20% | 视频+文章+数据报告 | 4次/月 |

**权重说明**：各阶段在不同支柱中的投入比重。例如"漏洞复现"在 D2（解剖）阶段投入最大，因为需要深度分析漏洞细节。

## 三、子技能说明

### 3.1 Discover（D1 — 发现）

> 详细定义见 `discover/SKILL.md`

**触发条件**：

| 触发词 | 说明 |
|--------|------|
| `发现安全选题` | 挖掘近期安全事件/趋势作为选题 |
| `分析安全趋势` | 分析行业安全趋势数据 |
| `选题调研` | 对指定方向进行选题可行性调研 |
| `受众分析` | 分析目标受众画像和需求 |

**核心能力**：
1. 安全事件/趋势挖掘（CVE、安全新闻、技术社区热点）
2. 选题可行性评估（新颖性、受众匹配度、竞争分析）
3. 受众画像生成（技术水平、关注点、内容偏好）
4. 核心洞察提炼（一句话概括 + 支撑数据）

### 3.2 Dissect（D2 — 解剖）

> 详细定义见 `dissect/SKILL.md`

**触发条件**：

| 触发词 | 说明 |
|--------|------|
| `深度分析这个漏洞` | 对指定漏洞进行深度技术分析 |
| `安全审计这段代码` | 调用 00-SecEngine 进行代码审计 |
| `拆解这个攻击链` | 分析完整攻击链路 |
| `技术解剖` | 对技术方案进行深度解剖 |

**核心能力**：
1. 漏洞深度分析（原理、影响范围、利用条件、修复方案）
2. 代码安全审计（集成 00-HOS-Sec-Engine，多语言支持）
3. 攻击链拆解（Kill Chain / MITRE ATT&CK 映射）
4. 技术对比分析（方案 A vs 方案 B 优劣对比）

### 3.3 Develop（D3 — 开发）

> 详细定义见 `develop/SKILL.md`

**触发条件**：

| 触发词 | 说明 |
|--------|------|
| `开发安全工具` | 基于分析结果开发安全工具 |
| `编写PoC代码` | 编写漏洞验证代码 |
| `构建Demo` | 构建演示用的 Demo 项目 |
| `制定技术方案` | 制定修复/实现技术方案 |

**核心能力**：
1. 安全工具开发（PoC、扫描器、检测脚本）
2. 技术方案制定（架构设计、实现路径、风险评估）
3. Demo 项目构建（可运行示例、测试用例）
4. 代码质量保障（测试覆盖、文档完善、安全检查）

### 3.4 Document（D4 — 记录）

> 详细定义见 `document/SKILL.md`

**触发条件**：

| 触发词 | 说明 |
|--------|------|
| `生成B站视频脚本` | 生成完整的 B站分镜脚本 |
| `把这个内容做成视频` | 从素材生成视频脚本 |
| `生成配套博客文章` | 调用 07 生成博客 |
| `创建GitHub仓库` | 生成仓库结构 |
| `多格式输出` | 同时输出所有格式 |

**核心能力**：
1. B站视频脚本生成（分镜级精度，10 分钟标准结构）
2. B站元数据优化（标题/简介/标签/分区/封面简报）
3. 博客文章生成（委托 07-HOS-IP-Writing/blog）
4. GitHub 仓库生成（README + LICENSE + 代码结构）
5. Demo 资产编排（委托 06-HOS-Fuck-Demo）

## 四、使用指南

### 4.1 触发条件汇总

| 场景 | 激活技能 | 触发词示例 |
|------|----------|------------|
| 寻找选题 | D1-Discover | `发现安全选题`、`分析安全趋势` |
| 深度分析 | D2-Dissect | `深度分析这个漏洞`、`安全审计` |
| 工具开发 | D3-Develop | `开发安全工具`、`编写PoC` |
| 视频脚本 | D4-Document | `生成B站视频脚本` |
| 博客生成 | D4-Document | `生成配套博客文章` |
| 完整流水线 | 全局路由 | `从选题到发布`、`完整内容生产` |

### 4.2 技能组合使用

**场景 1：漏洞复现全流程**

```
D1: 发现近期高危 CVE → 选题评估
  │
  ▼
D2: 深度分析漏洞原理 → 调用 00-SecEngine 审计相关代码
  │
  ▼
D3: 编写 PoC 验证代码 → 构建复现环境
  │
  ▼
D4: 生成 B站脚本 + 博客 + PoC GitHub 仓库
  │
  ├──▶ 06: 生成 PPT + 音频资产
  └──▶ 07: 生成多平台博客文章
```

**场景 2：安全科普快速产出**

```
D1: 分析安全趋势 → 确定科普选题
  │
  ▼
D4: 直接生成 B站脚本 + 博客（D2/D3 轻量参与）
  │
  └──▶ 07: 生成科普文章
```

**场景 3：工具开发 + 推广**

```
D1: 发现工具需求 → 竞品分析
  │
  ▼
D3: 开发安全工具 → 编写测试
  │
  ▼
D4: 生成 B站演示脚本 + GitHub 仓库 + 使用教程博客
  │
  ├──▶ 06: 生成 Demo 演示资产
  └──▶ 07: 生成技术博客
```

### 4.3 跨技能调用

| 目标技能 | 调用时机 | 调用方式 |
|----------|----------|----------|
| 06-HOS-Fuck-Demo | D4 需要生成 PPT/音频/视频资产时 | 传递 direction + depth + style |
| 07-HOS-IP-Writing/blog | D4 需要生成博客文章时 | 传递 4D 素材包核心内容 |
| 00-HOS-Sec-Engine | D2 需要安全审计能力时 | 传递目标代码/配置 |
