# Text Chunker · 文本/文章/方案切片规则

> 适用对象：`article` / `proposal` / `unknown` / `dataset`（文本形态）。
> 执行者：宿主 LLM 按本规则切片（M1 无工具模式）；M2 起可由脚本辅助。

## 1. 核心原则

- 按**语义边界**切：标题、论点段、条款，不按字数硬切；
- 长度只是**上限**（≤ 4000 tokens/单元），不是目标；
- 每个单元必须可独立评审：单看本单元就能形成判断。

## 2. Markdown / 富文本切片

### 2.1 有标题结构

1. 用 `h2`/`h3` 标题作为单元起点（`kind: text-heading`）；
2. 标题下的段落、列表、代码块并入该单元；
3. 标题缺失的正文开头（如简介）作为独立 `text-paragraph` 单元；
4. 单元标题 = 标题文本；`source_range` 记录起始行与结束行。

### 2.2 无标题结构（纯文本）

1. 空行分隔的段落为基本单元（`kind: text-paragraph`）；
2. 段落 token > 1000 时按句号/分号边界折半；
3. 连续 2-3 个小段落（合计 ≤ 2000 tokens）合并为一个单元。

### 2.3 特殊块

| 内容 | 处理 |
|------|------|
| 代码块 | 独立成单元（`kind: code-block`），记录语言 |
| 表格 | 并入所在节（表格内数据量大时可独立成单元） |
| 参考文献/链接清单 | 并入所在节；独立章节则自成单元 |
| 目录/TOC | 不单独成单元，并入其后首个正文单元或丢弃（记录丢弃） |

## 3. Proposal（方案文档）切片

按章节语义命名单元，`kind: proposal-section`：

| 常见章节 | 单元标题 | tags |
|----------|----------|------|
| 背景/问题 | 背景与问题定义 | `background` |
| 方案/架构 | 核心方案 | `architecture` |
| 技术选型 | 技术选型 | `tech-choice` |
| 计划/里程碑 | 实施计划 | `plan` |
| 风险/成本 | 风险与成本 | `risk` |
| 收益/度量 | 预期收益 | `value` |

缺失章节时按 §2.2 段落规则处理，并在 `tags` 注明「缺 X 章节」（该信息本身就是潜在 Finding：结构不完整）。

## 4. License 条款切片（license / repo 的 LICENSE）

按条款语义段切，`kind: license-clause`：

| 语义段 | 识别特征 |
|--------|----------|
| Grant | 授予权利（「Permission is hereby granted…」） |
| Conditions | 条件（「must retain…」「provided that…」） |
| Limitations | 限制（「WITHOUT WARRANTY…」） |
| Warranty/免责 | 免责条款 |
| 附加条款 | 专利授权、商标、出口合规等 |

> 只识别 SPDX 标识与条款边界，不修改原文。许可证文本超 4000 tokens 时按条款边界优先切。

## 5. Dataset 字段切片（dataset）

按「规模 / 来源 / 许可 / 字段说明」四段切（`kind: dataset-field`），每段一个单元；无明确段落时按 §2.2。

## 6. 参数默认值

| 参数 | 默认 |
|------|------|
| `unit_max_tokens` | 4000 |
| 段落折半阈值 | 1000 tokens |
| 小段落合并上限 | 2000 tokens |
| 定长兜底（降级） | 1500 tokens / overlap 150 |

## 7. 质量门槛

- 单元并集覆盖原文 ≥ 95%；
- 全部单元带 `source_range`（行区间）或章节路径；
- 单元间不重叠；超限单元必须再切。

## 8. 降级链

```
标题/段落语义切片 → 定长切分（1500/150）→ 整对象单单元
```
