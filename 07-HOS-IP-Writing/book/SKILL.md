# 书籍写作 Skill（Book Writing Skill）

> 完全自研的书籍写作系统，支持技术书籍、教程、博客合集等多种类型，提供从大纲到出版的全流程自动化支持。

---

## 一、触发条件

当用户输入匹配以下任意场景时，自动激活本 Skill：

### 1.1 直接触发词
- "写书"、"写一本书"、"帮我写书"
- "写技术书"、"写教程"、"写教材"
- "书籍写作"、"book writing"、"technical book"
- "生成目录"、"写章节"、"写前言"
- "出版书籍"、"投稿出版社"
- "写编程书"、"写算法书"、"写架构书"

### 1.2 意图触发
- 用户要求将系列博客整理成书籍
- 用户要求创建完整的技术教程书籍
- 用户要求生成书籍目录结构
- 用户要求撰写书籍章节
- 用户要求生成代码示例和练习题
- 用户要求书籍出版指导

### 1.3 文件触发
- 用户提供 `.md` 文件并要求整理成书籍格式
- 用户提供代码项目并要求生成配套教程书籍
- 用户提供博客合集并要求编辑成书

## 三、工作流程

### 3.1 标准书籍写作流程

```
需求分析 → 书籍提案 → 目录生成 → 用户确认 → 章节撰写 → 代码示例 → 练习题 → 插图描述 → 前言附录 → 审校优化 → 出版准备
```

**详细步骤：**

1. **需求分析**
   - 确认书籍类型（技术书/教程/博客合集）
   - 确认目标读者和技术水平
   - 确认核心主题和覆盖范围
   - 确认预计篇幅和章节数量
   - 确认出版方式（传统出版/自出版）

2. **书籍提案**
   - 加载模板：`templates/book-proposal.md`
   - 生成书籍提案文档
   - 包含：书籍简介、目标读者、作者介绍、市场分析、目录大纲
   - 等待用户确认或调整

3. **目录生成**
   - 加载模板：`templates/toc-template.md`
   - 生成完整目录结构（Part → Chapter → Section）
   - 每章包含：学习目标、主要内容、预计篇幅
   - 生成章节依赖关系图
   - 等待用户确认或调整

4. **章节撰写**
   - 加载模板：`templates/chapter-template.md`
   - 按目录逐章生成内容
   - 每章结构：
     - 章节引言（问题引入、学习目标）
     - 理论讲解（概念、原理、最佳实践）
     - 代码示例（可运行代码、详细注释）
     - 实战案例（完整项目案例）
     - 常见问题（FAQ、陷阱提示）
     - 本章小结（要点回顾）
     - 练习题（选择题、填空题、编程题）
     - 下一章预告

5. **代码示例生成**
   - 加载模板：`templates/code-example-template.md`
   - 生成完整可运行的代码示例
   - 包含：环境要求、代码说明、运行结果、扩展练习
   - 确保代码风格统一、注释完整

6. **练习题生成**
   - 加载模板：`templates/exercise-template.md`
   - 生成多种类型练习题：
     - 选择题（单选、多选）
     - 填空题
     - 判断题
     - 简答题
     - 编程题（基础、进阶、挑战）
   - 提供参考答案和解析

7. **插图描述生成**
   - 加载模板：`templates/illustration-guide.md`
   - 生成图表描述（可用于 Mermaid、Draw.io、Visio）
   - 包含：流程图、架构图、时序图、类图、ER 图
   - 提供插图位置和说明文字

8. **前言和附录生成**
   - 加载模板：`templates/preface-template.md` 和 `templates/appendix-template.md`
   - 生成前言（写作背景、目标读者、如何使用本书）
   - 生成序言（可选，邀请他人作序）
   - 生成附录（参考文献、术语表、工具清单、索引）
   - 生成作者简介

9. **审校优化**
   - 技术准确性审查
   - 语言风格统一
   - 代码示例验证
   - 交叉引用检查
   - 术语一致性检查
   - 生成审校报告

10. **出版准备**
    - 加载工作流：`workflows/publishing-workflow.md`
    - 格式化输出（Markdown、PDF、ePub）
    - 生成书籍提案（如需要）
    - 提供出版社推荐和投稿指南
    - 提供自出版平台指导

### 3.2 快速书籍生成流程

当用户要求快速生成时，跳过部分确认步骤：

```
用户需求 → 自动判断类型 → 生成提案和目录 → 批量生成章节 → 输出完整书籍
```

### 3.3 章节开发流程

当用户要求开发特定章节时：

```
指定章节 → 加载章节模板 → 生成章节内容 → 生成代码示例 → 生成练习题 → 审校优化
```

### 3.4 博客转书籍流程

当用户提供博客合集要求整理成书：

```
输入博客 → 分析主题 → 重新组织结构 → 补充过渡内容 → 统一风格 → 生成书籍
```

## 五、使用指南

### 5.1 写技术书籍

**输入示例：**
```
帮我写一本关于 Python 异步编程的技术书籍，面向中高级开发者
```

**执行流程：**
1. 识别书籍类型：技术书籍
2. 加载书籍提案模板，生成提案文档
3. 生成完整目录结构（预计 12-15 章）
4. 确认后逐章生成内容
5. 每章包含：理论、代码示例、练习题
6. 生成前言、附录、参考文献
7. 输出完整书籍 Markdown 文件

### 5.2 写教程书籍

**输入示例：**
```
写一本 Docker 入门教程，面向初学者，包含实战项目
```

**执行流程：**
1. 识别书籍类型：教程书籍
2. 生成循序渐进的目录结构
3. 每章包含：概念讲解、步骤演示、实战练习
4. 生成完整代码示例和项目文件
5. 生成练习题和参考答案
6. 输出教程 + 代码仓库结构

### 5.3 整理博客合集

**输入示例：**
```
把我的 Python 系列博客整理成一本书
```

**执行流程：**
1. 读取输入的博客文章
2. 分析主题和结构
3. 重新组织为书籍目录
4. 补充章节过渡和引言
5. 统一术语和风格
6. 生成前言和附录
7. 输出整理后的书籍

### 5.4 生成特定章节

**输入示例：**
```
帮我写《Python 异步编程》第 5 章：asyncio 高级特性
```

**执行流程：**
1. 加载章节模板
2. 生成章节详细内容
3. 生成代码示例和练习题
4. 生成插图描述
5. 输出完整章节

### 5.5 生成代码示例

**输入示例：**
```
为第 3 章生成关于装饰器的代码示例
```

**执行流程：**
1. 加载代码示例模板
2. 生成基础示例、进阶示例、实战案例
3. 添加详细注释和说明
4. 提供运行结果和扩展练习
5. 输出代码文件和使用说明

### 5.6 生成练习题

**输入示例：**
```
为第 4 章生成练习题，包含选择题和编程题
```

**执行流程：**
1. 加载练习题模板
2. 生成选择题（10 题）
3. 生成填空题（10 题）
4. 生成编程题（5 题，分难度）
5. 生成参考答案和解析
6. 输出练习题文档

### 5.7 出版指导

**输入示例：**
```
这本书应该如何出版？推荐一些出版社
```

**执行流程：**
1. 加载出版工作流
2. 分析书籍类型和目标读者
3. 推荐合适的出版社（电子工业、机械工业、人民邮电等）
4. 提供投稿流程和联系方式
5. 提供自出版平台选择（GitBook、Leanpub）
6. 输出出版指导报告

## 六、书籍类型详解

### 6.1 技术书籍
- **特点**：深度技术内容、系统性强、代码示例丰富
- **结构**：Part → Chapter → Section → Subsection
- **篇幅**：每章 8000-15000 字，全书 8-15 万字
- **代码**：每章 5-10 个完整代码示例
- **练习**：每章 10-20 道练习题
- **插图**：架构图、流程图、时序图

### 6.2 教程书籍
- **特点**：循序渐进、步骤详细、实战导向
- **结构**：Lesson → Step → Exercise
- **篇幅**：每章 5000-10000 字，全书 5-10 万字
- **代码**：每章 10-15 个步骤式代码示例
- **练习**：每章 15-25 道练习题（含实战项目）
- **插图**：操作步骤截图、流程图

### 6.3 博客合集
- **特点**：主题集中、风格统一、内容优化
- **结构**：Part → Chapter（原博客文章）
- **篇幅**：每章 3000-8000 字，全书 5-12 万字
- **代码**：保留原有代码，补充完整示例
- **练习**：可选，每章 5-10 道
- **插图**：保留原有插图，补充架构图

### 6.4 系列教程
- **特点**：分章节发布、循序渐进、互动性强
- **结构**：Day/Lesson → Task → Challenge
- **篇幅**：每章 3000-6000 字，全书 3-8 万字
- **代码**：每章 5-8 个代码示例
- **练习**：每章 10-15 道练习题（含挑战任务）
- **插图**：流程图、思维导图

## 七、输出格式

### 7.1 Markdown 格式
- 标准 Markdown 语法
- 支持代码块高亮
- 支持 Mermaid 图表
- 支持数学公式（LaTeX）

- 需要额外转换（Pandoc、LaTeX）

### 7.3 ePub 格式
- 电子书格式
- 适合 Kindle、iBooks 等阅读器
- 需要额外转换工具

## 八、最佳实践

### 8.1 写作原则
- **读者优先**：始终从读者角度思考
- **循序渐进**：由浅入深，避免跳跃
- **实践导向**：理论结合实践，代码示例丰富
- **术语统一**：全书术语保持一致
- **引用规范**：正确引用他人工作

### 8.2 代码示例原则
- **可运行**：所有代码示例必须可运行
- **完整**：提供完整的代码，避免省略
- **注释**：添加必要的注释说明
- **风格**：统一的代码风格
- **测试**：提供代码测试用例

### 8.3 练习题设计原则
- **分层**：基础、进阶、挑战三个层次
- **多样**：选择题、填空题、编程题结合
- **实用**：贴近实际应用场景
- **解析**：提供详细的参考答案和解析

### 8.4 出版建议
- **提前联系出版社**：了解出版流程和要求
- **准备书籍提案**：专业的提案文档
- **选择合适的自出版平台**：根据目标读者选择
- **重视审校**：确保技术准确性和语言质量
- **建立读者社区**：GitHub、论坛、微信群

## 九、常见问题

### 9.1 如何确定书籍范围？
- 明确目标读者和技术水平
- 调研同类书籍，找出差异化
- 列出核心主题和可选主题
- 根据篇幅限制取舍

### 9.2 如何保证技术准确性？
- 所有代码示例必须测试通过
- 引用权威资料和官方文档
- 邀请技术专家审校
- 建立读者反馈渠道

### 9.3 如何管理写作进度？
- 制定详细的写作计划
- 按章节追踪进度
- 设置里程碑和截止日期
- 定期回顾和调整

### 9.4 传统出版还是自出版？
- **传统出版**：适合追求权威性和广泛传播
- **自出版**：适合快速迭代和直接面对读者
- **混合模式**：先自出版验证，再联系传统出版
