## 二、核心能力

### 2.1 去 AI 写作模式（Deslop）

| 能力 | 说明 |
|------|------|
| 识别填充短语 | 检测并删除"值得注意的是"、"需要指出的是"、"众所周知"等 AI 常用填充词 |
| 打破公式化结构 | 消除"首先...其次...最后..."等机械式段落结构 |
| 去除 AI 套路 | 识别并改写 AI 偏好的表达方式（如过度使用"本质上"、"从根本上说"） |
| 主动语态转换 | 将被动语态改为主动语态，增强表达力度 |
| 人类主语注入 | 用"研究者"、"开发者"、"我们"等人类主语替代无灵主语 |

### 2.2 具体化表达

| 能力 | 说明 |
|------|------|
| 模糊词替换 | 将"很多"、"一些"、"相关"等模糊词替换为具体数据或明确描述 |
| 量化表达 | 用数字、百分比、具体案例替代笼统描述 |
| 实例支撑 | 为抽象观点添加具体实例或场景 |
| 精确术语 | 使用领域专业术语替代泛化表达 |

### 2.3 节奏变化

| 能力 | 说明 |
|------|------|
| 句式多样化 | 混合使用长短句，避免单调节奏 |
| 段落长度变化 | 交替使用短段落和长段落，创造视觉节奏 |
| 开头多样化 | 避免每段都以相同方式开头 |
| 过渡自然化 | 使用多样化的过渡词，避免机械式连接 |

### 2.4 语境匹配注册表

根据文本类型自动匹配润色策略：

| 语境类型 | 润色策略 |
|----------|----------|
| 学术论文 | 保持严谨性，去除口语化表达，规范引用格式 |
| 技术博客 | 保持专业性，增加可读性，适当使用口语化表达 |
| 商业文档 | 保持简洁性，突出行动导向，避免学术化表达 |
| 创意写作 | 保持个性，增强表现力，允许适度口语化 |
| 新闻报道 | 保持客观性，使用倒金字塔结构，避免主观判断 |

### 2.5 学术写作优化（HOS 扩展）

| 能力 | 说明 |
|------|------|
| 学术表达优化 | 将口语化表达改为学术用语（如"用"→"采用"，"做"→"实施"） |
| 引用格式规范 | 支持 APA、MLA、Chicago、GB/T 7714 等引用格式 |
| 段落结构改进 | 优化段落主题句、支撑句、结论句的逻辑关系 |
| 文献综述优化 | 改进文献综述的批判性分析和综合表述 |
| 论证逻辑强化 | 增强论点的逻辑链条，补充必要的推理步骤 |

## 四、使用指南

### 4.1 基础润色

**输入示例**：
```
请帮我润色这段文字：
"值得注意的是，人工智能技术在近年来取得了显著的发展。从本质上来说，
深度学习算法的实现使得计算机能够更好地理解复杂的数据模式。"
```

**输出示例**：
```
人工智能技术在近年来取得显著发展。深度学习算法使计算机能够更好地
理解复杂数据模式。
```

**润色说明**：
- 删除"值得注意的是"（填充短语）
- 删除"从本质上来说"（AI 套路）
- 将"的实现使得"简化为"使"（主动语态）

### 4.2 学术润色

**输入示例**：
```
请帮我学术润色：
"我们用了这个方法来做实验，结果发现效果挺好的，比以前的方法都要好。"
```

**输出示例**：
```
本研究采用该方法进行实验，结果表明其性能显著优于现有方法。
```

**润色说明**：
- "用了"→"采用"（学术用语）
- "来做实验"→"进行实验"（学术表达）
- "挺好的"→"显著"（量化表达）
- "都要好"→"优于"（学术比较）

### 4.3 引用格式规范

**输入示例**：
```
帮我规范引用格式（APA）：
"根据张三的研究(2020)，这个理论是正确的。李四(2019)也说过类似的话。"
```

**输出示例**：
```
根据 Zhang（2020）的研究，该理论得到验证。Li（2019）的研究亦支持
这一观点。
```

**润色说明**：
- 统一引用格式为 APA 格式
- "是正确的"→"得到验证"（学术表达）
- "也说过类似的话"→"亦支持这一观点"（学术引用）

## 七、高级功能

### 7.1 语境自动识别

系统自动识别文本类型并匹配最佳润色策略：

```python
# 伪代码示例
def detect_context(text):
    if contains_academic_markers(text):
        return "academic"
    elif contains_technical_terms(text):
        return "technical"
    elif contains_business_terms(text):
        return "business"
    else:
        return "general"
```

### 7.2 自定义润色规则

用户可自定义润色规则：

```yaml
# 自定义润色配置
custom_rules:
  - pattern: "值得注意的是"
    replacement: ""
    action: delete
  
  - pattern: "用了"
    replacement: "采用"
    action: replace
    context: academic
  
  - pattern: "很多"
    replacement: "具体数字"
    action: quantify
```

### 7.3 批量润色

支持批量处理多个文件：

```bash
# 批量润色命令示例
hos review --input ./drafts/*.md --output ./polished/ --style academic
```

## 八、最佳实践

### 8.1 润色原则

1. **保留原意**：润色不改变原文核心观点
2. **适度改写**：避免过度润色导致失去作者风格
3. **语境一致**：保持全文语体风格统一
4. **渐进改进**：优先处理最明显的 AI 痕迹

### 8.2 常见误区

1. ❌ 过度润色：将所有表达都改为"完美"表达
2. ❌ 忽视语境：在技术文档中使用过于口语化的表达
3. ❌ 机械替换：不考虑上下文直接替换词汇
4. ❌ 忽略节奏：只关注词汇，忽视句式变化

### 8.3 润色检查清单

**基础检查**：
- [ ] 是否删除了所有填充短语？
- [ ] 是否将被动语态改为主动语态？
- [ ] 是否将模糊表达改为具体描述？
- [ ] 是否保持了句式多样性？

**学术检查**：
- [ ] 引用格式是否统一？
- [ ] 术语使用是否一致？
- [ ] 论证逻辑是否清晰？
- [ ] 段落结构是否合理？

## 九、技术实现

### 9.1 核心算法

```python
# 润色核心流程
def polish_text(text, context="general"):
    # 1. 检测 AI 模式
    ai_patterns = detect_ai_patterns(text)
    
    # 2. 加载语境策略
    strategy = load_strategy(context)
    
    # 3. 执行润色
    polished = apply_polish_rules(text, strategy)
    
    # 4. 质量验证
    quality_score = evaluate_quality(polished)
    
    return polished, quality_score
```

### 9.2 规则引擎

润色规则采用优先级机制：

1. **高优先级**：删除填充短语、转换被动语态
2. **中优先级**：具体化表达、优化句式
3. **低优先级**：风格微调、词汇替换
