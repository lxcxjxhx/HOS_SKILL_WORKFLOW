# 专利写作 Skill

## 概述

本 Skill 提供完整的中国专利文档撰写能力，支持发明专利、实用新型专利和外观设计专利三种类型。从技术方案描述到完整专利文档生成，符合国家知识产权局（CNIPA）格式规范。

## 触发条件

当用户提出以下需求时自动触发：

- 撰写专利申请文件
- 生成权利要求书
- 撰写专利说明书
- 撰写专利摘要
- 生成发明交底书
- 撰写附图说明
- 回复审查意见（OA 回复）
- 专利文档格式化
- 技术方案专利化
- 专利类型咨询（发明/实用新型/外观设计）

关键词触发：`专利`、`权利要求`、`说明书`、`摘要`、`交底书`、`OA回复`、`审查意见`、`发明专利`、`实用新型`、`外观设计`

## 支持的专利类型

### 1. 发明专利
- 保护对象：产品、方法或其改进所提出的新技术方案
- 保护期限：20 年（自申请日起）
- 审查制度：实质审查
- 适用场景：技术创新程度高、需要长期保护的核心技术

### 2. 实用新型专利
- 保护对象：产品的形状、构造或其结合所提出的适于实用的新技术方案
- 保护期限：10 年（自申请日起）
- 审查制度：初步审查（不实质审查）
- 适用场景：产品结构的改进、小发明、快速保护需求

### 3. 外观设计专利
- 保护对象：产品的整体或局部的形状、图案或其结合以及色彩与形状、图案的结合所作出的富有美感并适于工业应用的新设计
- 保护期限：15 年（自申请日起）
- 审查制度：初步审查
- 适用场景：产品外观设计的创新保护

## 工作流程

### 阶段一：技术方案收集与分析

1. **接收技术方案描述**
   - 理解发明创造的核心技术点
   - 识别技术问题和技术效果
   - 分析技术方案的具体实施方式

2. **专利类型判断**
   - 根据技术方案特征推荐合适的专利类型
   - 参考 `workflows/patent-types-guide.md` 进行类型选择

3. **发明交底书生成**
   - 使用 `templates/invention-disclosure.md` 模板
   - 整理技术方案的结构化描述

### 阶段二：权利要求书撰写

1. **独立权利要求撰写**
   - 确定保护范围
   - 撰写前序部分（主题名称 + 必要技术特征）
   - 撰写特征部分（创新点描述）
   - 使用 `templates/claims-template.md` 模板

2. **从属权利要求撰写**
   - 引用在前权利要求
   - 补充附加技术特征
   - 构建多层次保护体系

3. **权利要求审查**
   - 检查权利要求的清楚性
   - 检查权利要求的支持性
   - 检查权利要求的层次性

### 阶段三：说明书撰写

1. **技术领域**
   - 明确所属技术领域
   - 使用 `templates/description-template.md` 模板

2. **背景技术**
   - 描述现有技术状况
   - 指出现有技术的不足
   - 客观评价，不贬低现有技术

3. **发明内容**
   - 阐述要解决的技术问题
   - 描述技术方案
   - 说明有益效果

4. **附图说明**
   - 描述各附图内容
   - 使用 `templates/drawings-description.md` 模板

5. **具体实施方式**
   - 详细描述实施方式
   - 提供具体实施例
   - 结合附图进行说明

### 阶段四：摘要撰写

1. **摘要正文**
   - 技术问题概述
   - 技术方案概述
   - 技术效果概述
   - 使用 `templates/abstract-template.md` 模板

2. **摘要附图**
   - 选择最能说明技术方案的附图

### 阶段五：审查意见回复（OA 回复）

1. **分析审查意见**
   - 理解审查员的意见要点
   - 识别驳回理由（新颖性/创造性/实用性/清楚性/支持性）

2. **制定回复策略**
   - 使用 `templates/oa-reply-template.md` 模板
   - 参考 `workflows/oa-reply-workflow.md` 工作流

3. **撰写回复意见**
   - 针对性答复每个驳回理由
   - 必要时修改权利要求书
   - 提供技术论证和法律依据

## 使用指南

### 基本用法

1. **从技术方案生成完整专利文档**
   ```
   用户提供技术方案描述 → 生成发明交底书 → 生成权利要求书 → 生成说明书 → 生成摘要
   ```

2. **单独生成某个文档部分**
   ```
   用户提供技术方案 → 指定生成部分（权利要求书/说明书/摘要等）→ 使用对应模板生成
   ```

3. **审查意见回复**
   ```
   用户提供审查意见 → 分析驳回理由 → 制定回复策略 → 生成回复文书
   ```

### 输入要求

用户需要提供以下信息：

- **技术方案描述**：发明的核心技术内容
- **专利类型**（可选）：发明/实用新型/外观设计，不提供则自动推荐
- **现有技术**（可选）：相关背景技术信息
- **具体实施方式**（可选）：具体实现细节
- **附图说明**（可选）：附图的描述信息

### 输出格式

所有输出文档遵循以下规范：

- 符合国家知识产权局（CNIPA）专利申请文件格式要求
- 使用标准专利用语和表达方式
- 权利要求书采用编号格式
- 说明书包含完整的五个部分
- 摘要控制在 300 字以内

## 中国专利格式规范

### 权利要求书撰写规则

1. **独立权利要求格式**
   ```
   [主题名称]，其特征在于，包括：
   [技术特征 A]；
   [技术特征 B]；
   ...
   [技术特征 N]。
   ```

2. **从属权利要求格式**
   ```
   根据权利要求 [X] 所述的 [主题名称]，其特征在于，所述 [引用特征] 进一步包括：
   [附加技术特征]。
   ```

3. **撰写原则**
   - 权利要求应当清楚、简明
   - 独立权利要求包含必要技术特征
   - 从属权利要求进一步限定
   - 方法专利用步骤描述，产品专利用结构描述
   - 避免使用模糊用语（如"大约"、"左右"等）

### 说明书格式规范

1. **技术领域**：一句话说明所属技术领域
2. **背景技术**：描述现有技术及其不足
3. **发明内容**：技术问题 + 技术方案 + 有益效果
4. **附图说明**：各附图的名称和简要说明
5. **具体实施方式**：结合附图详细描述实施方式

### 摘要格式规范

- 不超过 300 字（不含标点符号）
- 包含：技术问题、技术方案要点、主要用途/效果
- 不得使用商业性宣传用语
- 可包含数学式或化学式

## 注意事项

1. **新颖性保护**：在撰写过程中注意保护技术方案的新颖性
2. **创造性论证**：充分论证技术方案相对于现有技术的创造性
3. **实用性确认**：确保技术方案能够在产业中制造或使用
4. **充分公开**：说明书应当充分公开技术方案，使本领域技术人员能够实现
5. **支持性要求**：权利要求书应当得到说明书的支持
6. **用语规范**：使用专利标准用语，避免口语化表达
