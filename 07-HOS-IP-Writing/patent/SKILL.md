# 专利文档撰写系统

> 从技术方案到完整专利文档，支持发明、实用新型、外观设计三种类型。

---

## 触发条件

| 触发场景 | 示例表达 |
|---------|---------|
| 撰写专利 | "写专利申请"、"生成权利要求书" |
| 发明交底书 | "写交底书"、"整理技术方案" |
| 说明书撰写 | "写专利说明书"、"写具体实施方式" |
| 审查意见回复 | "回复 OA"、"审查意见答复" |
| 专利类型咨询 | "发明还是实用新型"、"外观设计能保护多久" |

**不触发**：软著申请（→ `copyright`），论文写作（→ `paper`）。

---

## 专利类型速查

| 类型 | 保护对象 | 保护期限 | 审查制度 | 适用场景 |
|------|---------|---------|---------|---------|
| 发明专利 | 产品、方法的技术方案 | 20 年 | 实质审查 | 核心技术创新 |
| 实用新型 | 产品形状/构造的改进 | 10 年 | 初步审查 | 产品结构改进、快速保护 |
| 外观设计 | 产品外观的新设计 | 15 年 | 初步审查 | 产品外观设计 |

## 执行流程

### Phase 1: 技术方案收集与分析

**操作步骤**：
1. 接收技术方案描述，理解核心技术点
2. 识别技术问题和技术效果
3. 分析技术方案的具体实施方式
4. 推荐合适的专利类型
5. 生成发明交底书

**交底书结构**：
```
## 发明名称
## 技术领域
## 背景技术（现有技术及其不足）
## 发明内容
  - 要解决的技术问题
  - 技术方案（核心）
  - 有益效果
## 具体实施方式（结合附图）
## 附图说明
```

**质量门禁**：技术问题、技术方案、技术效果三要素完整。

### Phase 2: 权利要求书撰写

**操作步骤**：
1. 确定保护范围，撰写独立权利要求
2. 撰写从属权利要求，构建多层次保护
3. 审查权利要求的清楚性、支持性、层次性

**独立权利要求格式**：
```
[主题名称]，其特征在于，包括：
[技术特征 A]；
[技术特征 B]；
...
[技术特征 N]。
```

**从属权利要求格式**：
```
根据权利要求 [X] 所述的 [主题名称]，其特征在于，所述 [引用特征] 进一步包括：
[附加技术特征]。
```

**撰写原则**：
- 独立权利要求包含所有必要技术特征
- 从属权利要求进一步限定，层次分明
- 方法专利用步骤描述，产品专利用结构描述
- 避免模糊用语（"大约"、"左右"等）

**质量门禁**：独立权利要求包含所有必要技术特征；从属权利要求层次分明。

### Phase 3: 说明书撰写

**操作步骤**：
1. 技术领域：一句话说明所属技术领域
2. 背景技术：描述现有技术及其不足（客观评价，不贬低）
3. 发明内容：技术问题 + 技术方案 + 有益效果
4. 附图说明：各附图的名称和简要说明
5. 具体实施方式：结合附图详细描述，提供具体实施例

**质量门禁**：五部分完整；充分公开使本领域技术人员能够实现。

### Phase 4: 摘要撰写

**操作步骤**：
1. 技术问题概述 + 技术方案要点 + 技术效果概述
2. 选择最能说明技术方案的摘要附图

**质量门禁**：摘要 <= 300 字；包含技术问题+方案+效果。

### Phase 5: 审查意见回复（OA 回复）

**操作步骤**：
1. 分析审查意见，识别驳回理由（新颖性/创造性/实用性/清楚性/支持性）
2. 制定回复策略：接受 / 部分接受 / 礼貌反驳
3. 撰写回复意见，提供技术论证和法律依据
4. 必要时修改权利要求书

## 输出规范

遵循 `shared/output-conventions.md` 中的 patent 部分：
- 输出目录：`patent/output/`
- 文件命名：`{project-name}-{document-type}.md`
- 必需产出：disclosure → claims → description → abstract

---

## 约束

1. **法律免责声明**：生成的专利文档仅供参考，正式提交前建议咨询专利代理人
2. **不虚构技术效果**：所有技术效果必须基于用户提供的真实数据
3. **充分公开**：说明书必须充分公开技术方案
4. **支持性要求**：权利要求书必须得到说明书的支持
5. **用语规范**：使用专利标准用语，避免口语化表达

---

## 上下文接口

**读取**（从 `shared/context-schema.md`）：
- `project.*`：项目名称、描述、技术栈、创新点

**写入**（供下游技能使用）：
- `patent.disclosure`：技术交底书（可传递给 `paper` 作为方法描述基础）
- `patent.claims`：权利要求书（可传递给 `copyright` 辅助功能描述）

## 生态集成

| 集成模块 | 触发条件 | 集成方式 |
|---------|---------|---------|
| `copyright` | 专利提交后需要软著保护 | 传递技术方案给 copyright |
| `paper` | 先专利后论文的知识产权保护链路 | 传递创新点给 paper |
| HOS-Vibe-Guard | 撰写具体实施方式时 | 确保技术方案描述有足够技术深度 |
