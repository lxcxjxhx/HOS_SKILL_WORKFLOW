# 博客写作 Skill（Blog Writing Skill）

> 完全自研的多平台博客写作系统，支持 CSDN、掘金、知乎、Medium、Dev.to 五大平台的格式自动适配与 SEO 优化。

---

## 一、触发条件

当用户输入匹配以下任意场景时，自动激活本 Skill：

### 1.1 直接触发词
- "写博客"、"写一篇博客"、"帮我写博客"
- "写一篇技术文章"、"写一篇教程"、"写一篇案例"
- "写一篇 CSDN 文章"、"写一篇掘金文章"、"写一篇知乎文章"
- "写一篇 Medium 文章"、"写一篇 Dev.to 文章"
- "博客写作"、"blog writing"、"technical writing"
- "发布到 CSDN/掘金/知乎/Medium/Dev.to"

### 1.2 意图触发
- 用户要求将技术内容整理成可发布的文章
- 用户要求将代码项目写成教程或案例分享
- 用户要求对已有文章进行多平台适配
- 用户要求对文章进行 SEO 优化
- 用户要求生成系列文章计划

### 1.3 文件触发
- 用户提供 `.md` 文件并要求转换为特定平台格式
- 用户提供代码文件并要求生成配套教程

## 三、工作流程

### 3.1 标准写作流程

```
用户需求 → 需求分析 → 大纲生成 → 用户确认 → 正文写作 → 平台适配 → SEO 优化 → 最终输出
```

**详细步骤：**

1. **需求分析**
   - 确认目标平台（单平台/多平台）
   - 确认文章类型（博客/教程/案例研究）
   - 确认目标读者和技术水平
   - 确认核心主题和关键要点

2. **大纲生成**
   - 根据需求选择合适的模板（`templates/`）
   - 生成文章大纲（标题层级、每节要点）
   - 生成候选标题（3-5 个）
   - 等待用户确认或调整

3. **正文写作**
   - 按大纲逐节生成内容
   - 插入代码示例和说明
   - 添加图表和插图占位
   - 确保技术准确性

4. **平台适配**
   - 根据目标平台转换格式
   - 调整标签和分类
   - 适配图片引用方式
   - 检查平台特有语法

5. **SEO 优化**
   - 关键词分析和优化
   - 标题和描述优化
   - 结构层级检查
   - 生成 SEO 报告

6. **最终输出**
   - 输出适配后的文章文件
   - 输出 SEO 优化报告
   - 输出发布建议

### 3.2 快速写作流程

当用户要求快速生成时，跳过确认步骤：

```
用户需求 → 自动判断 → 直接生成 → 平台适配 → 输出
```

### 3.3 平台适配流程

当用户提供已有文章要求适配时：

```
输入文章 → 识别原格式 → 选择目标平台 → 格式转换 → 标签适配 → 输出
```

## 五、使用指南

### 5.1 写博客文章

**输入示例：**
```
帮我写一篇关于 Python 异步编程的博客文章，发布到 CSDN 和掘金
```

**执行流程：**
1. 识别文章类型：技术博客
2. 加载模板：`templates/blog-post-template.md`
3. 生成大纲和候选标题
4. 确认后生成正文
5. 分别适配 CSDN 和掘金格式
6. 输出两个平台版本 + SEO 报告

### 5.2 写技术教程

**输入示例：**
```
写一篇关于 Docker 容器化的技术教程，面向初学者
```

**执行流程：**
1. 识别文章类型：技术教程
2. 加载模板：`templates/technical-tutorial.md`
3. 生成包含步骤、代码示例、练习的教程
4. 适配目标平台格式
5. 输出教程 + 代码清单

### 5.3 写案例研究

**输入示例：**
```
把我们项目中使用微服务架构的经验写成案例研究，发布到知乎
```

**执行流程：**
1. 识别文章类型：案例研究
2. 加载模板：`templates/case-study.md`
3. 生成包含背景、方案、效果的结构化案例
4. 适配知乎格式（富文本友好）
5. 输出案例 + 话题标签建议

### 5.4 多平台适配

**输入示例：**
```
把这篇 CSDN 文章适配到掘金、知乎和 Medium
```

**执行流程：**
1. 读取输入文章
2. 分析原文章结构和格式
3. 分别加载三个目标平台指南
4. 执行格式转换和内容调整
5. 输出三个平台版本

### 5.5 SEO 优化

**输入示例：**
```
帮我优化这篇文章的 SEO，目标是搜索引擎首页
```

**执行流程：**
1. 读取文章
2. 加载 SEO 检查清单
3. 执行全面 SEO 分析
4. 生成优化建议和修改后的版本
5. 输出 SEO 报告

## 六、平台特性详解

### 6.1 CSDN
- **编辑器**：Markdown 编辑器
- **代码块**：支持语法高亮，使用 ` ```language ` 格式
- **数学公式**：支持 LaTeX，行内 `$...$`，块级 `$$...$$`
- **目录**：自动生成，基于 H1-H6 标题
- **图片**：支持上传和外部链接，建议上传到 CSDN 图床
- **标签**：最多 5 个标签，第一个为主标签
- **专栏**：支持将文章加入专栏
- **特殊注意**：避免过多外部链接，优先引用 CSDN 站内文章

### 6.2 掘金
- **编辑器**：Markdown 编辑器
- **标记语法**：支持标准 Markdown + 部分扩展语法
- **代码块**：支持语法高亮，使用 ` ```language ` 格式
- **图片**：仅支持上传到掘金图床（不支持外部链接）
- **标签**：最多选择 1 个标签（分类标签）
- **专栏**：支持创建和管理专栏
- **特殊注意**：文章质量审核较严，避免营销内容

### 6.3 知乎
- **编辑器**：富文本编辑器（也支持 Markdown 导入）
- **公式**：支持 LaTeX 公式
- **话题标签**：使用 `#话题#` 格式，建议 3-5 个
- **专栏**：支持创建专栏
- **图片**：支持上传和外部链接
- **特殊注意**：知乎偏好深度内容，避免纯技术堆砌，注重可读性

### 6.4 Medium
- **编辑器**：专有富文本编辑器
- **语言**：主要面向英文读者
- **标签**：最多 5 个标签
- **Publication**：支持加入 Publication 增加曝光
- **图片**：支持上传，自动托管
- **代码块**：有限的代码支持，建议长代码使用 Gist 嵌入
- **特殊注意**：Partnership 计划可获利，注意内容原创性

### 6.5 Dev.to
- **编辑器**：Markdown 编辑器
- **Front Matter**：YAML 格式的元数据（title, published, tags, series, cover_image）
- **Liquid 标签**：支持 Liquid 模板语法（`{% embed %}`, `{% twitter %}` 等）
- **代码块**：支持语法高亮 + 文件名标注
- **系列文章**：原生支持 series，自动关联同系列文章
- **标签**：最多 4 个标签
- **特殊注意**：开源社区友好，鼓励分享学习和经验

## 七、输出规范

### 7.1 文件命名
- 博客文章：`{slug}.md`（如 `python-async-guide.md`）
- 平台适配：`{slug}-{platform}.md`（如 `python-async-guide-csdn.md`）
- SEO 报告：`{slug}-seo-report.md`

### 7.2 输出格式
每篇文章输出包含：
1. **元数据区**：标题、摘要、标签、分类、封面图建议
2. **正文区**：完整文章内容
3. **附录区**（可选）：参考资料、代码清单、术语表

### 7.3 质量标准
- 标题：简洁有力，包含核心关键词，15-25 字
- 摘要：100-300 字，概括核心内容，引发阅读兴趣
- 正文：结构清晰，代码准确，图文配合
- 标签：精准匹配内容，覆盖主要技术点
- SEO：关键词自然分布，标题层级合理，描述完整

---

## 八、注意事项

1. **技术准确性**：所有代码示例必须可运行，技术描述必须准确
2. **平台规则**：严格遵守各平台的内容规范和格式要求
3. **原创性**：生成的内容应为原创，避免抄袭和洗稿
4. **多平台差异**：同一内容在不同平台发布时，需根据平台特性调整表达方式
5. **图片版权**：建议使用原创图片或开源图片，注意版权问题
6. **SEO 适度**：SEO 优化不应影响文章可读性，避免关键词堆砌
