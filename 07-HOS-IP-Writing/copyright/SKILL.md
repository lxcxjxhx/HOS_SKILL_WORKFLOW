# 软件著作权申请文档自动生成

> 从代码仓库自动生成符合中国版权保护中心要求的软著申请材料。

---

## 触发条件

| 触发场景 | 示例表达 |
|---------|---------|
| 申请软著 | "帮我申请软著"、"生成软著材料" |
| 从仓库生成 | "从 GitHub 仓库生成软著文档" |
| 软件说明书 | "生成软件说明书"、"写用户手册" |
| 材料准备 | "准备软著材料"、"软件著作权登记" |

**不触发**：专利申请（→ `patent`），论文写作（→ `paper`）。

---

## 执行流程

### Phase 1: 代码仓库分析

**操作步骤**：
1. 读取仓库 URL 或本地路径
2. 提取 README.md 内容
3. 分析项目结构（目录树）
4. 识别技术栈（package.json / requirements.txt / pom.xml 等）
5. 提取核心模块和功能列表
6. 识别关键算法和技术亮点

**质量门禁**：技术栈识别完成；核心模块列表 >= 3 个。

### Phase 2: 文档生成

**操作步骤**：
1. 生成软件基本信息（名称、版本号、开发完成日期、用途）
2. 生成软件说明书，包含以下章节：
   - 引言（编写目的、背景）
   - 软件概述（功能、性能）
   - 运行环境（硬件、软件）
   - 使用说明（安装、配置、操作）
   - 模块设计说明
   - 功能详细说明
   - 关键算法描述
   - 数据库设计
   - 流程图说明
3. 生成辅助文档（创新点总结、截图指南、材料清单）

**质量门禁**：软件说明书包含所有必需章节（引言/概述/环境/使用说明）。

### Phase 3: 输出与调整

**操作步骤**：
1. 按模板生成所有必需文档
2. 展示文档摘要供用户确认
3. 根据反馈调整内容
4. 补充特定信息（截图、具体日期等）

**质量门禁**：文档符合版权保护中心格式要求；软件名称规范。

---

## 格式规范

### 软件名称规范
- 全称格式：`XXX软件` 或 `XXX系统`
- 简称：不能使用英文缩写
- 版本号：`VX.X` 格式

### 文档格式要求
- 说明书页数：一般 10-60 页
- 代码文档：前 30 页和后 30 页（每页 50 行）
- 字体字号：宋体小四或仿宋_GB2312 小四

### 常见驳回原因
- 软件名称不规范
- 功能描述过于简单
- 缺少必要章节
- 截图不清晰或缺失
- 代码文档格式不符合要求

---

## 输出规范

遵循 `shared/output-conventions.md` 中的 copyright 部分：
- 输出目录：`copyright/output/`
- 文件命名：`{software-name}-{document-type}.md`
- 必需产出：info → description → source-code

---

## 约束

1. **无法自动生成代码文档**：需手动提取源代码前后各 30 页
2. **无法生成实际截图**：仅提供截图指南
3. **无法自动提交申请**：需用户手动在版权保护中心操作
4. **生成文档需人工审核**：AI 生成内容仅供参考

---

## 上下文接口

**读取**（从 `shared/context-schema.md`）：
- `project.*`：项目名称、描述、技术栈
- `project.code-repo`：代码仓库 URL（用于自动分析）

**写入**（供下游技能使用）：
- `copyright.documents`：完整文档包（可传递给 `blog` 生成技术介绍文章）
