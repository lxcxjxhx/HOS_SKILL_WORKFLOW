# 管线：内容工厂

> blog(多篇) → review(统一润色) → book(合集)

---

## 触发条件

用户表达以下意图时激活此管线：
- "帮我批量生产内容"
- "写一组主题文章"
- "把博客合集整理成书"

## 链路

```
blog (多篇独立文章) → review (统一润色) → book (合集)
```

## 与 HOS-Fuck-Demo 集成

当用户同时使用 HOS-Fuck-Demo 时，管线扩展为：

```
Fuck-Demo (内容包) → blog (适配发布) → review (统一润色) → book (合集)
```

Fuck-Demo 产出的内容包（PPT 脚本、视频脚本、项目介绍等）可作为 blog 的输入素材。

## 执行步骤

### Step 1: 批量博客生成

1. 确定内容主题矩阵：
   - 核心主题 1 篇（深度长文）
   - 相关主题 3-5 篇（不同角度）
   - 实践主题 1-2 篇（教程/案例）
2. 为每篇文章执行 blog 执行流程
3. 确保文章间有交叉引用但不重复
4. 输出文章集

### Step 2: 统一润色

1. 读取所有文章
2. 执行批量润色：
   - 风格统一（语气、用词、格式）
   - 术语一致性检查
   - 代码示例风格统一
   - 交叉引用验证
3. 输出润色后文章集 + 修改报告

### Step 3: 合集整理

1. 确定合集结构：
   - 按主题分组
   - 按难度递进
   - 按时间线排列
2. 生成合集框架：
   - 合集前言（概述所有文章的关系）
   - 文章排序
   - 补充过渡段落
   - 生成合集目录
3. 输出合集

## 质量门禁

| 节点 | 标准 |
|------|------|
| blog 每篇完成 | 独立可读；代码可运行；字数符合平台要求 |
| review 完成 | 风格统一；术语一致；无 AI 套路 |
| book 合集完成 | 结构合理；过渡自然；目录完整 |

## 上下文传递

```
Fuck-Demo → blog (如适用):
  传递: 内容包 + 核心要点
  格式: Fuck-Demo 产出文件

blog → review:
  传递: 所有文章 + 术语表 + 风格指南
  格式: Markdown 文件目录

review → book:
  传递: 润色后文章集 + 修改报告
  格式: Markdown 文件目录
```
