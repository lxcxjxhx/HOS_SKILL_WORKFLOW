# 📝 审稿回复工作流

> 从收到审稿意见到完成修改的全流程指南。帮助作者系统化地处理审稿意见，撰写高质量的 rebuttal/revision。

---

## 🎯 工作流概览

```
收到审稿意见
    ↓
Step 1: 情绪管理与初步分析
    ↓
Step 2: 审稿意见分类
    ↓
Step 3: 制定修改计划
    ↓
Step 4: 执行修改
    ↓
Step 5: 撰写 Response Letter
    ↓
Step 6: 最终检查与提交
```

**预计总时长**：1-4 周（取决于修改量）

---

## Step 1: 情绪管理与初步分析

**时长**：1-3 天（建议冷静 24 小时后再开始）

### 1.1 情绪管理

```
重要提醒：
1. 收到负面评价时，先冷静 24 小时
2. 审稿意见是针对论文，不是针对你个人
3. 即使是拒稿，也是有价值的反馈
4. 大多数论文都经历了修改-重投的过程
5. 保持专业、礼貌的态度
```

### 1.2 初步分析

```
操作：
1. 通读所有审稿意见（不做回应，只是阅读）
2. 标记哪些意见是合理的
3. 标记哪些意见存在误解
4. 标记哪些意见你不同意
5. 统计：共有多少位审稿人？多少条意见？

输出：
- 审稿意见概览表
```

### 1.3 判断投稿状态

| 状态 | 说明 | 策略 |
|------|------|------|
| **Accept** | 直接接收 | 几乎不需要修改 |
| **Minor Revision** | 小修 | 逐条修改，通常可接收 |
| **Major Revision** | 大修 | 需要大量修改，但仍有接收机会 |
| **Reject & Resubmit** | 拒稿但允许重投 | 当作新论文处理，需要重大改动 |
| **Reject** | 拒稿 | 分析意见后转投其他会议/期刊 |

---

## Step 2: 审稿意见分类

**时长**：1-2 天

### 2.1 分类标准

将每条审稿意见分为以下类别：

| 类别 | 说明 | 处理方式 |
|------|------|---------|
| **A - 必须修改** | 影响论文正确性的问题 | 必须修改，无例外 |
| **B - 应该修改** | 影响论文质量的问题 | 尽量修改 |
| **C - 可以修改** | 改善论文的建议 | 选择性修改 |
| **D - 不同意** | 你认为不正确的意见 | 礼貌反驳，提供证据 |
| **E - 误解** | 审稿人理解有误 | 澄清误解，改善表述 |

### 2.2 创建审稿意见跟踪表

```markdown
| 编号 | 审稿人 | 意见内容（摘要） | 类别 | 修改方案 | 状态 |
|------|--------|----------------|------|---------|------|
| R1-1 | R1 | ... | A | ... | 待修改 |
| R1-2 | R1 | ... | B | ... | 待修改 |
| R2-1 | R2 | ... | D | ... | 待反驳 |
| R2-2 | R2 | ... | E | ... | 待澄清 |
```

### 2.3 识别共性问题

```
检查：
1. 多个审稿人是否提出了相同的问题？
   → 这通常是核心问题，必须优先处理
2. 是否有系统性的问题（如实验不足、写作不清）？
   → 需要整体性修改，而非逐条修补
3. 是否有审稿人特别正面？
   → 可以在 response 中引用正面评价
```

---

## Step 3: 制定修改计划

**时长**：1-2 天

### 3.1 优先级排序

```
优先级 1（必须立即处理）：
- A 类：影响正确性的问题
- 多个审稿人共同提出的问题
- 审稿人明确标记为 "critical" 的问题

优先级 2（应该处理）：
- B 类：影响质量的问题
- 需要补充的实验

优先级 3（选择性处理）：
- C 类：改善性建议
- D/E 类：需要反驳或澄清的意见
```

### 3.2 评估工作量

```
操作：
1. 估算每条修改需要的时间
2. 检查是否有需要补充的实验
3. 评估是否需要在截止日期前完成
4. 如有必要，与导师/合作者讨论分工

输出：
- 修改计划时间表
```

### 3.3 决定策略

| 情况 | 策略 |
|------|------|
| 所有审稿人正面，只有小问题 | 快速修改，礼貌回复 |
| 审稿意见分歧大 | 在 response 中突出正面评价，逐条回应负面意见 |
| 需要大量补充实验 | 优先做最关键的实验，其余在 limitation 中说明 |
| 审稿人有明显错误 | 礼貌指出，提供证据，不要对抗 |

---

## Step 4: 执行修改

**时长**：1-3 周

### 4.1 修改原则

```
1. 宁多勿少：能改的地方都改，即使你认为不必要
2. 标记修改：使用高亮/颜色标记所有修改内容
3. 保持一致：修改一处后检查全文是否需要同步修改
4. 记录变更：记录每处修改的位置和内容
```

### 4.2 常见修改类型

#### 补充实验

```
操作：
1. 确定需要补充的实验
2. 使用相同的实验设置
3. 将新结果整合到论文中
4. 更新相关章节的讨论

注意：
- 新实验必须与现有实验设置一致
- 如果无法复现原始结果，诚实说明
```

#### 改善写作

```
操作：
1. 重写被指出的问题段落
2. 检查全文是否有类似问题
3. 请合作者/母语者帮忙润色

注意：
- 不要只修改被指出的段落
- 检查全文的连贯性
```

#### 补充相关内容

```
操作：
1. 在 Related Work 中补充遗漏的文献
2. 在 Discussion 中补充遗漏的讨论
3. 在 Methods 中补充遗漏的细节

注意：
- 补充内容要与现有内容融合
- 注意篇幅限制
```

#### 修正错误

```
操作：
1. 修正公式推导错误
2. 修正图表中的错误
3. 修正数据/统计错误
4. 修正引用错误

注意：
- 修正后检查是否影响结论
- 如果结论需要改变，诚实修改
```

### 4.3 修改记录表

```markdown
| 编号 | 审稿意见 | 修改位置 | 修改内容摘要 | 修改类型 |
|------|---------|---------|-------------|---------|
| R1-1 | ... | Sec 3.2, p.5 | 重写了 XX 段落 | 写作改善 |
| R1-2 | ... | Table 2, p.7 | 补充了 XX 实验 | 补充实验 |
| R2-1 | ... | Sec 4.1, p.8 | 修正了公式 (3) | 错误修正 |
```

## Step 5: 撰写 Response Letter

**时长**：2-5 天

### 5.1 Response Letter 结构

```
Dear Editor and Reviewers,

We thank the reviewers for their constructive comments. 
We have carefully revised the paper based on the feedback. 
Below we provide point-by-point responses to each comment.

---

## Summary of Changes

[Brief overview of major changes]

---

## Response to Reviewer 1

### Comment 1: [原文引用]

**Response:** 
We thank the reviewer for this insightful comment. 
[Your response]

**Changes:** 
[Description of changes made, with page/line numbers]

---

### Comment 2: [原文引用]

**Response:**
[Your response]

**Changes:**
[Description of changes]

---

## Response to Reviewer 2

[Same structure]

---

We hope these revisions address all the concerns raised by the reviewers.
```

### 5.2 回复模板

#### 同意并修改

```
We thank the reviewer for this valuable suggestion. 
We agree that [acknowledge the point]. 
We have revised [section/page] to [describe the change].

Changes: [具体描述修改内容，标注页码/行号]
```

#### 补充实验

```
We appreciate the reviewer's suggestion to evaluate [aspect]. 
We have conducted additional experiments on [dataset/scenario]. 
The results are presented in Table X / Figure Y. 
As shown, [brief summary of results].

Changes: Added new experiments in Section Z (Page N, Lines M-M).
```

#### 礼貌反驳

```
We thank the reviewer for raising this point. 
However, we respectfully disagree that [point of disagreement], 
because [reason with evidence/citation]. 
Specifically, [detailed explanation]. 
We have clarified this in Section X (Page N) to avoid confusion.

Changes: Clarified the discussion in Section Z (Page N).
```

#### 澄清误解

```
We apologize for the lack of clarity in the original manuscript. 
The reviewer's concern about [concern] stems from our unclear presentation. 
To clarify, [clear explanation]. 
We have revised Section X to make this clearer.

Changes: Revised Section Z (Page N, Lines M-M) for clarity.
```

#### 无法修改（如篇幅限制）

```
We thank the reviewer for this suggestion. 
While we agree that [acknowledge value], 
we are unable to [action] due to [constraint, e.g., page limit]. 
However, we have [alternative action, e.g., added a brief discussion / 
moved to supplementary material / noted as future work].

Changes: [Describe alternative action taken].
```

### 5.3 回复注意事项

```
✅ 必须做到：
1. 逐条回复每一条意见
2. 引用审稿人的原文
3. 标注修改的具体位置（页码/行号）
4. 保持礼貌、专业的语气
5. 对每位审稿人都表示感谢
6. 用不同颜色/字体区分审稿人意见和你的回复

❌ 绝对不要：
1. 忽略任何一条意见
2. 使用对抗性语言（"The reviewer is wrong"）
3. 过度道歉（"We are sorry for this terrible mistake"）
4. 做虚假承诺（"We will add this in the final version"）
5. 在回复中包含未修改的内容
```

### 5.4 中英文回复示例

#### 英文回复示例

```
Reviewer 1, Comment 3: "The authors should compare their method with 
Baseline X [citation]."

Response: We thank the reviewer for this suggestion. We have added 
Baseline X [citation] to our comparison. The results are shown in 
Table 2 (Page 7). Our method outperforms Baseline X by 12.3% on 
Metric A, while achieving comparable performance on Metric B. 
This improvement can be attributed to [brief reason].

Changes: Added comparison with Baseline X in Table 2 (Page 7, 
Section 4.2). Updated Related Work to discuss Baseline X (Page 3).
```

#### 中文回复示例

```
审稿人 1，意见 3："作者应与基线方法 X [引用] 进行对比实验。"

回复：感谢审稿人的建议。我们已补充了与基线方法 X [引用] 的对比实验。
结果如表 2 所示（第 7 页）。本文方法在指标 A 上比基线方法 X 提升了 
12.3%，在指标 B 上取得了相当的性能。这一提升可归因于 [简要原因]。

修改：在表 2（第 7 页，第 4.2 节）中补充了与基线方法 X 的对比。
更新了相关工作部分以讨论基线方法 X（第 3 页）。
```

## Step 6: 最终检查与提交

**时长**：1-2 天

### 6.1 修改稿检查

```
检查清单：
- [ ] 所有审稿意见都已回复
- [ ] 所有承诺的修改都已执行
- [ ] 修改位置都已标注（页码/行号）
- [ ] 修改内容与回复一致
- [ ] 全文已通读，无遗漏修改
- [ ] 图表已更新
- [ ] 参考文献已更新
- [ ] 篇幅仍符合要求
```

### 6.2 Response Letter 检查

```
检查清单：
- [ ] 每条意见都有回复
- [ ] 回复语气礼貌、专业
- [ ] 修改位置标注准确
- [ ] 审稿人意见用不同格式区分
- [ ] 没有拼写/语法错误
- [ ] 开头和结尾致谢完整
```

### 6.3 提交

```
操作：
1. 登录投稿系统
2. 上传修改稿（标注修改版本）
3. 上传 Response Letter
4. 上传修改标记版（如要求）
5. 确认提交
6. 保存提交确认

注意：
- 保留所有文件的备份
- 记录提交日期
```

## ⚠️ 特殊情况处理

### 情况 1：审稿人之间意见矛盾

```
策略：
1. 在 response 中指出矛盾
2. 说明你选择了哪个方向及理由
3. 如果可能，同时满足两个审稿人
4. 请 editor 做最终判断

示例：
"Reviewer 1 suggests [A], while Reviewer 2 suggests [B]. 
We have chosen to [your choice] because [reason]. 
We believe this addresses both concerns by [explanation]."
```

### 情况 2：审稿人要求引用其论文

```
策略：
1. 检查被引用的论文是否真的相关
2. 如果相关：正常引用，不需要特别说明
3. 如果不相关：礼貌说明为什么不引用
4. 绝对不要为了讨好审稿人而引用不相关的文献

示例（相关）：
"We thank the reviewer for pointing out this relevant work. 
We have added a discussion of [paper] in Section 2.3 (Page 4)."

示例（不相关）：
"We thank the reviewer for the suggestion. After careful consideration, 
we believe that [paper] focuses on [different topic], which is outside 
the scope of our work. However, we have added a brief mention in the 
Related Work section to provide broader context."
```

### 情况 3：审稿人有明显事实错误

```
策略：
1. 不要直接说 "The reviewer is wrong"
2. 用 "We would like to clarify..." 开头
3. 提供证据（引用、数据、公式推导）
4. 承认可能是自己的表述不够清楚

示例：
"We appreciate the reviewer's careful reading. We would like to clarify 
that [correct information]. This is supported by [evidence]. 
We apologize if our original presentation was unclear and have revised 
Section X (Page N) to make this more explicit."
```

### 情况 4：需要大幅修改但时间不够

```
策略：
1. 优先处理 A 类和共性问题
2. 对于无法完成的修改，诚实说明
3. 将其列为 future work
4. 请求 editor 理解

示例：
"We acknowledge the reviewer's suggestion to [suggestion]. 
While we agree this would strengthen the paper, implementing [action] 
requires [time/resource] that is beyond the scope of the current 
revision. We have added a discussion of this direction in Section 5.4 
(Page N) as important future work."
```
