## 一、主对比：FuzzingBrain V2 vs AEGIS vs HOS-LS（论文核心表）

| 维度 | FuzzingBrain V2（2605.21779） | AEGIS（2603.20637） | **HOS-LS（本系统）** |
|------|-------------------------------|---------------------|----------------------|
| **路线** | LLM + fuzzing（动态） | LLM + CPG 图谱（静态推理） | **hybrid：静态规则 → LLM → 确定性验证** |
| **验证闭环** | OSS-Fuzz 复现（报告必须 fuzzer 可复现）✅ | Audit Agent 单向否决（与 Verifier 同模型）⚠️ | DynamicLoader + Validator Registry + sanitizer 仲裁（确定性） |
| **Agent 架构** | 自研 BaseAgent loop + 固定流水线阶段 | 四层管线（线索→证据→辩证→元审计） | 7 Agent + LangGraph 编排 + AIDecisionEngine 自适应 |
| **检索/知识** | fuzz 靶标驱动 | CPG 图谱 | RAG 混合检索（BM25+向量）+ NVD/ExploitDB |
| **评测集** | AIxCC 2025 场景 + OSS-Fuzz | PrimeVul（首个破 100 Pair-wise） | 待定（建议 PrimeVul 函数级+仓库级 + 自建 post-cutoff 样本） |
| **成本** | ~$20 可跑（声称） | 未披露 | 需实测（有 token 跟踪模块，可量化） |
| **口径问题（RVE）** | 29 vs 41 零日矛盾（HIGH）；90% 赛后回测 vs 现场 44%（HIGH）；39/41 零日不可核验（MED） | FPR 口径非常规 fp=P-V+P-R（HIGH）；122 vs 96 单次运行无统计（MED）；README 声称文件不在仓库（MED） | **无（论文必须公开全部口径）** |
| **评分（HOS 评审）** | 67/100 🟡 | 66/100 🟡 | — |

## 二、补充对照 1：DREA（2607.13439，Internetware 2026）

| 项 | 内容 | 对 HOS-LS 的用途 |
|----|------|------------------|
| 贡献 | Agent 解耦（Reasoning/Exploring 分离）+ RepoPairBench | 对比 Agent 编排设计：HOS-LS 7 Agent 分工 vs DREA 双 Agent 解耦 |
| 成本 | token offload 93%、成本降 16-48x | **HOS-LS 的 token 效率对标**（HOS-LS 有分层扫描省 50-80% token 的机制，正好同台） |
| 口径问题 | 基准样本修在测试文件（HIGH）；公开 CVE 训练记忆污染（HIGH）；LLM-as-judge 自指偏置（MED） | 反面教材：评测集必须 post-cutoff；judge 必须盲审 |
| 可借鉴 | 主动自曝 Lucky Hits 负结果（26-55% TP 推理理由错误）——2026 最诚实的自我解剖 | HOS-LS 也可公开「误报误判清单」，比自评 92/100 可信 |

## 三、补充对照 2：PrimeVul（ICSE 2025，评测基准）

| 项 | 内容 | 对 HOS-LS 的用途 |
|----|------|------------------|
| 贡献 | 严格去重 + 时间切分基准；BigVul 68.26% F1 → 3.09% | **HOS-LS「误报率 <5%」声称的现成尺子**：跑 PrimeVul 函数级 + 仓库级协议 |
| 口径问题 | 标签核验仅抽样 50 函数/基准（MED）；函数级评估盲区（HIGH）；无 SAST 对照（MED） | HOS-LS 的立足点：PrimeVul 证明函数级 code LM 不行，但没回答「AI+规则混合系统 vs Semgrep/CodeQL 行不行」——这就是 HOS-LS 论文要回答的问题 |
| 用法 | 协议参照（pair-wise + 1:32.8 不平衡 + 时间切分） | HOS-LS 评测协议直接引用/改编，保证与领域对齐 |
