## 二、单篇卡片

### 1. SCOUT（IEEE 2026）
- claim：LLM 通过交互式仓库探索（文件级图 + 按需拉取）做漏洞检测，降低一次性全量上下文成本。
- mechanism：文件级图导航 + 按需探索（标题级核实）。
- numbers：未核实。
- HOS-LS fit：阶段 2 Search Agent 的探索机制对照——HOS-LS 用 RAG+Top-K 候选筛选，SCOUT 用交互式图探索，路径不同但目标一致。
- verdict：**consider**。

### 2. Code-Augur（arXiv 2606.18619）
- claim：先推断代码规格（规范意图）再做漏洞判定，agent 按规格引导审计。
- mechanism：specification inference → 差分判定（标题级核实）。
- numbers：未核实。
- HOS-LS fit：阶段 3——「先建立意图模型再判偏差」与 HOS-LS 的 ContextAnalyzer/InputTracer 同属语义接地思路；其规格推断可作为 Agent prompt 增强参考。
- verdict：**consider**。

### 3. HoF-Bench（arXiv 2607.27030，AISLE 团队）
- claim：把「AI 真实发现并被确认的 CVE」做成可复现基准，验证非 frontier 模型也能复现。
- mechanism：Hall-of-Fame 风格 CVE 基准 + 可复现评测（标题级核实，GitHub 仓库存在）。
- numbers：未核实（GitHub README 可查）。
- HOS-LS fit：评测集——提供「真实 AI 发现 CVE」的对照口径；HOS-LS 的 RepoPairBench（真实 CVE pairs）与其互补。
- verdict：**adopt（评测参照）**——若投稿需展示「真实漏洞发现能力」，HoF-Bench 是补充证据。

### 4. Antaeus（arXiv 2607.01138）
- claim：针对仓库级**逻辑漏洞**（非内存安全类）的上下文接地 LLM 推理。
- mechanism：上下文接地推理 + 逻辑类漏洞猎捕（标题级核实）。
- numbers：未核实。
- HOS-LS fit：阶段 2/3——逻辑漏洞（认证/业务逻辑/配置错误）正是 HOS-LS 语义检测（CWE 语义 + 多 Agent 推理）的主场，Antaeus 可作同类定位对照。
- verdict：**consider**。

### 5. SEC-bench Pro（arXiv 2605.26548）
- claim：长程软件安全任务评测——单任务多步（漏洞发现→利用→修复）评测 LLM 能力。
- mechanism：多步安全任务编排基准（SEC-bench NeurIPS 2025 的 Pro 版，标题级核实）。
- numbers：未核实。
- HOS-LS fit：评测协议——多步任务的评测设计可借鉴；HOS-LS 的「检测→验证→报告」链路正好是多步任务的实例。
- verdict：**consider**。

### 6. EntailLLM（arXiv 2608.01763）
- claim：用逻辑编程（Prolog 类）+ 领域知识验证 LLM 漏洞发现路径，把「发现路径」变成可符号化验证的结论。
- mechanism：LLM 生成发现路径 → 逻辑程序编码 → 领域知识约束验证（标题级核实；检索命中含部分表格数字如 83(95.4%)，未完整核实）。
- numbers：部分核实（检索摘要含数值表，未全文核对）。
- HOS-LS fit：阶段 4——与 HOS-LS 的确定性验证闭环（DynamicLoader/Validator/sanitizer 仲裁）同一阵营：**验证必须独立于模型自证**。EntailLLM 用符号验证，HOS-LS 用执行/污点验证，可互相引用作为「LLM 结论必须过外部验证」的领域证据。
- verdict：**adopt（方法验证）**。

**HOS-LS 优势定位（可辩护版）**：
1. **同数据同 API 是唯一受控对比**——DREA 是 RepoPairBench 唯一同源可对账系统（§4.6），新增 6 篇均无同源数据可跑，HOS-LS 的 L1 受控对比设计（07 文档）在 2026 全景中仍然成立。
2. **确定性验证闭环是差异化武器**——EntailLLM（符号验证）、RECEIPT（XSS 确定性验证）与 HOS-LS（执行/污点/sanitizer 仲裁）构成「LLM 结论必须外部验证」的领域共识；HoF-Bench 的「AI 发现可复现性」进一步支持该方向。
3. **口径透明度**——新增论文（SCOUT/Code-Augur/Antaeus/SEC-bench Pro）均未核实到完整指标定义；HOS-LS 全部指标公开分子/分母/样本 ID，延续 16 篇评审教训的差异化立场。
