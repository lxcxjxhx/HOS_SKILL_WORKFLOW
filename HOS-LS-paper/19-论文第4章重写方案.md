## 1 §4.1 评测协议

### 1.1 任务定义（论文正文草稿）

> 本工作在**仓库级**设定下评测漏洞定位：给定 CVE 编号、漏洞描述与 CWE 类别，系统在**漏洞快照（修复提交 fix 的父提交 fix~1）**的完整仓库范围内定位漏洞代码（文件、函数与行号），**不提供目标文件路径**。与函数级逐文件扫描（RepoPairBench 原协议）的本质区别在于：系统必须自己完成"全仓候选生成 → 语义筛选 → 定位"的完整链路，且可利用仓库级结构（文件粒度差异、调用关系、真实污点传播）。

**评测协议由两个机制构成**：差分证据协议（DEP）保证"检出的漏洞可复验"，Sink 锚定定位（SAL）保证"定位有锚、候选有界"。二者叠加形成本工作的协议层贡献。

### 1.2 DEP —— 差分证据协议（论文正文草稿）

**定义**：把"漏洞"操作化为**双快照差分中消失且可达的危险模式**。

- **双快照独立输入**：漏洞快照（fix~1）与修复快照（fix）**分别、独立**地交给系统分析（模型不知配对关系，无泄露）。
- **消失性判定**：验证链合并两端输出，做确定性判定：
  **CONFIRMED ⇔ 定位命中（报告文件/函数 ∈ fix diff 涉及文件）∧ 该危险模式在修复快照的同构位置消失（不再被报告）。**
- **真实场景映射**：审计员手上同时持有升级前后两个版本——双快照差分就是真实审计动作，而非评测取巧。
- **结构性收益**：
  1. Pair-Correct 从"事后统计口径"变成"验证链内建语义"（不再依赖事后过滤 patched 端输出）；
  2. "修复不完整"类误报（原表 6 的 0294b9f1 XXE、0f0215bf SSRF 类）被**结构性压制**——patched 端仍报告即不满足消失性；
  3. 每个 CONFIRMED 均可被审稿人**机械复验**（双端 diff 对照），对抗 Lucky Hit。

### 1.3 与 DREA / AEGIS 的协议层差异（论文正文草稿 + 表）

> 与 2026 年相关系统的差异不在"模型多强"而在**协议层**：DREA 与 AEGIS 均为**单快照**协议——系统只在漏洞版本上取证，验证依赖模型自述或内部辩论；本工作引入**双快照差分**，把"修复后消失"变成可机械判定的必要条件。

**表 4-1　协议层差异（DREA / AEGIS / HOS-LS）**

| 维度 | DREA [27] | AEGIS [26] | **HOS-LS（本工作）** |
|---|---|---|---|
| 协议输入 | 单快照（漏洞版本）Planner→Explorer 全仓取证（~10 轮/样本） | 单快照 CPG 切片 + Clue Discovery → 红蓝辩证辩论 | **双快照（fix~1 / fix）独立输入**，模型不知配对 |
| 验证机制 | 模型自述 + LLM-as-Judge 推理正确性（4 准则） | 辩证验证 + 审计 veto（四类推理缺陷） | **确定性消失性判定** + SAST 硬证据 + AI 证据链 |
| 定位机制 | 探索式假设取证（按目标导向，无显式 sink 锚） | CPG 按需切片（最坏情况 taint 假设） | **SAL：CWE→sink 锚定候选 + 可达性剪枝** + Search Agent Top-K |
| Pair-Correct 语义 | 事后统计 | 事后统计 | **验证链内建**（消失性判定） |
| 差分信号 | 无（单快照） | 无（单快照） | **有**（双快照） |
| 对抗 Lucky Hit | LLM-as-Judge（human κ 标定，自曝 26–55% TP 为 Lucky Hits） | 审计 veto（依赖模型自省） | **机械复验**（双端 diff 对照，可人工复核） |

> 【重写说明】该表即新 §4.1 的核心论证表；引用编号沿用论文参考文献表（DREA [27]、AEGIS [26]）。

### 1.4 SAL —— Sink 锚定定位（论文正文草稿）

**定义**：CWE→sink 模式映射 + 数据流可达性判定，定位从"全仓语义猜测"变为"sink 锚定的候选生成 + 可达性剪枝"。

- 机制：CVE 描述/CWE → sink 模式集（如 CWE-78 → `Runtime.exec`/`ProcessBuilder`/`subprocess`；CWE-502 → 反序列化入口；CWE-79 → `innerHTML`/`v-html`）→ 仓库内锚定候选文件（正则/SAST 命中）→ AI 只分析"可达 sink"。
- 收益：
  1. 消除类型错位/描述错位类漏检（原表 6 的 00c73b6e / 03e97308 / 0dc2e99d 类）；
  2. AI 候选集从全仓 Top-K 压缩到 sink 相关文件，token 成本直接下降（压缩比 [TBD]，S2 消融项）；
  3. 与 DEP 叠加：**锚定（sink 存在）+ 消失性（双端模式差）= 静态可计算的证据对**，AI 只负责确认可达性与可利用性。

> 【重写说明】SAL 的 Java sink 表实现于 `hosls-eval/sal_java_sinks.json`；Python/TS 候选生成待扩展（Phase 3 工具链项）。

### 1.5 评测基准：VulnGym 仓库级漏洞猎捕基准（论文正文草稿）

> 本工作的主基准为 **VulnGym**（腾讯，[arXiv 2608.02001](https://scirate.com/arxiv/2608.02001) · [GitHub](https://github.com/Tencent/VulnGym) · HF `tencent/VulnGym`）：**408 条仓库级漏洞条目（393 条 verify=1）**，全部源自 GitHub Advisory Database（reviewed），38 个开源项目。每条含 **fix commit、critical_operation（sink：文件/行/代码）、entry_point（source）、完整 trace 利用链、L1/L2 分类、CVE/GHSA 编号**——通用、公开、可核验，非论文专用合成集；仓库级 + 业务逻辑盲点定位（L1 业务逻辑类 278/408 = 68%）恰是 HOS-LS 语义检测（CWE 语义 + 多 Agent 推理）的目标类型。

**数据转换**（实现于 `hosls-eval/vulngym_to_manifest.py`，0 API 成本）：
1. 393 条 verify=1 条目转 manifest（`bench-runs/framework-audit/manifest-vulngym.json`）；
2. 每条生成 ground truth：`file_paths` = critical_operation.file + entry_point.file + trace[].file（去重，251/393 为多文件利用链）；**sink_file/sink_line = critical_operation（定位主目标）**；
3. CWE 映射：L1 分类 → CWE（命令注入→CWE-78、反序列化→CWE-502、SSRF→CWE-918、XSS→CWE-79、路径穿越→CWE-22 等）；**业务逻辑类无单一 CWE（298/393），标记为语义类——SAL 无法锚定，靠 AI 语义推理**；
4. **commit 语义（实测确认）**：VulnGym 的 `commit` 是**漏洞存在/验证快照**（如 open-webui entry-00057 的 commit 为 "refac/fix: mermaid"，与 XSS 文件无关），**不是 fix commit**。因此：**vuln 快照 = commit 本身**；定位 ground truth = critical_operation（sink 文件+行+代码）；fix-diff 消失性判定为**可选增强**（需自行从 GHSA/版本历史定位 fix commit，默认不启用）。

**实测数据画像（2026-08-17 本地解析）**：语言分布 TypeScript 296 / Python 71 / Go 19 / 其余 7；框架分布 openclaw 182、n8n 45、Flowise 39、NVIDIA/NeMo 19、paperclip 17、langflow 8、mlflow 7 等（AI 应用框架为主）；95 条有 CWE（SAL 可锚定），298 条语义类。

**抽样与防偏置策略**：openclaw 单框架占 46%——按框架分层抽样（每框架上限 N 条）并分框架报告；S0/S1 优先小仓库 + 有 CWE 条目（先验证协议），S2 覆盖语义类。

> 注：此前规划的"8 框架审计集"（NVD/GHSA 自组 manifest，Dubbo/Nacos/RocketMQ 等）降级为**可选应用案例**（附录 E）：在 VulnGym 主结果之外，对个别中国企业常用框架做证据链审计展示，不承载主结论。

**RepoPairBench 降级说明**：RepoPairBench（DREA 自建 100 对）不再作为主协议，降级为**附录 A「历史对齐口径」**——仅用于与 DREA 函数级基线（19–26%）的同数据对账，保留 2026-08-16 的 50 样本实测（42.0% / 54.0% / 28.0% / 26.0%）作为历史存档行，不承载主结论。

## 2 §4.2 机制消融：A0 差分/锚定信号与仓库级必要性

> 本节论证链：**切片虚拟测试集缺乏差分信号（A0 量化）→ 差分/锚定信号的载体是仓库级真实结构 → 仓库级协议是 DEP/SAL 生效的必要条件**。本节数字来自 2026-08-17 完成的零 API 消融（详见 18 号文档与 `hosls-eval/reports/dep-ablation0-report.{md,json}`、`sal-ablation0-report.{md,json}`）。

### 2.1 静态差分信号在函数级切片上不可用

**表 4-3　A0 静态差分消融（100 对函数级切片，2026-08-17，0 API 调用）**

| 类别 | 系统静态层 | 官方规则（semgrep p/python + bandit） |
|---|---|---|
| V+P-（危险模式漏洞端命中、修复端消失 → 差分信号可用） | **4/100（4%）** | 1/100（1%） |
| V+P+（双端残留 → 误报风险） | 72/100 | 3/100 |
| V-P-（静态不可见，需 AI） | 20/100 | 96/100 |
| V-P+（静态误报） | 4/100 | 0 |

> 切片粒度下，漏洞函数与修复函数的结构高度相似（补丁往往仅改动数行），危险模式必然双端命中——差分信号仅 4%（官方规则 1%）。**差分信号在函数级切片上不可用，是"虚拟测试集脱离实际"的量化证据**：切片把真实审计中"升级前后两个版本"的差异抹平了。

### 2.2 锚定差分信号同样不可用

**SAL-A0**（100 对，CWE→sink 正则锚定）：漏洞端锚定命中 52%、修复端 58%、**vuln-only（差分信号）仅 1%**、双侧命中 51%。

> sink 模式在双端几乎同样频繁出现——锚定在切片粒度下**无判别力**。锚定要成为证据，必须依赖仓库级上下文（sink 的可达性、调用链、真实数据流），这正是 SAL 需要仓库级协议的原因。

### 2.3 Pair-Correct 口径的 46% 残留假阳性（A0 后处理）

复用 50 样本 AI 双端结果（`opt-hos-ls-vuln-50-results.json` / `opt-hos-ls-patched-50-results.json`）：

- 现状 Pair-Correct（vuln CONFIRMED ∧ patched 非 CONFIRMED）：**13/50**
- DEP 消失性判定后（vuln CONFIRMED ∧ patched **无 finding**）：**7/50**
- **6/13（46%）的"正确"样本其 patched 端仍残留 finding**——即"修复不完整"类样本被现有口径错误计为正确。

> 这是**可发表的机制发现**：现有 AI 漏洞定位评测的 Pair-Correct 口径存在系统性验证缺陷，DEP 是协议级修正（从"事后统计"到"验证链内建"）。A0 的 50 样本分析基于 confirmed/recog/findings 字段的数学结构对照，AI 端完整验证链下的收紧效应以 S1-A 付费消融实测为准 [TBD]。

### 2.4 仓库级必要性（旁证）

**证据 1 —— 上下文增益（原表 7，保留主文）**：在 octoprint 4 个样本上，从"单函数切片"切换到"完整函数源码 + 跨文件被调函数注入"后，检出由 **0/4 提升至 3/4**（表 4-4）。函数级切片截断了可判定信息，仓库级上下文直接消除该类漏检。

**表 4-4　上下文增益对比（octoprint 4 样本，原表 7）**

| 样本（pair） | CVE | 单函数（code_before 切片） | 深 CPG 上下文（完整源码 + 跨函数注入） |
|---|---|---|---|
| 6e68fb86 | CVE-2022-2822 | 0 | 2（检出） |
| 8c57d15f | CVE-2022-2930 | 0 | 2（检出） |
| d873de7f | CVE-2022-1430 | 0 | 0 |
| ee76e0c9 | CVE-2022-3068 | 0 | 1（检出） |

> 注：n=4 样本量小（随机性 ±2）；注入为空的 2 个样本亦检出，说明完整函数源码是主要变量，跨文件注入为次要因素。

**证据 2 —— 仓库级 CodeQL 硬命中（cascade，保留主文）**：仓库级三级 cascade（semgrep/bandit → CodeQL → AI 盲区）实测 9 对中 **5/9 目标文件被 CodeQL 硬命中**（0f0215bf path-injection、966c6ef1/ad9c9cd4 url-redirection、d873de7f、ee76e0c9），其中 **d873de7f、ee76e0c9 是函数级 AI 与 DREA 均漏检的盲区样本**——污点分析在真实仓库结构下才能成立（函数级切片下 CodeQL 0/21，见附录 A 历史行）。

**结论段（论文正文草稿）**：

> A0 消融表明：差分与锚定信号的载体是**仓库级真实结构**，而非函数级切片。切片虚拟测试集在构造上抹平了"修复前后"的差异（差分信号 4%、锚定差分 1%），并把 46% 的"修复不完整"样本误计为正确——这正是本工作把主协议升级为仓库级双快照（DEP）+ sink 锚定（SAL）的实验依据。需要强调的是，DEP 是**诚实性收紧器**：它首先使数字下降（13/50 → 7/50），但下降后的每个检出声称均可机械复验；定位率的提升必须来自仓库级上下文（0/4 → 3/4）与 SAL 锚定，而 DEP 保证提升后的数字可复现、可核验。

> **依赖数据**：

## 5 §4.5 局限与口径声明

### 5.1 跨源不可比（论文正文草稿）

> 本工作的主基准为 VulnGym（TS/Python/Go、仓库级、双快照），与 AEGIS [26]/VulAgent 使用的 PrimeVul [7]（C/C++、函数级对级、单快照）**不同源、不同协议**，二者数字**不做直接优劣判定**；跨源对账仅作叙事背景（沿用原 §4.6 原则）。与 DREA [27] 的同数据对账保留在附录 A（RepoPairBench 历史对齐口径），标注协议差异（函数级单快照 vs 仓库级双快照）。

### 5.2 小样本置信区间（论文正文草稿）

> 受预算限制，新基准实测样本量 n=[TBD]（目标 ≥30）。比例指标（如 CONFIRMED）的 95% Wilson 置信区间宽度随 n 变化：n=30 时约 ±[TBD] 个百分点（以 p=0.5 计），n=50 时约 ±13.9 个百分点——主结论只基于区间不重叠的对比，细粒度分层结论标注样本数并降级为观察性结果。

### 5.3 AI 验证链 key 配置 caveat（论文正文草稿）

> A0 消融的 50 样本后处理基于 confirmed/recog/findings 字段的**数学结构对照**；基线结果文件的 stderr 含 `AI API key not configured, skipping AI verification`（验证链部分环节当时未配置 key）。因此**完整验证链下 DEP 收紧效应的最终数值以 S1-A 付费消融实测为准 [TBD]**；§4.3 主结果全部在配置完整 key 与余额门槛（`HOSLS_BALANCE_GATE`）下执行，并逐样本记录验证链完成状态。

### 5.4 其余声明（沿用原 §5.3/§5.4 要点）

- **单一模型**：所有 AI 层实验基于 deepseek-v4-flash，机制结论在恒定模型下成立，模型无关性不在声称范围内；
- **单次运行**：主结果为单次运行，多 seed 统计检验列为待补；
- **样本可追溯**：全部样本以 pair_id 公开，脚本与 manifest 随论文发布，口径定义（分子/分母/判定规则）全公开。

> **依赖数据**：无（声明类）；CI 数值与 n 待 S2 确定后填写 [TBD]。
