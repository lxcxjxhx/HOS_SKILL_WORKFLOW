## 二、50 样本 vs 100 样本：统计充分性

| 指标 | n=50 | n=100 | 差异 |
|---|---|---|---|
| 检出率 95% 置信区间（以 80% 为例） | 80% ± **11.1%** | 80% ± **7.8%** | 50 样本 CI 宽 3.3 个百分点 |
| 检出率 95% CI（以 50% 为例） | 50% ± **13.9%** | 50% ± **9.8%** | 同上 |
| 分层子集（函数内/跨函数/测试文件） | 每层约 17/10/5 | 每层约 35/20/10 | 100 才能支撑测试文件层（10 个样本）的独立结论 |
| 与 DREA 基线 19–26% 对比 | 50 样本可分辨（50% vs 26% 远超 CI） | 更稳 | **50 足够** |

**判断**：
- **若目标是对比类结论**（HOS-LS vs DREA 基线、vs 裸 LLM）——**50 样本足够**，差距远超置信区间。
- **若目标是分层细粒度结论**（测试文件层 10.0%）——50 样本里该层只有 ~5 个，结论弱；但可**按层加权抽样**缓解。
- **审稿人视角**：50 个"同数据同 API + 双侧（vuln/patched）"比 100 个"只有 vuln 侧、口径混乱"更可信。**50 双侧 = 100 次扫描的完整证据**，性价比最优。

**推荐：n=50（双侧）**，理由：①余额 ¥11 恰好覆盖；②统计上足以支撑主结论；③比"100 但只单侧"更完整。

## 三、压缩方案（还想更省）

| 方案 | 成本 | 代价 | 建议 |
|---|---|---|---|
| **A. n=50 双侧** | ¥11.12 | 无（完整 vuln+patched） | ✅ **推荐** |
| B. n=100 单侧（只 vuln） | ¥11.12 | 缺误报口径 → Pair-Correct/FPR 没法算 | 不推荐（丢了核心卖点） |
| C. n=21 截断（现状） | ¥4.67 | 样本太少，审稿人质疑选择性 | 只作过渡 |
| D. 用 baseline 配置省 token | 略省（711K vs 738K/10） | 无 | 自然生效，无需特调 |
| E. 降级模型（如更小 flash 变体） | 未知 | 与论文声明模型不一致 | 不推荐（破坏同 API 口径） |

**再压缩的杠杆**：`cpg_context_enabled` 等实验开关默认关（省 token）；实测每文件 72.9K 已是 baseline 自然值，**没有无损压缩空间**——所以 50 双侧就是预算内的最优解。
