# HOS 论文评分模型（Score Model）

> 灵感来源：ghfind.com（毒舌 GitHub 评分）——用**一个决定性分数 + 维度倾向 + 评级标签 + 一句话点评**把结论压进 3 秒可读的卡片里。本模型把同一套思路搬到论文上：**先给结论，再给证据，长文靠后。**

## 一、为什么需要评分卡

长文鞭尸局的问题：**读者看不到 3 秒内的结论**。评分卡把"这篇论文值不值得信"压成一个数字 + 一句话 + 几条维度条，任何人都能瞬间扫完，想看细节再展开。

## 二、评分维度

### 2.1 通用六维（默认，通用于所有论文类型）

卡片模板（`src/render.ts`）默认使用**通用六维**，满分合计 100，不绑定任何领域：

| 维度 | key | 满分 | 评价对象 | 低分特征 |
|------|-----|------|----------|----------|
| 新颖性 | `novelty` | 20 | 方法/问题是否新 | 拼接物、无新技术迭代 |
| 严谨性 | `rigor` | 25 | 论证/实验/统计 | 画靶射箭、无基线、选择性报告 |
| 贡献度 | `contribution` | 20 | 实际贡献价值 | 结论超出证据、水分大 |
| 可复现性 | `repro` | 15 | 代码/数据/参数 | 闭源、缺参数、绑死付费 API |
| 清晰度 | `clarity` | 10 | 表达/结构/图表 | 表达混乱、结构缺失 |
| 影响力 | `impact` | 10 | 领域相关度与影响 | 与领域脱节、无人引用 |

定义见 `src/types.ts` 的 `UNIVERSAL_DIMS`。

### 2.2 AI/安全论文专用维度（可选定制）

审 AI/安全领域论文时，可把通用六维映射为领域专用五维（本 skill 原始设计），满分仍合计 100：

| 维度 | 代码 | 权重 | 评价对象 | 低分特征 |
|------|------|------|----------|----------|
| 实验 | `EVAL` | 30% | 基线、指标、消融、统计、选择性报告 | 画靶射箭、无基线、单项遮丑 |
| 数据 | `DATA` | 20% | 样本量、来源、标签、污染 | 样本贫血、单来源、硬编码 |
| 复现 | `REPRO` | 20% | 开源、参数、门槛、可验证性 | 闭源、缺参数、绑死付费 API |
| 新颖 | `NOV` | 15% | 方法/问题的新意 | 拼接物、无新技术迭代 |
| 安全 | `SEC` | 15% | LLM/Agent/数据集安全 | 污染未验、逃逸、注入 |

> 两套维度都是数据驱动的：评分卡渲染器（`src/render.ts`）只认 `dimensions` 数组，传哪套渲染哪套。**评分卡结构本身通用于所有论文类型。**

## 三、综合评分

维度满分合计为 100 时（通用六维与领域五维都满足）：

```
综合分(0-100) = Σ(维度得分)
```

例（通用六维）：新颖 14 + 严谨 11 + 贡献 14 + 复现 10.5 + 清晰 8 + 影响 8 = **65.5 / 100**

若自定义维度满分合计 ≠ 100，则归一化：`综合分 = Σ(得分/max) × 100`。

## 四、评级标签（ghfind "真大佬/水货" 的论文版）

按综合分 + **最低维度（主导倾向）** 打标签：

| 综合分 | 评级 |
|--------|------|
| ≥ 85 | 🟢 硬核货 |
| 70-84 | 🟢 方法论扎实 |
| 55-69 | 🟡 有亮点有硬伤 |
| 40-54 | 🟠 画靶射箭型 |
| 25-39 | 🔴 噱头大于实质 |
| < 25 | 🔴 学术水货 |

**主导倾向标签**（取最低维度）：
- EVAL 最低 → `实验拖累`
- DATA 最低 → `数据贫血`
- REPRO 最低 → `复现劝退`
- NOV 最低 → `新颖性枯竭`
- SEC 最低 → `安全裸奔`

展示格式：`⚠️ 画靶射箭型 · 实验拖累`

## 五、一句话点评（One-line Roast）

ghfind 式毒舌锐评的论文版。规则：

1. **一句话，一个事实**——只保留杀伤力最大且可核验的那条，不堆砌。
2. **≤ 40 字**——目标是能放进卡片、能被转发。
3. **先结论后证据**——"结论（毒舌）+ 证据（数字）"结构。
4. **禁止作者人身攻击**。

示例：
- "精确率 48.8%，一半告警是误报，拿召回率遮丑。"（MultiVer）
- "433 个告警自称全面工业实证，样本连泛化都不配提。"（LLMPFA）
- "2025 下半年还在测 GPT-4，语料和模型都过季了。"（SAST-Genius）

## 六、击败百分比（Percentile）

对照 `database/paper.json` 历史已审论文，计算 `综合分 ≥ 本论文` 的比例：

```
击败了 X% 的已审论文
```

样本 < 5 篇时显示 `暂无足够样本`，避免误导。这是 ghfind "击败了 X% 的开发者" 的论文版，用于制造可传播的社交货币。

## 七、输出模式

`config.yaml#output_mode`：

| 模式 | 行为 | 适用 |
|------|------|------|
| `scorecard` | 只输出评分卡 + RVE 摘要，长文按需展开 | 默认，快速可视化 |
| `full` | 评分卡 + 完整鞭尸局长文 | 深度场景 |
| `brief` | 只给评分 + 一句话点评 + 评级 | 最紧凑，社交媒体 |

**铁律：无论哪种模式，评分卡都必须出现在输出的最顶部。**

## 八、评分流程

1. 全部审计完成（Experiment/Security/Repro 输出 RVE 后）→ Scorer 汇总。
2. 维度分：以各层 RVE 严重度为基础扣分（CRITICAL -3.0 / HIGH -2.0 / MEDIUM -1.0 / LOW -0.5，按该维度满分比例折算），下限 0；再结合 Hype Detector 与 Claim Analyzer 的定性判断微调。
3. 维度分须引用 RVE 证据，禁止凭感觉打分。
4. 打分结果组装成 `PaperReviewData`（`src/types.ts`），调用 `src/render.ts` 渲染评分卡。
5. 渲染出的卡置于所有输出最顶部。
