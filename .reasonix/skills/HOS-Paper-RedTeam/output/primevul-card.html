🏆 亮点

  • 首个严格去重+时间切分的代码大模型漏洞检测基准，正面拆穿现有基准系统性高估
  • VD-S 指标 + pair-wise 评估协议，回击 Accuracy/F1 与真实漏洞检测的失配
  • 成为后续 AEGIS / VulnAgent-R2 / Phoenix 等研究的默认评测集

🛠 关键方法

  • 自动标注双技术：PrimeVul-NvdCheck（CVE 专家分析）+ PrimeVul-OneFunc（commit 唯一变更）
  • 多数据集合并 + 严格去重（现有基准最高 18.9% 测试样本泄漏自训练集）+ 时间切分
  • 函数级 fine-tuning 评测（StarCoder2 等）+ class weights / contrastive learning 增强
  • Vulnerability Detection Score (VD-S) + pair-wise 评估协议

🔥 毒舌点评

PrimeVul 是领域的打脸专业户：把 BigVul 上 68.26% F1 的 7B 模型直接干到 3.09%，顺手证明 GPT-3.5/GPT-4 在最强设置下接近抛硬币——这功劳必须记。但别高兴太早：标签核验每基准只随机抽 50 个函数、三位作者自评正确率 92%，没有独立第三方复核；评估锁死在函数级，跨函数跨文件上下文依赖的漏洞它压根看不见（论文自己承认 Need for More Context），3.09% 这个戏剧性数字有一部分是 1:32.8 极端不平衡 + 严格 pair-wise 协议挤出来的。它证明了「函数级代码大模型不行」，却没回答「AI 驱动工具相对 Semgrep/CodeQL 到底行不行」——而这恰恰是 HOS-LS 这类系统真正该被拷问的问题。

一句话结论：把 BigVul 68% F1 打到 3%，但函数级评估看不见跨函数漏洞。

维度说明

  • 新颖性 14/20 — 创新在评测协议（去重+时间切分+VD-S）而非检测方法本身；但开创了严格评测范式
  • 严谨性 17/25 — 去重/时间切分/标签核验方法严谨；但核验仅抽样 50 函数/基准、函数级评估有上限、VD-S 无第三方验证
  • 贡献度 17/20 — PrimeVul 成为后续多 Agent 漏洞检测研究（AEGIS/VulnAgent-R2/Phoenix）的事实标准评测集
  • 可复现性 12/15 — 代码+数据全公开（MIT）；fine-tuning 需 GPU、GPT API 有成本门槛
  • 清晰度 8/10 — 问题-方法-证据链条清晰，打脸结论表述直接
  • 影响力 9/10 — 68.26%→3.09% F1 的发现重塑 LLM 漏洞检测评估标准，领域内高被引

建议

  1. 补齐仓库级/跨函数上下文评估协议，回答 3.09% 中有多少是协议选择而非模型无能
  2. 标签核验扩大到更大随机样本，并引入独立第三方复核正确率
  3. 与传统 SAST（Semgrep/CodeQL/Snyk）同台对比，回答实用部署问题
  4. 公开时间切分点、样本分布与 CWE 平衡细节
