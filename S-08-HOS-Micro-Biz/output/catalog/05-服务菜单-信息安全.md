## 一、模块定位与使用说明

本菜单覆盖 HOS 微商技术服务运营中"信息安全"品类下的全部对外服务项,包括 CTF 辅导、渗透测试、安全加固、等保咨询四类。本菜单用于:

1. 一线接单时快速查阅服务范围、报价区间、交付物;
2. 与客户进行需求确认与合同签订的依据;
3. 内部排期与派单的工时参考基准。

信息安全服务具有强合规属性,所有服务必须在"书面授权 + 范围确认 + 保密协议"三件齐备后方可启动技术工作。任何口头承诺、模糊授权、第三方转委托均不得作为开工依据。

### 1.1 服务总览

| 服务项 | 核心内容 | 起步价 | 标准工期 |
|---|---|---|---|
| CTF 辅导 | 赛题讲解 + 思路训练 | ¥50/题 | 即时 |
| 渗透测试 | Web 应用安全测试 + 报告 | ¥500 起 | 3-7 天 |
| 安全加固 | 服务器/应用安全配置 | ¥300 起 | 1-3 天 |
| 等保咨询 | 等保 2.0 合规咨询 | ¥1000 起 | 按项目 |

### 1.2 难度系数说明

难度系数用于工时与报价推演,取值 1.0-3.0:

- 1.0:标准化、模板化任务,可复用既有方案;

- 2.0:复杂场景,需多轮验证;
- 3.0:高复杂度、高责任、需资深人员交付。

## 六、信息安全服务合规前置清单

信息安全服务必须在以下三件齐备后方可启动技术工作。任何缺失项均视为未授权,不得开工。

### 6.1 授权书模板要点

```
《授权测试/服务协议》要点:
1. 委托方主体信息(企业全称、统一社会信用代码、联系人)
2. 受托方主体信息
3. 授权服务类型(渗透测试/加固/等保)
4. 授权范围(IP 列表、域名、系统清单、接口)
5. 授权时间窗口(起止时间)
6. 禁止动作清单(DoS、数据删除、社工真人等)
7. 数据处理条款(采集、存储、销毁)
8. 责任界定(造成业务影响的处理方式)
9. 双方签字盖章(企业公章)
```

### 6.2 测试范围确认

| 确认项 | 内容 |
|---|---|
| IP/域名清单 | 明确每一项,不含通配符 |
| 系统清单 | 含系统名称、版本、用途 |
| 接口清单 | API 路径、方法、参数 |
| 账号权限 | 测试账号等级与范围 |
| 排除项 | 明确不可测试的系统/功能 |

### 6.3 保密协议要点

```
《保密协议(NDA)》要点:
1. 保密信息定义(测试结果、漏洞详情、系统架构)
2. 保密期限(服务结束后 3-5 年)
3. 保密义务(不得向第三方披露、不得用于非服务目的)
4. 例外情形(法律强制要求、已公开信息)
5. 违约责任(违约金、赔偿范围)
6. 数据归还/销毁(服务结束后 X 日内销毁)
```

## 七、信息安全服务法律责任边界

### 7.1 合规边界

1. 所有测试必须在授权书明确的范围内进行,越界测试一律禁止;
2. 不得对未授权系统进行任何形式的探测;
3. 不得保留客户业务数据,测试结束后按约定销毁;
4. 发现重大漏洞应同步客户,不得私下披露或公开。

### 7.2 法律红线

依据《中华人民共和国刑法》《网络安全法》《数据安全法》:

- 未授权访问他人计算机系统:刑事风险;
- 提供入侵工具:刑事风险;
- 非法获取公民个人信息:刑事风险;
- 拒不履行信息网络安全管理义务:刑事风险。

### 7.3 责任界定原则

| 情形 | 责任归属 |
|---|---|
| 按授权范围测试,造成非故意影响 | 双方按授权书约定共担 |
| 越界测试 | 受托方全责 |
| 客户隐瞒系统信息导致误判 | 客户全责 |
| 客户未按修复建议整改导致后续事件 | 客户全责 |

## 八、报告交付标准

### 8.1 报告结构规范

```
1. 封面(项目名称、报告版本、日期、密级)
2. 摘要(测试范围、主要发现、风险概述)

4. 漏洞详情(逐项)
   - 漏洞名称

   - 复现步骤(含截图)
   - 影响评估

5. 风险矩阵与统计
6. 附录(工具清单、测试账号、变更记录)
```

### 8.2 风险等级评定

| 等级 | CVSS 区间 | 处置时限建议 |
|---|---|---|
| 严重 | 9.0-10.0 | 24 小时内 |
| 高危 | 7.0-8.9 | 7 天内 |
| 中危 | 4.0-6.9 | 30 天内 |
| 低危 | 0.1-3.9 | 90 天内 |
| 信息 | 0.0 | 建议关注 |

### 8.3 交付格式要求

- 主报告:PDF(含签章页)+ Markdown 源文件;
- 证据:独立打包,按漏洞编号命名;
- 报告密级:默认"商业秘密-内部",未经客户同意不得外发。

## 九、拒接场景

以下场景一律拒接,不得以任何理由变通。一线接单人员遇此类需求应直接引用《红线清单与拒绝话术》标准话术回绝。

### 9.1 绝对拒接(法律红线)

| 场景 | 拒绝理由 |
|---|---|
| 未授权攻击指定目标 | 无书面授权,涉嫌违法 |
| 攻击政府/关键基础设施 | 刑事风险,绝对禁止 |
| 黑产工具开发(木马、远控) | 涉嫌提供入侵工具罪 |
| 撞库、脱库、数据窃取 | 涉嫌非法获取数据 |
| 网络赌场/黑产平台安全服务 | 涉嫌帮助犯罪 |
| 考试作弊工具/系统 | 违反考试管理法规 |
| 钓鱼页面制作 | 涉嫌诈骗帮助犯 |

### 9.2 有条件拒接(需升级审核)

| 场景 | 处理方式 |
|---|---|
| 个人声称测试自己系统但无法证明所有权 | 要求提供权属证明 |
| 第三方转委托无法确认最终委托方 | 要求直接与最终委托方签约 |
| 模糊授权("随便测") | 要求明确范围,否则拒接 |
| 紧急需求但拒绝签授权书 | 拒接,优先级低于合规 |
| 要求不留下任何记录 | 拒绝,服务必须可追溯 |

### 9.3 标准拒绝话术

```
话术A(未授权攻击):
"您好,渗透测试服务必须基于书面授权开展,这是法律底线。
请您提供目标系统的权属证明并签署授权协议后,我们再进一步沟通。
感谢理解。"

话术B(黑产/作弊):
"您好,您描述的需求超出我们的服务范围。
我们仅提供合法合规的信息安全服务,不涉及相关业务。
祝您找到合适的解决方案。"

话术C(模糊授权):
"您好,为了保证测试合法合规且结果有效,
我们需要明确测试范围(IP/域名/系统清单)并签署授权书。
如无法提供,我们暂时无法启动服务,感谢理解。"
```

## 十、价格声明

本菜单所列价格均为起步价或参考价,实际报价依据以下因素动态核算:

1. 服务项难度系数;
2. 测试/服务范围广度;
3. 工期要求(是否加急);
4. 客户行业合规要求;
5. 是否含售后与复核。

最终报价以双方签署的服务合同为准。本菜单价格不构成要约,有效期至下次版本更新。所有信息安全服务必须先签合同后开工,不接受"先做后付"。
