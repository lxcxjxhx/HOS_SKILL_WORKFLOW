# 定价策略引擎

> **模块**: catalog
> **文档编号**: CAT-0002
> **版本**: 1.0.0 | **最后更新**: 2026-07-26
> **适用阶段**: 冷启动 / 稳定期 / 扩张期

---

## 一、模块概述

定价策略引擎是技术服务微商/私域运营体系中价值变现的核心枢纽。它将"工时 × 能力 × 难度 × 紧急度"四维变量统一映射为可解释、可复用、可谈判的报价模型,确保报价决策在冷启动期、稳定期与扩张期均保持一致性、专业性与盈利性。

本引擎适用于以下场景:

- 客户首次咨询时的快速报价
- 复杂需求的分阶段预算拆解
- 议价过程中的让步边界判断
- 内部成本核算与利润复盘

核心目标:**让每一次报价都有据可依,让每一次让步都有边界可守**。

---

## 二、定价公式

```
基础报价 = 预估工时(h) × 时薪基准 × 难度系数 × 紧急系数
```

### 公式变量说明

- **预估工时(h)**:基于需求拆解后的实际投入预估,含沟通、调研、编码、测试、文档全链路工时,不含纯等待时间。
- **时薪基准**:根据项目类型与个人能力档位确定的单位时间价值,详见时薪基准表。
- **难度系数**:根据技术复杂度与领域知识要求确定的乘数,详见难度系数表。
- **紧急系数**:根据交付周期对排期冲击程度确定的乘数,详见紧急系数表。

### 报价生成链路

```
最终报价 = 基础报价 × (1 + 议价缓冲率)
         = 预估工时 × 时薪基准 × 难度系数 × 紧急系数 × (1.10 ~ 1.20)
```

议价缓冲率默认取 **10%**,冷启动期可下调至 5%,扩张期建议固定 15%~20%。

---

## 三、时薪基准表

根据项目类型与个人能力档位,确定单位时间价值锚点。时薪基准是整个定价体系的"地基",严禁低于下限。

```
| 项目类型 | 时薪区间(CNY/h) | 说明 | 典型项目 |
|--------|--------------|------|--------|
| 课设/简单脚本 | 50-80 | 标准化程度高 | 课设辅导/代码调试 |
| 毕设/中型项目 | 80-150 | 需要理解业务逻辑 | 毕业设计/课程大作业 |
| AI应用/安全审计 | 150-300 | 需要领域专业知识 | RAG系统/渗透测试 |
| 架构咨询/高端服务 | 300-500 | 需要全局视野 | 企业顾问/系统架构设计 |
```

### 时薪档位选择规则

- **冷启动期**:取区间下限,快速积累案例与口碑。
- **稳定期**:取区间中值,匹配市场均价。
- **扩张期**:取区间上限,通过案例密度支撑溢价。
- **个人能力跃迁**:每完成 10 个同类型项目且好评率 >=90%,时薪可上移一档。

---

## 四、难度系数表

难度系数反映技术复杂度、领域知识门槛与创新投入。判断时以"是否需要额外研究时间"为核心信号。

```
| 等级 | 判断标准 | 系数 | 典型场景 |
|------|---------|------|--------|
| 简单 | 套模板/改配置 | 1.0 | 环境搭建/简单脚本 |
| 中等 | 需理解业务逻辑 | 1.3 | 课设/中型网站 |
| 困难 | 需研究/创新 | 1.8 | AI应用/安全审计 |
| 极难 | 前沿技术/复杂系统 | 2.5 | 大模型微调/企业级系统 |
```

### 难度判定决策树

```
需求是否已有成熟方案可直接套用?
├─ 是 → 简单 (1.0)
└─ 否 → 是否需要理解客户业务逻辑?
    ├─ 是 → 是否需要领域专业知识或创新方案?
    │   ├─ 否 → 中等 (1.3)
    │   └─ 是 → 是否涉及前沿技术或复杂系统架构?
    │       ├─ 否 → 困难 (1.8)
    │       └─ 是 → 极难 (2.5)
    └─ 否 → 重新评估需求,可能拆分为多个简单任务
```

### 难度叠加规则

- 跨领域融合(如 AI + 安全):取较高难度系数 +0.2
- 需要对接多个第三方系统:系数 +0.1
- 需要适配多端(Web/移动/桌面):系数 +0.1
- 叠加后总系数不超过 3.0

---

## 五、紧急系数表

紧急系数反映交付周期对正常排期的冲击。短期高压交付需以溢价补偿机会成本与加班成本。

```
| 等级 | 交付周期 | 系数 | 备注 |
|------|---------|------|------|
| 正常 | >=3天 | 1.0 | 正常排期 |
| 加急 | 1-3天 | 1.5 | 影响其他订单 |
| 特急 | <24h | 2.0 | 需加班/暂停其他 |
```

### 紧急系数适用原则

- 紧急系数仅在客户明确指定交付周期时启用,不因"我比较急"等模糊表述触发。
- 特急档需提前告知客户:"此价格包含排期调整成本,如延期至 3 天外可按正常价执行"。
- 同一订单内不同任务模块可分别适用不同紧急系数,但需在报价单中明示拆分。

## 六、定价计算推演示例

以下三个示例覆盖简单、中等、困难三档难度,展示从需求拆解到最终报价的完整推演过程。

### 示例 1:Python 数据可视化课设

**需求背景**:客户为大三学生,需完成 Python 数据可视化课程设计,提供数据集,要求生成 5 张图表 + 分析报告,交付周期 2 天。

**推演过程**:

```
需求拆解:
- 数据清洗与探索: 1.5h
- 图表设计与编码: 2.5h
- 分析报告撰写: 1.0h
- 沟通与修改预留: 1.0h
─────────────────────
预估工时合计: 6.0h

参数匹配:
- 项目类型: 课设/简单脚本 → 时薪基准 60 CNY/h
- 难度判定: 套用成熟可视化方案,需理解数据但无创新 → 简单 1.0
- 紧急判定: 交付周期 2 天,属加急档 → 1.5

基础报价计算:
6.0 × 60 × 1.0 × 1.5 = 540 CNY

议价缓冲(上浮 10%):
540 × 1.10 = 594 CNY

取整报价: 600 CNY
```

**报价话术参考**:

```
这个课设我评估下来工作量约 6 小时,包含数据清洗、
5 张图表编码和分析报告。考虑到您要求 2 天内交付,
我需要调整手头其他安排优先做,报价 600 元。
如果时间能放宽到 3-4 天,可以按 540 元走正常排期。
```

**需求背景**:客户为本科毕业生,需完成基于 SpringBoot + Vue 的图书管理系统毕设,含前后端、数据库设计、文档,交付周期 20 天。

**推演过程**:

```
需求拆解:
- 需求分析与数据库设计: 4h
- 后端接口开发(SpringBoot): 12h
- 前端页面开发(Vue): 10h
- 联调与测试: 6h
- 文档与部署说明: 4h
- 沟通与修改预留: 4h
─────────────────────
预估工时合计: 40.0h

参数匹配:
- 项目类型: 毕设/中型项目 → 时薪基准 100 CNY/h
- 难度判定: 需理解业务逻辑,但技术栈成熟 → 中等 1.3
- 紧急判定: 交付周期 20 天,属正常档 → 1.0

基础报价计算:
40 × 100 × 1.3 × 1.0 = 5200 CNY

议价缓冲(上浮 10%):
5200 × 1.10 = 5720 CNY

取整报价: 5800 CNY
```

**报价话术参考**:

```
毕设这类项目我做过比较多,图书管理系统属于中型项目,
工作量约 40 小时,含前后端、数据库、文档全套。
按市场价核算报价 5800 元,包含:
- SpringBoot 后端 + Vue 前端完整代码
- MySQL 数据库设计
- 毕设文档与部署说明
- 2 轮免费修改

交付周期 20 天,中间会同步进度。如果需要加急,
可以谈周期但价格需要相应调整。
```

```
我们可以另签运维合同。
```

## 七、议价空间预留策略

报价生成时已在基础报价外上浮 10%~20% 作为议价缓冲,确保在谈判中有让步余地而不侵蚀利润底线。

### 缓冲率配置

```
| 阶段 | 缓冲率 | 说明 |
|------|-------|------|
| 冷启动期 | 5%-10% | 快速成交优先,薄利换案例 |
| 稳定期 | 10%-15% | 标准议价空间 |
| 扩张期 | 15%-20% | 筛选客户,溢价服务 |
```

### 三种让步策略

当客户压价时,优先使用"减价值"而非"减价格",守住单价底线。

#### 策略一:减功能降价

```
适用场景: 客户预算明确低于报价
操作方式: 拆解需求,砍掉非核心模块,重新核算工时

话术模板:
"我理解预算有限,我们可以把 XX 模块先不做,
先保证核心功能上线,这样报价可以降到 XX 元。
后续需要再加,我们单独报价。"
```

#### 策略二:延期折扣

```
适用场景: 客户对价格敏感但对时间不敏感
操作方式: 延长交付周期,降低紧急系数

话术模板:
"如果您能把交付时间放宽到 X 天,我可以按正常排期走,
报价可以降到 XX 元。这样我也能把其他订单排开,
质量更有保障。"
```

#### 策略三:价值锚定不降

```
适用场景: 客户压价但需求不可裁剪
操作方式: 强化价值锚点,提供分期或赠品,不降总价

话术模板:
"这个价格已经匹配市场均价,而且包含 X 轮修改和
Y 天售后。如果一次性付清,我可以赠送一次部署指导,
但总价不能再低了,否则没法保证交付质量。"
```

### 让步红线

- 单次让步幅度不超过报价的 10%
- 累计让步幅度不超过报价的 20%(即吃掉全部缓冲)
- 让步必须换取对等条件(减功能/延期/全额预付/案例授权等)
- 永远不通过降低时薪基准来让步

## 八、定价禁忌

以下行为会系统性破坏报价体系的可信度与盈利能力,严格禁止。

```
| 禁忌 | 风险 | 替代方案 |
|------|------|---------|
| 恶意低价竞争 | 破坏市场生态,陷入价格战 | 以价值与服务差异竞争 |
| 低于时薪基准下限 | 贬损个人能力估值 | 拒单或改为标准化产品售卖 |
| 免费做复杂需求 | 时间黑洞,无利润可言 | 复杂需求一律报价,可送简单咨询 |
| 承诺固定价格后无限制修改 | 范围蔓延,工时失控 | 合同明确修改轮次与范围 |
| 拍脑袋报价无依据 | 报价飘忽,失去客户信任 | 强制走定价公式推演 |
| 只报总价不拆工时 | 客户无法感知价值 | 报价单含工时拆解明细 |
```

### 禁忌执行细则

- **不恶意低价竞争**:即使冷启动期急需案例,也不得低于同类型市场均价的 70%。低价换来的客户多为价格敏感型,复购率与口碑转化率均低。
- **不低于时薪基准下限**:时薪基准下限是个人能力的"地板价",跌破即等于自我贬值。宁可拒单,不破底线。
- **不免费做复杂需求**:复杂需求(难度系数 >=1.8)一律报价,可赠送 30 分钟内的简单咨询作为引流,但落地执行必须收费。
- **不承诺固定价格后无限制修改**:合同/订单确认时必须明确"含 N 轮修改,N>=2 后按 X 元/小时计费",防止范围蔓延。

每份正式报价应包含以下结构,确保可解释、可追溯。

```
==================================================
报价单编号: QUO-YYYYMMDD-XXX
客户: _____________
项目名称: _____________
报价日期: _____________
有效期: 7 天
--------------------------------------------------
一、需求概述
(简要描述客户需求与交付物清单)

二、工时拆解
| 模块 | 工时(h) | 说明 |
|------|---------|------|
| ... | ... | ... |
合计: XX h

三、定价参数
- 时薪基准: XX CNY/h
- 难度系数: X.X
- 紧急系数: X.X
- 议价缓冲: 10%

四、报价明细
基础报价: XX × XX × X.X × X.X = XXXX CNY
最终报价: XXXX CNY(取整)

五、交付与售后
- 交付周期: X 天
- 修改轮次: 2 轮
- 售后支持: 7 天

六、付款方式
(预付比例/尾款节点)
==================================================
```

## 十、定价复盘机制

定价不是一次性动作,需通过复盘持续校准参数。

### 复盘指标

```
| 指标 | 计算方式 | 健康区间 |
|------|---------|---------|
| 实际工时偏差率 | (实际工时-预估工时)/预估工时 | ±15% |
| 报价成交率 | 成交单数/报价单数 | 60%-80% |
| 单小时实际收入 | 实际收款/实际工时 | >=时薪基准下限 |
| 让步幅度均值 | 让步金额/报价金额 | <=10% |
```

### 复盘节奏

- **冷启动期**:每单复盘,校准预估工时与难度判断。
- **稳定期**:每周复盘,关注成交率与让步幅度。
- **扩张期**:每月复盘,调整时薪档位与缓冲率。

## 十一、阶段化定价策略

不同发展阶段定价策略侧重不同,需动态调整。

```
| 阶段 | 时薪档位 | 缓冲率 | 报价策略 | 核心目标 |
|------|---------|-------|---------|---------|
| 冷启动期 | 区间下限 | 5%-10% | 低价换案例,快速成交 | 积累口碑与案例库 |
| 稳定期 | 区间中值 | 10%-15% | 标准化报价,筛选客户 | 建立品牌与流程 |
| 扩张期 | 区间上限 | 15%-20% | 溢价报价,聚焦高端 | 利润最大化与壁垒构建 |
```
