# 退款策略与纠纷处理

> **模块**: compliance
> **文档编号**: CMP-0004
> **版本**: 1.0.0 | **最后更新**: 2026-07-26
> **适用阶段**: 冷启动 / 稳定期 / 扩张期

---

## 文档说明

本文档基于 HOS 微商技术服务业务场景,系统化构建退款策略与纠纷处理机制。微商技术服务具有"先定金后交付""定制化程度高""质量主观性强"等特点,退款与纠纷不可避免。本策略旨在:保护合理利润的同时维护客户关系,提供可执行的决策矩阵与话术,降低纠纷升级概率,防范法律与平台风险。

**原始策略基准**(来自 SKILL.md):
```
未开始:全额退定金
已开始未交付:协商退 50% 定金
已交付:不接受退款(但可协商修改)
客户原因取消:定金不退
```

本文档在此基础上,按订单阶段、责任归属、金额区间进行精细化扩展。

## 一、退款策略总则

### 1.1 退款基本原则

```
退款五项原则:

1. 契约优先原则
   - 以定金支付时的约定为准
   - 口头承诺与文字承诺具有同等效力
   - 定金性质明确(预付款 vs 履约保证金)

2. 责任归属原则
   - 我方原因:优先退款 + 补偿
   - 客户原因:优先协商,定金不退为底线
   - 不可抗力:协商解决,各退一步

3. 阶段对应原则
   - 未开始:退款空间大
   - 已开始未交付:按工时扣除
   - 已交付:以修改替代退款

4. 关系维护原则
   - 退款不撕破关系
   - 保留复购与转介绍可能
   - 即使退款,也要专业收尾

5. 证据闭环原则
   - 退款决策基于证据
   - 退款过程留存记录
   - 退款后归档复盘
```

### 1.2 退款触发条件分类

| 退款触发类型 | 具体情形 | 处理优先级 |
|------------|---------|-----------|
| 客户主动取消 - 未开始 | 客户改变主意/找到替代 | 中(按约定退) |
| 客户主动取消 - 已开始 | 客户中途退出/不需了 | 中(扣工时) |
| 客户质量异议 - 已交付 | 客户认为质量不达标 | 高(优先修改) |
| 我方原因 - 未开始 | 我方无法接单/排期冲突 | 高(全额退+致歉) |
| 我方原因 - 已开始 | 我方无法完成/交付延期 | 极高(全额退+补偿) |
| 我方质量缺陷 - 已交付 | 确认存在质量缺陷 | 极高(修复+补偿/退款) |
| 沟通误解 | 需求理解偏差导致争议 | 高(协商) |
| 不可抗力 | 客户方/我方突发状况 | 中(协商) |

### 1.3 退款协商优先级

```
退款处理优先级(从高到低):

P0 - 立即处理
├── 我方原因导致无法交付
├── 确认我方质量缺陷
└── 客户情绪激烈,有升级风险

P1 - 24小时内处理
├── 客户主动取消(未开始)
├── 沟通误解导致争议
└── 平台介入投诉

P2 - 48小时内处理
├── 客户主动取消(已开始)
├── 客户质量异议(已交付)
└── 不可抗力协商

P3 - 常规处理
├── 客户试探性询问退款
└── 售后期内小问题
```

## 二、退款场景决策矩阵

### 2.1 决策矩阵总表

| 订单阶段 | 责任归属 | 金额区间 | 退款策略 | 附加处理 |
|---------|---------|---------|---------|---------|
| 未开始 | 客户原因 | 任意 | 定金不退(可改期一次) | 改期不收违约金 |
| 未开始 | 我方原因 | 任意 | 全额退定金 + 致歉 | 赠送优惠券 |
| 已开始未交付 | 客户原因 | < 500 元 | 协商退 30%-50% 定金 | 扣除已投入工时 |
| 已开始未交付 | 客户原因 | 500-2000 元 | 协商退 30%-50% 定金 | 扣除工时,可改期 |
| 已开始未交付 | 客户原因 | > 2000 元 | 协商退 20%-40% 定金 | 扣除工时,签订解约确认 |
| 已开始未交付 | 我方原因 | 任意 | 全额退定金 + 补偿 | 补偿 = 定金 10%-30% |
| 已交付 | 客户原因 - 质量异议 | 任意 | 优先修改,拒不退款 | 修改不超过 2 次 |
| 已交付 | 我方质量缺陷 - 轻微 | 任意 | 免费修复 + 适当补偿 | 补偿 = 定金 5%-15% |
| 已交付 | 我方质量缺陷 - 严重 | 任意 | 免费修复 + 协商退款 | 退款 30%-70% |
| 已交付 | 我方质量缺陷 - 致命 | 任意 | 全额退款 + 致歉 | 退款 100% + 补偿 |

### 2.2 场景细化处理细则

#### 场景 A:未开始 - 客户原因

```
处理细则:
1. 定金不退为底线(定金具有履约担保性质)
2. 但提供"改期一次"权益,不收违约金
3. 改期需在 30 天内重新启动
4. 超过 30 天未启动,定金视为放弃
5. 沟通话术保持温和,避免激化

例外:
- 客户确有不可抗力(疾病、家庭变故) → 可酌情退 30%-50%
- 定金支付 24 小时内反悔 → 可全额退(冷静期)
```

#### 场景 B:未开始 - 我方原因

```
处理细则:
1. 全额退定金,不扣任何费用
2. 主动致歉,说明原因(排期冲突/能力匹配/突发状况)
3. 赠送优惠券(下次服务 9 折)
4. 推荐替代服务商(如有)
5. 保留关系,未来可能合作

话术要点:
- 诚恳致歉,不推诿
- 快速退款,不拖延
- 给出补偿,留有余地
```

#### 场景 C:已开始未交付 - 客户原因

```
处理细则:
1. 扣除已投入工时成本(按 50-100 元/小时计算)
2. 协商退还剩余部分(通常 30%-50%)
3. 高客单价(>2000 元)退款比例更低(20%-40%)
4. 需签订《解约确认单》,明确双方不再追诉
5. 已交付的中间产物归客户

工时计算标准:
| 服务类型 | 工时单价 | 备注 |
|---------|---------|------|
| 代码开发 | 80-100 元/小时 | 按实际投入 |
| 文档撰写 | 60-80 元/小时 | 按实际投入 |
| 答疑咨询 | 50-80 元/小时 | 按实际投入 |
| 需求分析 | 60-80 元/小时 | 按实际投入 |
```

#### 场景 D:已开始未交付 - 我方原因

```
处理细则:
1. 全额退定金
2. 补偿金额 = 定金 × 10%-30%(视延误程度)
3. 已完成部分免费交付客户
4. 诚恳致歉,承担违约责任
5. 记录内部复盘,避免复发
```

#### 场景 E:已交付 - 客户原因质量异议

```
处理细则:
1. 优先提供修改服务(不退款)
2. 修改次数上限 2 次
3. 修改范围限于原始需求确认单
4. 新增需求按新订单处理
5. 客户拒不接受修改 → 拒绝退款(已交付)

判断标准:
- 是否在原始需求范围内 → 是:免费修改
- 是否超出交付后 7 天 → 是:可拒绝(售后期外)
- 客户是否提出具体问题 → 是:针对性修改
- 客户是否恶意找茬 → 是:按红线处理
```

#### 场景 F:已交付 - 我方质量缺陷

```
处理细则(按缺陷等级):

轻微缺陷(不影响功能,小瑕疵):
1. 免费修复
2. 补偿 = 定金 × 5%-15%(优惠券/现金)
3. 延长售后期至 14 天

严重缺陷(影响主要功能):
1. 免费修复(优先级最高)
2. 修复不成 → 协商退款 30%-70%
3. 补偿 = 定金 × 15%-30%

致命缺陷(完全无法使用/抄袭/重大错误):
1. 全额退款
2. 致歉
3. 内部严肃复盘
4. 考虑额外补偿(定金 × 30%-50%)
```

## 三、退款协商话术

### 3.1 未开始 - 客户原因取消

**话术 A - 坚守底线型**:
```
[客户昵称],理解你目前的情况有变化。
关于定金,咱们当时约定的是定金不退,主要是定金起到了锁档期的作用,
你下单后我已经推掉了其他客户的需求,排期也预留了。
不过,我可以给你保留档期,30 天内随时启动,不收任何违约金。
你看这样行吗?
```

**话术 B - 灵活处理型(不可抗力)**:
```
[客户昵称],听到 [具体原因],理解你的难处。
这种情况虽然按约定定金不退,但我也不想让你为难。
这样吧,我退你 30% 定金,剩余部分作为档期占用补偿,
另外给你保留一次改期权益,后续有需要随时用。
你看这个方案可以吗?
```

**话术 C - 冷静期全额退**:
```
[客户昵称],你下单还不到 24 小时,属于冷静期,
我直接全额退你定金,不用有心理负担。
后续如果还需要,随时找我。
```

### 3.2 未开始 - 我方原因

**话术 A - 诚恳致歉型**:
```
[客户昵称],非常抱歉,由于 [具体原因:排期冲突/能力评估/突发状况],
这次可能没办法按时为你提供服务了。
我立即全额退你定金,另外送你一张 9 折券,
后续有需要可以优先排期。
这次真的非常抱歉,希望后续还有合作机会。
```

**话术 B - 推荐替代型**:
```
[客户昵称],抱歉,这次 [原因] 导致我无法接你的单。
定金我全额退你,另外我认识一位同行 [推荐人],
水平也不错,我可以帮你引荐,你报我名字可能有优惠。
这次很抱歉,希望理解。
```

### 3.3 已开始未交付 - 客户原因

**话术 A - 扣工时型**:
```
[客户昵称],理解你想取消,咱们算一下:
目前我已经投入了 [X] 小时,按 [单价] 算,工时成本是 [Y] 元。
定金 [Z] 元扣除工时后,可以退你 [Z-Y] 元。
已经做出来的 [中间产物] 可以发你,你看这样处理可以吗?
```

**话术 B - 协商让步型**:
```
[客户昵称],知道你现在不需要了,没关系。
目前已经做了一部分,工时成本大概 [X] 元,
按理说定金 [Z] 元扣除 [X] 元,退你 [Z-X] 元。
但考虑到咱们关系,我多退你一点,退你 [Z-X+100] 元,
算是交个朋友,你看行吗?
```

**话术 C - 高客单价型**:
```
[客户昵称],这个项目金额比较大,已经投入了不少精力,
目前工时成本 [X] 元,加上需求分析、方案设计的投入,
按约定定金 [Z] 元可以退你 [20%-40%] × Z = [金额] 元。
另外,已完成的部分我会整理好发你,你也可以拿去用。
我们需要签一个《解约确认单》,确认双方不再追诉,你看方便吗?
```

### 3.4 已开始未交付 - 我方原因

**话术 A - 全额退+补偿型**:
```
[客户昵称],非常抱歉,由于 [具体原因],
这次项目我无法继续完成了。
定金 [Z] 元全额退你,另外补偿你 [Z × 10%-30%] = [金额] 元,
已完成的部分免费给你,你可以找其他人继续。
这次是我的责任,非常抱歉,希望你能谅解。
```

### 3.5 已交付 - 客户质量异议

**话术 A - 优先修改型**:
```
[客户昵称],收到你的反馈,具体是哪些地方不满意?
你可以列一下,我逐项修改。
按咱们的约定,交付后提供 [X] 次免费修改,
本次修改不额外收费,你看具体改哪些?
```

**话术 B - 范围界定型**:
```
[客户昵称],你提到的问题我看了一下,
其中 [问题 1、2] 属于原始需求范围内,我可以免费修改。
[问题 3、4] 超出了原始需求,属于新增需求,
这部分需要按新订单处理,你看是否需要?
我把原始需求确认单发你,咱们对一下。
```

**话术 C - 售后期外型**:
```
[客户昵称],你提到的问题我看了,确实存在。
不过距离交付已经超过 7 天售后期了,
按约定售后期外不提供免费修改。
但你是老客户,我给你破例一次,免费改 [X] 处,
其他的如果需要,可以按 [优惠价] 算,你看行吗?
```

**话术 D - 拒绝退款型**:
```
[客户昵称],理解你对 [具体问题] 不满意,
但按咱们的约定,已交付的服务以修改为主,不退款。
我已经提供了 [X] 次修改,每次都按你的要求调整了。
如果你还有具体问题,我可以再帮你调,但退款确实没办法。
希望理解。
```

### 3.6 已交付 - 我方质量缺陷

**话术 A - 轻微缺陷**:
```
[客户昵称],你反馈的 [问题] 确实是我的疏忽,非常抱歉。
我立即修复,今天内给你新版本。
另外,作为补偿,我送你 [优惠券/免费答疑/现金补偿],
后续有问题随时找我,这次确实抱歉。
```

**话术 B - 严重缺陷**:
```
[客户昵称],你指出的问题我确认了,确实是我的质量缺陷,非常抱歉。
我立即优先修复,预计 [X] 天内完成。
如果修复后仍不满意,我们协商退款方案,退你 [30%-70%] 定金。
另外补偿你 [金额],这次是我的责任,绝不推诿。
```

**话术 C - 致命缺陷**:
```
[客户昵称],非常抱歉,[问题] 是我的重大失误,我承担全部责任。
我立即全额退你定金 [Z] 元,另外补偿你 [Z × 30%-50%] = [金额] 元。
这次质量事故我会内部严肃复盘,确保不再发生。
非常对不起,希望你能给我改进的机会。
```

### 3.7 话术选择决策树

```
客户提出退款/纠纷
      ↓
订单处于什么阶段?
├── 未开始
│   ├── 客户原因 → 3.1 话术 A/B/C
│   └── 我方原因 → 3.2 话术 A/B
├── 已开始未交付
│   ├── 客户原因 → 3.3 话术 A/B/C
│   └── 我方原因 → 3.4 话术 A
└── 已交付
    ├── 客户质量异议
    │   ├── 售后期内 → 3.5 话术 A/B
    │   ├── 售期外 → 3.5 话术 C
    │   └── 多次修改后 → 3.5 话术 D
    └── 我方质量缺陷
        ├── 轻微 → 3.6 话术 A
        ├── 严重 → 3.6 话术 B
        └── 致命 → 3.6 话术 C
```

## 四、纠纷升级处理流程

### 4.1 三级处理流程

```
┌─────────────────────────────────────────┐
│  一级处理:直接协商(运营人员)            │
│  ├─ 时效:24-48 小时                      │
│  ├─ 方式:微信/电话沟通                   │
│  ├─ 目标:达成一致,执行退款/修改          │
│  └─ 工具:话术模板 + 决策矩阵             │
└──────────────────┬──────────────────────┘
                   ↓ 协商失败
┌─────────────────────────────────────────┐
│  二级处理:主管调解(主管/负责人)         │
│  ├─ 时效:48-72 小时                      │
│  ├─ 方式:电话/视频会议                   │
│  ├─ 目标:重新评估,折中方案               │
│  └─ 工具:证据链 + 折中方案               │
└──────────────────┬──────────────────────┘
                   ↓ 调解失败
┌─────────────────────────────────────────┐
│  三级处理:平台/法律途径                  │
│  ├─ 时效:7 个工作日                      │
│  ├─ 方式:平台申诉/法律应对               │
│  ├─ 目标:依法依规处理,保护权益           │
│  └─ 工具:证据链 + 法律顾问               │
└─────────────────────────────────────────┘
```

### 4.2 一级处理:直接协商

**处理要点**:
- 24 小时内首次响应
- 倾听客户诉求,不急于反驳
- 基于决策矩阵给出方案
- 留出协商空间(首次报价留 10%-20% 让步空间)
- 全程文字记录,关键节点截图保存

**协商技巧**:
```
1. 先共情,再讲理
   "理解你的感受,我来看看怎么解决"

2. 聚焦问题,不针对人
   "咱们一起看看具体哪里出了问题"

3. 给选项,不做单选题
   "我给你两个方案:A 是 [X],B 是 [Y],你看哪个合适"

4. 锚定原则,逐步让步
   首次报价 → 客户还价 → 让步 → 成交
   让步幅度递减:首次让 20% → 二次让 10% → 三次让 5%

5. 限时成交,推动决策
   "这个方案有效期到 [日期],你看尽快确认"
```

### 4.3 二级处理:主管调解

**升级条件**:
- 一级协商 48 小时未达成一致
- 客户情绪激烈,运营人员无法处理
- 客户明确要求升级处理
- 涉及金额 > 2000 元

**调解流程**:
```
1. 运营人员移交案件
   - 整理纠纷时间线
   - 提供证据链
   - 说明已协商方案

2. 主管介入沟通
   - 致电客户,表明身份
   - 重新倾听诉求
   - 评估责任归属
   - 给出折中方案

3. 折中方案设计
   - 双方各让一步
   - 我方让步:退款比例上调 / 补偿增加
   - 客户让步:接受部分修改 / 放弃部分诉求
   - 签订《调解协议》

4. 执行与归档
   - 按协议执行
   - 双方确认结案
   - 归档复盘
```

### 4.4 三级处理:平台/法律途径

**升级条件**:
- 二级调解失败
- 客户已在平台发起投诉/维权
- 客户威胁法律手段
- 涉及金额较大(> 5000 元)

**平台应对**:
- 闲鱼:提交交易凭证,等待平台裁决(详见第六节)
- 淘宝:配合客服介入,提供证据
- 微信:基于聊天记录申诉

**法律应对**:
- 评估法律风险(合同效力、证据充分性)
- 准备证据链(详见第五节)
- 必要时咨询法律顾问
- 小额诉讼:积极应诉,提供证据

## 六、平台纠纷应对

### 6.1 闲鱼平台纠纷应对

**闲鱼维权规则要点**:
- 买家可在确认收货前申请退款
- 卖家可拒绝退款,进入闲鱼小法庭
- 闲鱼小法庭由用户投票裁决
- 虚拟商品(服务)维权难度较高

**应对策略**:
```
闲鱼纠纷应对流程:

1. 买家申请退款
   ├─ 未交付:同意退款(避免差评)
   ├─ 已交付:拒绝退款,提供证据
   └─ 已交付+质量异议:协商修改,拒绝退款

2. 进入闲鱼小法庭
   ├─ 准备证据链(截图+说明)
   ├─ 撰写申诉说明(客观、有条理)
   ├─ 强调:已交付 + 需求已确认 + 质量达标
   └─ 提供:交付截图 + 聊天记录 + 需求确认

3. 小法庭裁决
   ├─ 胜诉:退款申请被驳回
   ├─ 败诉:执行退款,接受结果
   └─ 持平:平台最终裁决

4. 差评应对
   ├─ 胜诉后客户差评:理性回应,说明事实
   ├─ 败诉后:接受差评,改进服务
   └─ 恶意差评:申诉平台删除
```

**闲鱼申诉话术模板**:
```
尊敬的闲鱼小法庭:
本次交易为技术服务订单,具体情况如下:
1. 需求确认:[日期] 客户确认需求(见截图 [X])
2. 定金支付:[日期] 客户支付定金 [金额](见截图 [X])
3. 交付完成:[日期] 我方完成交付并发送(见截图 [X])
4. 客户确认:[日期] 客户确认收到(见截图 [X])
5. 售后沟通:[日期] 客户提出 [问题],我方已提供修改(见截图 [X])

基于以上:
- 我方已按约定完成交付
- 客户已确认收到交付物
- 售后问题已提供修改服务
- 退款申请不符合交易约定

恳请小法庭公正裁决。
```

### 6.2 淘宝平台纠纷应对

**淘宝维权规则要点**:
- 虚拟商品默认不支持 7 天无理由退换
- 买家可申请售后,卖家可拒绝
- 淘宝客服介入裁决
- 严重纠纷可能影响店铺评分

**应对策略**:
```
淘宝纠纷应对流程:

1. 买家申请售后
   ├─ 拒绝售后,提供交付证据
   ├─ 与买家协商,提供修改
   └─ 协商不成,等待客服介入

2. 客服介入
   ├─ 提交证据:需求确认 + 交付记录 + 沟通记录
   ├─ 说明:已按约定交付,质量达标
   ├─ 强调:虚拟商品特性,不支持无理由退
   └─ 配合客服调查

3. 裁决执行
   ├─ 支持卖家:正常结案
   ├─ 支持买家:执行退款
   └─ 折中:部分退款

4. 店铺评分保护
   ├─ 差评申诉:提供证据,申请删除恶意差评
   ├─ 评分解释:理性回应,说明事实
   └─ 持续优化:降低纠纷率
```

### 6.3 微信交易纠纷应对

**微信交易特点**:
- 无平台担保,基于信任交易
- 维权难度最高
- 证据依赖聊天记录

**应对策略**:
```
微信纠纷应对流程:

1. 预防为主
   ├─ 交易前明确约定(文字)
   ├─ 大额交易签订电子协议
   ├─ 关键节点文字确认
   └─ 保留完整聊天记录

2. 纠纷协商
   ├─ 基于聊天记录协商
   ├─ 提供交付证据
   ├─ 必要时语音/电话沟通
   └─ 达成一致后文字确认

3. 协商不成
   ├─ 微信投诉:微信支付交易投诉
   ├─ 法律途径:小额诉讼
   └─ 接受损失,改进流程

4. 风险控制
   ├─ 大额交易建议走平台(闲鱼/淘宝)
   ├─ 微信仅用于小额/老客户
   ├─ 定金不超过 50%
   └─ 尾款交付前结清
```

### 8.1 案例 1:未开始 - 客户原因取消

```markdown
**案例编号**: CASE-0001
**纠纷类型**: 未开始 - 客户原因取消
**涉及金额**: 500 元(定金)
**处理级别**: 一级协商
**处理结果**: 改期,未退款

**背景**:
客户下单课设服务,支付定金 500 元,排期 2 周后。
下单 3 天后,客户称"找到同学帮忙了",要求退款。

**处理过程**:
1. 运营人员回应:理解情况,但定金已锁档期
2. 提供方案:定金不退,但可改期一次(30 天内)
3. 客户不接受,情绪激动
4. 升级主管:主管致电路径,说明档期成本
5. 最终方案:改期 30 天,客户接受

**经验总结**:
- 定金性质需在交易前明确说明
- 改期权益是有效的缓冲方案
- 主管介入可缓解情绪
```

### 8.2 案例 2:已交付 - 客户质量异议

```markdown
**案例编号**: CASE-0002
**纠纷类型**: 已交付 - 客户质量异议
**涉及金额**: 800 元(已付全款)
**处理级别**: 一级协商
**处理结果**: 修改后结案,未退款

**背景**:
客户下单毕设项目,支付 800 元,交付后客户称"代码跑不通",要求退款。

**处理过程**:
1. 运营人员请客户提供具体问题截图
2. 客户提供截图,确有 1 处 bug
3. 运营人员 2 小时内修复,发新版本
4. 客户测试后仍称"不满意",要求退款
5. 运营人员要求具体问题,客户无法指出
6. 引用需求确认单,确认已按需求交付
7. 客户最终接受,结案

**经验总结**:
- 交付前充分测试,减少 bug
- 要求客户具体描述问题
- 需求确认单是关键证据
- 修改后仍不满意,需坚定拒绝退款
```

### 8.3 案例 3:已开始未交付 - 我方原因

```markdown
**案例编号**: CASE-0003
**纠纷类型**: 已开始未交付 - 我方原因
**涉及金额**: 1500 元(定金)
**处理级别**: 一级协商
**处理结果**: 全额退款 + 补偿 300 元

**背景**:
客户下单项目辅导,支付定金 1500 元。
因我方人员变动,无法按期完成,客户要求退款。

**处理过程**:
1. 主动告知客户无法按期完成
2. 全额退定金 1500 元
3. 补偿 300 元(定金 20%)
4. 已完成部分免费交付
5. 致歉并赠送优惠券
6. 客户接受,关系未破裂

**经验总结**:
- 我方原因需主动告知,不拖延
- 全额退款 + 补偿是标准处理
- 主动承担违约责任
- 保留关系,未来可能复购
```

### 8.4 案例 4:已交付 - 我方质量缺陷(严重)

```markdown
**案例编号**: CASE-0004
**纠纷类型**: 已交付 - 我方质量缺陷(严重)
**涉及金额**: 1200 元(已付全款)
**处理级别**: 二级调解
**处理结果**: 免费修复 + 退款 400 元(33%)

**背景**:
客户下单课设,交付后客户发现核心功能无法运行。
确认是我方代码逻辑错误,属严重缺陷。

**处理过程**:
1. 客户反馈问题,运营确认缺陷
2. 优先修复,48 小时内出新版本
3. 客户测试后仍不满意(功能勉强但体验差)
4. 升级主管调解
5. 协商方案:免费修复 + 退款 400 元(33%)
6. 客户接受,签订调解协议

**经验总结**:
- 严重缺陷需优先处理
- 修复不成需协商退款
- 退款比例 30%-70% 合理
- 签订调解协议,避免后续追诉
```

**处理过程**:

2. 准备证据:需求确认 + 交付记录 + 客户确认消息
3. 撰写申诉说明,提交小法庭

5. 小法庭投票:支持卖家
6. 客户差评,理性回应说明事实

**经验总结**:
- 闲鱼交易需保留完整证据
- 小法庭申诉需客观、有条理
- 交付确认消息是关键证据
- 差评需理性回应
```

运营要求具体问题,客户拒绝提供,威胁差评 + 投诉。

2. 客户威胁差评 + 群内抹黑

### 8.7 案例 7:需求变更纠纷

**涉及金额**: 900 元(已付全款)

**处理结果**: 部分修改,未退款

**背景**:
客户下单课设,交付后客户称"我还要加 XX 功能",要求免费加。
运营认为超出原始需求,客户认为"当时说过的"。

**处理过程**:
1. 调取需求确认单,核对原始需求
2. 确认新增功能不在原始需求内
3. 提供方案:新增功能按新订单,享 8 折
4. 客户不接受,要求免费
5. 坚持原则,引用需求确认单
6. 客户最终接受 8 折新增

**经验总结**:
- 需求确认单是核心证据
- 新增需求按新订单处理
- 坚持原则,不因客户坚持让步
- 提供优惠作为缓冲
```

### 8.8 案例 8:小额诉讼应对

```markdown
**案例编号**: CASE-0008
**纠纷类型**: 已交付 - 客户诉讼
**涉及金额**: 2000 元(微信交易)
**处理级别**: 三级法律
**处理结果**: 调解结案,退款 500 元

**背景**:
客户交付后不满意,要求全额退款 2000 元。
我方拒绝,客户通过微法院提起小额诉讼。

**处理过程**:
1. 收到法院通知,评估案件
2. 整理证据:需求确认 + 交付记录 + 客户确认
3. 撰写答辩状,线上提交
4. 庭前调解:法官主持调解
5. 调解方案:退款 500 元(25%),双方接受
6. 签订调解书,执行退款

**经验总结**:
- 小额诉讼成本高,优先调解
- 证据链是核心
- 调解比判决更灵活
- 接受折中方案,降低风险
```
