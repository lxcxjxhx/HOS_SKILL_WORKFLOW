# 报价话术模板

> **模块**: templates
> **文档编号**: TPL-0003
> **版本**: 1.0.0 | **最后更新**: 2026-07-26
> **适用阶段**: 冷启动 / 稳定期 / 扩张期

---

## 文档说明

本模板是 HOS 微商技术服务运营体系中报价沟通环节的专项参考。文档基于《定价策略引擎》的报价推演公式,将定价逻辑转化为可直接用于客户沟通的话术脚本,覆盖报价前置准备、标准报价呈现、议价应对、加价处理、跟进催复与失败复盘全流程。

使用规则:

1. 所有报价话术必须以《定价策略引擎》推演出的报价为依据,严禁拍脑袋报价或随意让步。
2. 话术中的方括号 `[X]`、`[XXX]` 等占位符为必填项,发送前必须替换为实际数值。
3. 报价一经客户书面确认即视为合同金额,后续让步需走《需求变更确认流程》。
4. 议价应对需遵守"单次让步不超过 10%、累计让步不超过 20%"的红线,详见第七章禁忌清单。
5. 本模板与《沟通话术库》《需求确认 Checklist》《定价策略引擎》配套使用,不得单独引用。

## 一、报价前置准备

报价不是孤立动作,而是需求确认到价值呈现的链路终点。以下三个动作必须在报价前完成,缺一不可。

### 1.1 动作一:需求确认单闭环

**适用情境**:任何报价发送前,必须确保需求已书面确认。

```
报价前自检清单:

□ 需求确认单已双方签字(电子签名亦可)
□ 功能清单已逐条列出并标注优先级
□ 交付物清单已明确(代码/文档/PPT/答辩辅导)
□ 截止时间已精确到日,加急与否已确认
□ 技术栈已确认,含"是否允许 AI 辅助"
□ 售后条款已约定(修改次数/有效期/超范围计费)

未完成上述任一项,不得发送正式报价。
需求模糊会导致报价失准,后续必然扯皮。
```

**注意事项**:

- 需求确认单是报价的"地基",地基不稳报价必塌。
- 如客户催促报价但需求未确认,按《沟通话术库》2.1 节澄清话术处理,不妥协。
- 例外:极简需求(如代码调试)可口头确认后报价,但仍需文字留痕。

### 1.2 动作二:报价推演与缓冲预留

**适用情境**:基于确认需求,按《定价策略引擎》公式推演报价,并预留议价缓冲。

```
报价推演记录单(内部使用,不发客户)

【需求拆解】
- 模块 A:工时 Xh
- 模块 B:工时 Xh
- 模块 C:工时 Xh
- 沟通修改预留:Xh
合计:Xh

【参数匹配】
- 时薪基准:[XX] 元/h(按项目类型与阶段取值)
- 难度系数:[X.X](套用难度判定决策树)
- 紧急系数:[X.X](按交付周期)
- 议价缓冲率:[10%~20%](按运营阶段)

【报价计算】
基础报价 = X × XX × X.X × X.X = [XXXX] 元
最终报价 = 基础报价 × (1 + 缓冲率) = [XXXX] 元
取整报价:[XXXX] 元

【让步底线】
- 单次让步上限:[XXXX] 元(报价 10%)
- 累计让步上限:[XXXX] 元(报价 20%)
- 利润底线:[XXXX] 元(时薪基准下限,不可破)
```

**注意事项**:

- 报价推演单为内部记录,归档备查,不发送客户。
- 缓冲率必须预留,冷启动期 5%-10%,稳定期 10%-15%,扩张期 15%-20%。
- 利润底线即"时薪基准下限",跌破即拒单,不通过降时薪让步。

### 1.3 动作三:客户画像与报价策略匹配

**适用情境**:根据客户类型选择报价呈现方式与让步策略。

```
客户画像判定:

【客户类型】
□ 学生党:预算敏感,价格驱动,需突出性价比
□ 创业者:关注 ROI,价值驱动,需突出业务价值
□ 企业客户:流程规范,需正式报价单与开票
□ 老客户:信任已建立,可直给老客价

【报价策略匹配】
- 学生党:报价取区间下限,缓冲率 5%-10%,优先减功能降价
- 创业者:报价取区间中值,缓冲率 10%-15%,优先延期折扣
- 企业客户:报价取区间中上限,缓冲率 15%,优先全额预付优惠
- 老客户:报价直接打 95 折,缓冲率 5%,不再额外让步

【呈现方式】
- 学生党:微信轻量报价(简明扼要)
- 创业者:结构化报价单 + 语音沟通
- 企业客户:正式报价单 PDF + 邮件
- 老客户:微信直接报老客价
```

**注意事项**:

- 客户画像需基于历史沟通与渠道来源判断,不凭单次对话下结论。
- 学生党不等于低价值,部分研究生项目客单价高。
- 企业客户必须走对公流程,个人收款会引发合规问题。

## 二、标准报价话术模板

### 2.1 结构化报价单话术

**适用情境**:中型以上项目(报价 ≥1000 元),需正式结构化呈现,适用于微信长文本或邮件。

```
您好,基于我们确认的需求,本次项目报价如下:

==================================================
报价单编号:QUO-[YYYYMMDD]-[XXX]
客户:[姓名/公司]
项目名称:[项目名]
报价日期:[YYYY-MM-DD]
有效期:7 天
--------------------------------------------------

【一、需求概述】
[一句话概括项目目标与交付物范围]

【二、工时拆解】
| 模块 | 工时(h) | 说明 |
|------|---------|------|
| [模块 A] | [X] | [说明] |
| [模块 B] | [X] | [说明] |
| [模块 C] | [X] | [说明] |
| 文档与测试 | [X] | [说明] |
| 沟通修改预留 | [X] | [说明] |
合计:[XX] h

【三、定价参数】
- 时薪基准:[XX] 元/h
- 难度系数:[X.X]
- 紧急系数:[X.X]

【四、报价明细】
基础报价:[XX] × [XX] × [X.X] × [X.X] = [XXXX] 元
最终报价:[XXXX] 元(已含议价缓冲,取整)

【五、交付与售后】
- 交付周期:[X] 天
- 修改轮次:2 轮(范围限 Bug 与小调整)
- 售后支持:交付后 7 天

【六、付款方式】
- 定金:50% 即 [XXXX] 元,到账后开工
- 尾款:交付验收后支付 [XXXX] 元
- 收款方式:[支付宝/微信/银行卡/对公]

==================================================

报价依据为工时拆解 + 难度系数 + 紧急系数,
明细可查,无虚高。请您确认报价无误,
我发送收款方式。如有调整需求可随时沟通。
报价有效期 7 天,超期需重新核算。
```

**注意事项**:

- 结构化报价单必须包含工时拆解,让客户感知价值构成。
- 报价有效期必填,防止客户数月后要求按旧价执行。
- 发送后需跟问"是否有疑问",不发了之。

### 2.2 微信轻量报价

**适用情境**:小型项目(报价 <1000 元)或学生客户,微信即时沟通,需简明扼要。

```
您好,需求我看过了,报价如下:

【项目】[一句话描述]
【交付物】代码 + 文档(含注释)
【工时】约 [X] 小时
【报价】[XXX] 元
【周期】[X] 天
【条款】
- 定金 50% 即 [XXX] 元,到账开工
- 尾款验收后付 [XXX] 元
- 含 2 次免费修改,售后 7 天

价格已经按学生价/老客价核算,明细可查。
确认的话我发收款方式,有疑问随时说。
```

**注意事项**:

- 轻量报价虽简,但定金、尾款、售后条款不可省。
- 主动提及"明细可查",建立可信度。
- 不省略"定金到账开工"这一条,防止白做风险。

### 2.3 闲鱼商品报价

**适用情境**:闲鱼商品页咨询,需在平台规则内报价,避免违规。

```
(闲鱼私信回复)

您好,这个需求可以做。具体价格要看:
- 功能点多少
- 用什么技术
- 什么时候要

方便的话私聊详谈 [引导加微信]。
一般这类项目价格在 [XX-XX] 元区间,
确认需求后给准确报价。

可以先免费咨询,合适再合作。
```

**注意事项**:

- 闲鱼不直接报实价,给区间即可,防止比价与违规。
- 区间需真实,下限为成本线,上限为正常报价。
- 引导加微信的话术需委婉,避免被判定导流违规。

## 三、报价呈现技巧

报价不只是报数字,更是价值传递。以下四种技巧可组合使用,提升报价的接受度。

### 3.1 价值锚定

**适用情境**:客户对报价缺乏参照,需主动建立价值锚点。

```
关于这个报价,给您几个参照:

【工时锚点】
这个项目预计投入 [X] 小时,按 [时薪] 元/h 核算,
相当于您花 [XX] 元/小时请一位 [技术领域] 工程师,
市场均价在 [XX-XX] 元/小时,我们处于 [中位/偏下]。

【服务锚点】
报价不只是代码,还包含:
- [X] 轮免费修改,确保验收通过
- [X] 天售后支持,交付不撒手
- 代码含详细注释,您可自主维护
- [文档/PPT/答辩辅导] 全套交付

【市场锚点】
同类项目市场均价 [X-X] 元,
我们的报价 [处于中位 / 偏下 / 略高但因 XXX],
售后更全,性价比更高。

这样看,[XXXX] 元的报价是否合理?
```

**注意事项**:

- 价值锚定核心是"让客户感觉赚了",而非"我们便宜"。
- 市场锚点需真实可验证,不虚构不夸大。
- 工时锚点与市场锚点二选一即可,过多锚点反而稀释说服力。

### 3.2 工时拆解呈现

**适用情境**:客户质疑"为什么这么贵",用工时透明化建立信任。

```
这个报价的工时拆解是这样的:

【工时明细】
- 需求分析与方案设计:[X]h
- 数据库设计:[X]h
- 后端接口开发:[X]h
- 前端页面开发:[X]h
- 联调与测试:[X]h
- 文档与部署说明:[X]h
- 沟通与修改预留:[X]h
合计:[XX]h

【核算】
[XX]h × [时薪] 元/h × [难度系数] × [紧急系数]
= [XXXX] 元

每一项工时都有对应交付物,不存在虚报。
如果您觉得某部分可以自己完成,我们可以扣减,
比如 [模块] 您自己做,减 [XX] 元。
```

**注意事项**:

- 工时拆解需与报价单一致,不自相矛盾。
- 主动提供"客户自己做某模块可减价"的选项,体现灵活。
- 沟通修改预留工时必须明示,让客户理解"售后有成本"。

### 3.3 对比锚定

**适用情境**:客户提及"别人更便宜",需通过对比强化差异。

```
理解您对比了其他报价。价格差异通常来自这几个方面:

【服务范围对比】
- 低价报价可能只含代码,不含 [文档/PPT/售后]
- 我们的报价包含 [X 轮修改 + X 天售后 + 全套交付物]

【质量保障对比】
- 低价报价可能套用模板,无定制
- 我们按您的需求定制开发,含详细注释,可自主维护

【售后保障对比】
- 低价报价交付后可能失联
- 我们提供 [X] 天售后,[X] 轮免费修改

【风险对比】
- 低价报价无需求确认单,纠纷无据
- 我们全程书面确认,权益有保障

如果您只看价格,低价确实有吸引力。
但考虑到服务全包与售后保障,
我们的综合性价比更高。
```

**注意事项**:

- 对比锚定基于事实,不诋毁同行,只强调自身差异。
- 主动承认低价存在,不否认市场现实,更显客观。
- 落脚点在"综合性价比",而非"我们更便宜"。

### 3.4 稀缺性暗示

**适用情境**:课设季/毕设季等旺季,或客户要求加急,需暗示稀缺促成决策。

```
提醒您一点:现在是 [课设季/毕设季/年底],
我们的排期比较紧:

【当前排期】
- 本周档期:仅剩 [X] 个名额
- 下周档期:已满 [X]/[X]
- 您要求的 [日期] 交付,需在本周内确认

【建议】
如果确认合作,建议尽快付定金锁定档期。
定金到账后排期正式锁定,不会插单。
如果延后确认,可能需要顺延到 [日期] 后才能开工,
可能影响您的截止时间。

这不是催您,是排期实际情况,如实告知。
```

**注意事项**:

- 稀缺性暗示必须真实,不虚构档期紧张。
- 语气客观,不制造焦虑,如"这不是催您"的免责表述。
- 落脚点在"为您着想"(避免影响截止时间),而非"为我创收"。

## 四、议价应对话术矩阵

议价是报价后最高频的场景。以下按客户类型与压价话术分类,提供分场景应对脚本。

### 4.1 "太贵了"应对话术

#### 话术 1:工时拆解回应(适用于学生党)

```
理解您觉得贵。我拆解下您看:

这个项目预计 [X] 小时,报价 [XXX] 元,
折算 [XX] 元/小时,跟家教一个价。
而且包含 [文档/PPT/答辩辅导] 和 [X] 天售后,
不是单纯给个代码。

如果预算紧,我们可以:
- 去掉 [非核心模块],降到 [XXX] 元
- 延长交付到 [X] 天,降到 [XXX] 元(去加急)

您看哪个方案合适?
```

#### 话术 2:价值锚定回应(适用于创业者)

```
贵不贵看跟什么比。

如果只买代码,确实有更便宜的。
但我们的报价包含:
- 定制开发(非套模板)
- [X] 轮修改确保验收
- [X] 天售后支持
- 全套交付物与文档

相当于请一位 [技术领域] 工程师 [X] 小时,
时薪 [XX] 元,市场均价 [XX-XX] 元。

如果您关注的是落地效果与后续可维护性,
这个价格是值得的。
```

#### 话术 3:减功能降价回应(适用于预算明确的客户)

```
没问题,价格可以谈,我们看怎么调整:

【方案一】去掉 [模块 A],降到 [XXX] 元
【方案二】去掉 [模块 A + B],降到 [XXX] 元
【方案三】保留全部,延长工期到 [X] 天,降到 [XXX] 元

需要说明:减掉的功能后续如需补回,单独报价。
您倾向哪个?
```

#### 话术 4:质量底线回应(适用于压价过狠的客户)

```
理解您想压价,但有个底线我需要说明:

时薪 [XX] 元已经是这个技术方向的下限,
再降就没法保证交付质量,得不偿失。

如果您预算确实在 [XXX] 元以内,
建议您找 [其他渠道/学生兼职],
我们这个价位匹配的是 [定制开发 + 全套售后],
定位不同。

希望您理解,不是不接,是不能勉强。
```

#### 话术 5:老客优惠回应(适用于老客户)

```
老客户当然有优惠。这个项目原价 [XXX] 元,
给您按老客价 [XXX] 元(95 折)走。

不过这个价格已经是底价了,
- 时薪没降,只是让出了缓冲
- 服务标准不变,仍含 [X] 轮修改 + [X] 天售后

您看可以的话,我发收款方式。
后续有需要随时找我,老客优先排期。
```

### 4.2 "别人更便宜"应对话术

#### 话术 1:服务范围对比(通用)

```
理解您货比三家。价格差异主要来自服务范围:

- 低价报价可能只含代码,不含 [文档/售后]
- 我们的报价含 [全套交付物 + X 天售后]

您方便把对方的报价明细发我看看吗?
我帮您分析下差异在哪,不强行比价,
只帮您判断哪个更划算。
```

#### 话术 2:质量差异说明(适用于创业者/企业客户)

```
便宜的可能有便宜的道理:

- 是否定制开发(非套模板)
- 是否含售后修改
- 是否有需求确认单(纠纷依据)
- 交付后是否还找得到人

我们的报价包含上述全部保障。
如果对方也包含,价格还更低,那是好选择;
如果对方不包含,您省的可能后续要补回来。
```

#### 话术 3:风险提示(适用于学生党)

```
学生接单确实价格低,但有几个风险您评估下:

- 是否同校同专业,理解您的课程要求
- 交付后能否找到人修改(售后)
- 是否签需求确认单(防止跑单)
- 代码质量是否可答辩(老师追问能解释)

不是说不让学生接,而是看您更看重什么。
我们贵一点,但上述风险都有保障。
```

#### 话术 4:不诋毁同行(通用)

```
每个服务商定价不同,我们不评价同行。

我能告诉您的是:
- 我们的报价依据是工时 × 时薪 × 系数,可查
- 服务包含 [X 轮修改 + X 天售后]
- 全程书面确认,权益有保障

如果您选择更低价的,完全理解。
如果后续遇到问题,也欢迎回来找我们,
不过那时候按新订单计费。
```

#### 话术 5:匹配需求档次(适用于压价过狠)

```
市场确实有更低价的,但定位不同:

- [XX] 元档:学生兼职,质量与售后无保障
- [XX] 元档:个人接单,有基本售后
- [XX] 元档:我们这档,定制开发 + 全套保障
- [XX] 元档:工作室/公司,流程更重价格更高

您现在的需求是 [项目类型],
建议选 [XX] 元档比较合适,质量与性价比平衡。
如果您预算在 [XX] 元档,我们也可以谈,
但服务范围需要调整。
```

### 4.3 "能不能再优惠"应对话术

#### 话术 1:让步换条件(通用)

```
优惠可以谈,但需要对等条件:

【选项】
- 减功能:[去掉某模块],降 [XX] 元
- 延工期:从 [X] 天延到 [Y] 天,降 [XX] 元
- 全额预付:不分开付,降 [5%]
- 案例授权:允许脱敏后作为案例展示,降 [XX] 元

单方面降价不行,得换取对等价值。
您倾向哪个?
```

#### 话术 2:让步边界说明(适用于反复压价)

```
我已经让了 [XX] 元,到了边界了:

- 单次让步不超过报价 10%(已到)
- 累计让步不超过报价 20%(还剩 [XX] 元空间)
- 时薪基准不能再降(否则亏本)

再降就没法保证质量了,希望您理解。
如果您还是觉得贵,我们看下能否减功能,
而不是继续压总价。
```

#### 话术 3:赠品替代降价(适用于不想降总价)

```
价格真的到底了,但我可以给您加点东西:

- 原:[X] 轮免费修改 → 加到 [X+1] 轮
- 原:[X] 天售后 → 延长到 [X+3] 天
- 赠送:一次远程演示 / 部署指导(价值 [XX] 元)

总价不变,但服务更全,您看可以?
```

#### 话术 4:分期支付缓解压力(适用于预算紧但总价可接受)

```
总价不变,但付款方式可以灵活:

- 原方案:定金 50% + 尾款 50%
- 分期方案:定金 30% + 中期 40% + 尾款 30%
  (中期款在 [里程碑] 时支付)

这样前期压力小点,但总价不降,
只是分摊到不同节点。您看可以?
```

#### 话术 5:坚定拒绝(适用于无理压价)

```
这个价格确实做不了,我坦诚说明:

- 时薪 [XX] 元已是下限,再降亏本
- 缓冲率 [X%] 已全部让出
- 服务范围已最小化,无法再减

如果您预算卡在 [XXX] 元,
建议找 [其他渠道],我们匹配不了。
不是不想接,是不能亏本接。

希望您理解,也祝您找到合适的。
```

### 4.4 "预算有限"应对话术

#### 话术 1:分期报价(适用于大项目预算不足)

```
预算有限我们可以分期做:

【分期方案】
- 第一期:核心功能 [模块 A + B],报价 [XXX] 元
  → 交付可运行的 MVP
- 第二期:扩展功能 [模块 C + D],报价 [XXX] 元
  → 按需追加,时间不限

这样您先花 [XXX] 元拿到可用的版本,
后续预算宽裕了再扩展,不影响使用。
```

#### 话术 2:裁剪需求(适用于预算硬性卡死)

```
那我们看下哪些功能可以裁:

【必须保留】
- [核心模块 A]:报价 [XX] 元
- [核心模块 B]:报价 [XX] 元

【可以裁掉】
- [锦上添花模块 C]:省 [XX] 元
- [非必要模块 D]:省 [XX] 元

裁掉后报价 [XXX] 元,符合您的预算。
后续如需补回,单独报价,不影响。
您看这样安排可以?
```

#### 话术 3:延期换折扣(适用于时间不敏感)

```
预算紧的话,时间上能放宽吗?

- 原交付:[X] 天(含加急)
- 延期到:[Y] 天(正常排期)
- 价格:从 [XXX] 元降到 [XXX] 元(去加急)

这样我也能把其他订单排开,
质量更有保障。您时间允许的话,建议这个方案。
```

#### 话术 4:替代方案(适用于预算极低)

```
预算 [XXX] 元确实低于我们的底线,
但有几个替代方案您可以考虑:

- 方案一:买我们的标准化教程/模板,[XX] 元,自己改
- 方案二:只买核心代码(不含文档/售后),[XXX] 元
- 方案三:找学生兼职,[XX-XX] 元区间

如果您坚持要定制开发 + 全套售后,
[XXX] 元确实做不了,抱歉。
看您怎么选?
```

#### 话术 5:全额预付换折扣(适用于预算够但想省)

```
预算够但想省点,可以这样:

- 原方案:定金 50% + 尾款 50%,总价 [XXX] 元
- 全额预付:一次性付清,总价 [XXX] 元(95 折)

省 [XX] 元,但需要前期就把全款付了。
您手头宽裕的话,这个方案划算。
```

## 五、加价场景话术

加价是执行中的敏感动作,必须基于事实,沟通透明,给客户选择权。

### 5.1 需求蔓延加价

**适用情境**:客户在执行中不断追加小需求,累积超出原范围。

```
项目进行中,我梳理了下需求变更:

【原需求】
[复述确认单中的需求范围]

【新增需求】
- [新增点 1]:[说明]
- [新增点 2]:[说明]
- [新增点 3]:[说明]

【评估】
- 新增工时:[X]h
- 加价金额:[XXX] 元
- 工期影响:增加 [X] 天

【说明】
这些需求不在原确认单范围内,
属于需求扩展,需另收费。
单次小需求看着不多,但累积起来工时不少,
现在跟您确认,不擅自加价也不擅自做主。

【选项】
□ 同意加价,按新方案执行
□ 部分加价(只做 [新增点 1]),[XXX] 元
□ 不加价,新增需求本期不做,后续另议

您怎么看?
```

**注意事项**:

- 需求蔓延加价必须及时,不等到交付才一次性算账。
- 每个新增点都要列明,不笼统说"超出范围"。
- 提供部分加价选项,体现灵活。

### 5.2 难度超预期加价

**适用情境**:执行中发现技术难点,实际工时远超预估,需说明并加价。

```
项目执行中遇到一个技术情况,需要跟您确认:

【情况说明】
- 原预估:[模块] 工时 [X]h
- 实际情况:[技术难点描述],需额外 [Y]h
- 发现时间:[日期]

【原因】
[说明:需求文档未明确 / 第三方 API 变动 / 技术栈兼容性问题等]

【影响】
- 新增工时:[Y]h
- 加价金额:[XXX] 元
- 工期影响:增加 [X] 天 / 无影响(可消化)

【选项】
□ 同意加价 [XXX] 元,按新方案执行
□ 不加价,但需 [简化该模块 / 延长工期 / 降低标准]
□ 暂停,双方讨论其他方案

这个情况开始前确实难以预判,
现在如实告知,不隐瞒也不擅自决定。
```

**注意事项**:

- 难度超预期加价必须基于客观事实,不能因自身能力不足加价。
- 说明原因时区分"需求方原因"与"我方原因",后者不宜加价。
- 提供不加价选项(降标准/延工期),不强推加价。

### 5.3 加急加价

**适用情境**:客户在执行中要求提前交付,需调整紧急系数并加价。

```
您提到希望提前到 [日期] 交付,我评估了下:

【原排期】
- 交付时间:[原日期]
- 紧急系数:1.0(正常)

【新排期】
- 交付时间:[新日期]
- 紧急系数:1.5(加急)/ 2.0(特急)
- 影响:需调整其他订单 / 加班赶工

【加价方案】
- 原报价:[XXX] 元(紧急系数 1.0)
- 新报价:[XXX] 元(紧急系数 [X.X])
- 加价金额:[XXX] 元

【说明】
加急费用用于补偿排期调整与加班成本,
不是我多收您钱,而是工时单价按紧急度调整。
如果您能接受原交付时间,价格不变。

您看是加急还是按原排期?
```

**注意事项**:

- 加急加价必须基于客户明确要求提前,不因"我比较急"等模糊表述触发。
- 加急系数按《定价策略引擎》标准:1-3 天 1.5,<24h 2.0。
- 提供不加急选项,不强推。

## 六、报价后跟进话术

报价发送后客户沉默是常态,需按节奏跟进,不催不冷。

### 6.1 24h 未回复

**适用情境**:报价发送后 24 小时客户未回复,需轻量跟进。

```
您好,昨天发的报价方案您看到了吗?

如果有疑问可以随时说,我帮您解答。
如果还在考虑,也不着急,想好了再决定。

另外提醒下,报价有效期 [X] 天,
超期可能需要重新核算排期。

需要调整功能范围或付款方式,也可以聊。
```

**注意事项**:

- 24h 跟进需轻量,不催促,不施压。
- 主动提及"可调整",降低客户决策门槛。
- 提醒报价有效期,制造轻微紧迫感。

### 6.2 48h 未回复

**适用情境**:报价发送后 48 小时仍未回复,需进一步跟进。

```
您好,报价方案发过去两天了,还没收到您的反馈。

是不是预算或需求有变化?
方便的话可以说下您的想法:
- 预算不合适?我们可以谈分期或减功能
- 需求有调整?我们重新确认后再报
- 还在比较?理解,有疑问随时问
- 暂时不做了?也没关系,告知一声即可

不管什么情况,都欢迎直说,不尴尬。
我这边排期也比较紧,如果您确定不做,
我好把档期让给其他客户,望理解。
```

**注意事项**:

- 48h 跟进需更直接,主动列出可能原因,降低回复门槛。
- 提及"排期紧,需让档期",制造合理紧迫感,但不威胁。
- 给客户台阶(暂不做也没关系),避免僵局。

### 6.3 已读不回

**适用情境**:客户已读报价但无回复,需打破僵局。

```
看到您已读了报价,但还没回复,猜您可能在考虑。

直接问下:是不是价格方面有顾虑?
如果是,我们可以聊:
- 减功能降价
- 延期折扣
- 分期支付

或者您觉得哪里不合适,直说无妨。
我们这行沟通越直接,合作越顺。
就算这次不合作,也希望能给个反馈,
我们改进,下次有机会再合作。
```

**注意事项**:

- 已读不回需主动打破,不被动等待。
- 直接点出"价格顾虑",这是最常见原因。
- 给客户"不合作也没关系"的出口,降低回复压力。

### 6.4 被压价后跟进

**适用情境**:客户压价后我方已让步,但客户仍未确认,需跟进。

```
上次聊到价格,我给了 [方案 X](让步后 [XXX] 元),
您当时说考虑下,现在有结论了吗?

需要说明:
- 这个让步方案有效期 [X] 天(到 [日期])
- 超期后需按原报价 [XXX] 元执行
- 让步空间已到边界,无法再降

如果您确认 [方案 X],我发收款方式锁定档期。
如果您还在比较,也告知一声,
我这边好安排排期,望理解。
```

**注意事项**:

- 被压价后跟进需明确让步有效期,防止客户无限拖延。
- 强调"让步已到边界",杜绝二次压价。
- 语气坚定但不强硬,留合作余地。

## 七、报价失败复盘话术

报价失败不等于关系终结,友好收尾可为未来合作留口子。

### 7.1 失败单友好收尾

**适用情境**:客户明确表示不合作(选了别家/预算不够/暂不做),需体面收尾。

```
理解您的决定,感谢您给的机会。

不管这次是否合作,几点说明:

【关于本次报价】
- 报价有效期 [X] 天,期间如有变化可随时联系
- 超期需重新核算,可能因排期变动调价

【关于后续】
- 如果合作方出现问题(质量/售后/跑单),
  欢迎随时回来找我们,按新订单计费
- 后续有新需求,老询价客户有优惠

【关于反馈】
如果您方便,能否告知不合作的原因?
- 价格高?我们优化定价策略
- 服务范围不符?我们调整服务设计
- 其他原因?我们改进

您的反馈对我们很重要。祝项目顺利!
```

**注意事项**:

- 失败收尾需真诚,不带怨气,不追问"为什么选别人"。
- 主动留口子(后续回来找我们),但说明按新订单计费。
- 询问反馈用于内部优化,但尊重客户不回复的权利。

### 7.2 失败单复盘记录

**适用情境**:报价失败后,内部复盘原因,优化后续报价策略。

```
报价失败复盘单(内部记录)

【基本信息】
- 报价单号:QUO-[YYYYMMDD]-[XXX]
- 客户:[脱敏标识]
- 项目类型:[类型]
- 报价金额:[XXX] 元
- 失败日期:[YYYY-MM-DD]

【失败原因】
□ 价格过高(客户选了更低价)
□ 服务范围不符(客户需求不同)
□ 交付周期不匹配(客户要更快/更慢)
□ 客户预算不足(项目搁置)
□ 客户选择了自助/学生兼职
□ 其他:[说明]

【客户反馈】(如有)
[记录客户原话或转述]

【复盘分析】
- 报价推演是否合理:□ 是 □ 否(原因:[说明])
- 缓冲率是否恰当:□ 是 □ 否(原因:[说明])
- 客户画像判断是否准确:□ 是 □ 否(原因:[说明])
- 是否存在改进点:□ 是 □ 否(改进:[说明])

【后续动作】
□ 无,正常归档
□ 跟进客户(何时/方式)
□ 调整定价策略(具体调整)
```

**注意事项**:

- 复盘单为内部记录,归档备查,用于优化定价与沟通策略。
- 失败原因需如实记录,不粉饰,用于真实改进。
- 冷启动期每单必复盘,稳定期每周复盘,扩张期每月复盘。

## 八、报价话术禁忌清单

以下话术会引发纠纷、破坏信任或侵蚀利润,严格禁止。

### 8.1 不能说的话

```
【价格类禁忌】
✗ "随便你给多少都行" —— 显得没底线,必被压价
✗ "我先做着,价格好说" —— 范围蔓延,无法结算
✗ "这次亏本做,下次补" —— 下次客户不来了
✗ "市场最低价" —— 违反广告法,且自贬身价
✗ "包过,不过退款" —— 越权承诺,且涉及学术红线

【承诺类禁忌】
✗ "100% 通过验收" —— 验收权在客户,无法保证
✗ "无限制免费修改" —— 范围蔓延,工时失控
✗ "做完不满意全额退" —— 已投入工时无法回收
✗ "一定比某某便宜" —— 恶性竞争,且无法兑现
✗ "保证答辩通过" —— 答辩权在老师,无法保证

【沟通类禁忌】
✗ "你不懂,听我的" —— 傲慢,破坏信任
✗ "别问了,照做就行" —— 隐瞒风险,典型黑产特征
✗ "别人家更贵" —— 不诋毁同行,只讲自身差异
✗ "不做拉倒" —— 态度生硬,失去客户
✗ "你怎么这样" —— 情绪化,引发冲突
```

### 8.2 容易引发纠纷的表达

```
【模糊表述】(必须避免)
✗ "差不多 X 元" —— 用精确数字
✗ "尽快交付" —— 用具体日期
✗ "含基本售后" —— 明确次数与天数
✗ "小修改免费" —— 界定什么是"小修改"
✗ "看情况加价" —— 明确加价触发条件

【口头承诺】(必须避免)
✗ "口头说好了就行" —— 必须书面确认
✗ "微信语音说的" —— 语音后必须文字复述
✗ "到时候再说" —— 当下确认,不留尾巴
✗ "我记住了" —— 文字记录,不依赖记忆
✗ "放心吧" —— 用条款保障,不用口头安抚

【越权表述】(必须避免)
✗ "我们团队做" —— 个人接单不能虚报团队
✗ "X 年经验" —— 如实描述,不夸大
✗ "做过 N 个案例" —— 真实可验证,不编造
✗ "包售后一年" —— 不超出实际能力承诺
✗ "随时响应" —— 明确响应时效,不承诺 7×24
```

### 8.3 禁忌执行细则

```
1. 价格类禁忌的替代方案
   - "随便你给" → 按报价单执行,不让步无底线
   - "先做着" → 定金到账开工,不预支工时
   - "亏本做" → 拒单,不通过亏本换案例

2. 承诺类禁忌的替代方案
   - "100% 通过" → "按需求确认单交付,验收不通过免费修改"
   - "无限制修改" → "含 X 轮免费修改,超出按 X 元/小时"
   - "全额退" → "未开工全退定金,已开工按进度协商"

3. 沟通类禁忌的替代方案
   - "你不懂" → "我解释下原因:[说明]"
   - "别问了" → "这个问题我说明下:[说明]"
   - "不做拉倒" → "这个价格做不了,抱歉,祝您找到合适的"
```

- 冷启动期建议每单必记,稳定期可简化为关键节点记录。

### 9.2 让步决策快查表

谈判中快速判断是否可以继续让步。

```
让步前自检:

□ 本次让步是否超过报价 10%?
  → 是:停止,不再让步
  → 否:继续

□ 累计让步是否超过报价 20%?
  → 是:停止,已达缓冲上限
  → 否:继续

□ 让步是否换取对等条件?
  → 是:可以让步
  → 否:不让步,改为赠品或分期

□ 时薪基准是否被突破?
  → 是:拒单,不让步
  → 否:继续

□ 是否为口头让步?
  → 是:无效,必须书面确认
  → 否:继续

记忆口诀:单次不过十,累计不过二十,
         让步换条件,底线不可破。
```
