# 社群推广脚本

> **模块**: marketing
> **文档编号**: MKT-0004
> **版本**: 1.0.0 | **最后更新**: 2026-07-26
> **适用阶段**: 冷启动 / 稳定期 / 扩张期

---

## 一、社群类型与推广策略

不同社群的属性、成员构成与互动规则差异较大,需差异化制定推广策略,避免"一刀切"导致被封禁或口碑受损。

| 社群类型 | 推广策略 | 注意事项 |
|---------|---------|---------|
| 技术交流群 | 技术分享 + 问题解答 + 软植入 | 先建立技术人设,再引出服务 |
| 同学群 | 帮忙解答问题 + 分享资源 | 不要硬广,同学关系优先 |
| 老乡群 / 兴趣群 | 偶尔分享技术相关内容 | 频率要低,避免被踢 |
| 课程群 | 课设季精准投放 | 注意群规,很多课程群禁止广告 |

**策略要点说明:**

- **技术交流群**:核心阵地。通过持续输出高质量技术内容(如踩坑总结、源码解析、性能优化案例)建立专业人设,成员主动咨询时再顺势介绍服务,转化率最高。
- **同学群**:信任基础强,但商业氛围弱。以"帮忙"姿态出现,如解答同学的技术疑问、分享学习资料,建立"技术靠谱"的印象,私聊转化。
- **老乡群 / 兴趣群**:非目标社群,仅在成员聊到相关话题时自然切入,每月不超过 1-2 次。
- **课程群**:课设季(通常为学期末 1-2 个月)需求集中,可针对性提供"课设辅导"类服务,但必须先确认群规是否允许,避免被踢出甚至被举报。

## 二、技术分享脚本(5 分钟分享模板)

适用于技术交流群的定时分享环节。整体时长控制在 5 分钟以内,结构为"开场—问题—方案—软植入"四段式,确保信息密度高、广告感弱。

```
【开场 - 30 秒】
大家好,我是 [姓名/昵称],主要做 [技术方向,如 Java 后端 / Python 数据处理 / 前端工程化] 方向的开发。
今天跟大家分享一个小主题:[分享标题,如"线上 OOM 排查的 3 个常用手段"]。

【问题 - 30 秒】
先抛一个大家可能遇到的场景:
[描述一个具体问题,如"系统上线一周运行正常,突然某天凌晨 CPU 飙到 100%,重启后恢复正常,但隔几天又复现,日志里没有明显异常"]

这种情况排查起来比较麻烦,因为没有现场。下面分享我常用的排查思路。

【方案 - 3 分钟】
第一步:[具体操作,如"开启 GC 日志,观察 Full GC 频率"]
    [附简短代码或命令]
    -XX:+PrintGCDetails -Xloggc:gc.log

第二步:[如"使用 jstat 观察各代内存变化"]
    jstat -gcutil <pid> 1000

第三步:[如"用 jmap dump 堆内存,MAT 分析大对象"]
    jmap -dump:format=b,file=heap.hprof <pid>

通过这三步,基本能定位是 [具体原因,如"缓存对象未清理导致老年代撑爆"]。

【软植入 - 30 秒】
这种线上问题排查其实有一套比较通用的方法论,如果大家以后遇到类似问题,
或者项目里有性能、稳定性方面想找人看看的,可以随时私聊我,免费帮忙诊断一下。
```

**使用提示:**

- 分享内容务必真实,避免编造案例,否则被追问时露馅会严重损害人设。
- 代码片段控制在 5-10 行以内,过长会影响群内阅读体验。
- 软植入部分语气温和,以"帮忙"姿态出现,不要带价格或服务清单。

## 三、限时优惠推广脚本

适用于稳定期,在已建立一定信任基础的群内投放。核心是通过"限时 + 限量"制造紧迫感,但必须给群成员专属感,避免被当作普通广告。

```
【群内专属优惠话术】
@全体成员 跟大家同步个消息:
本月针对本群成员开放 [服务名称,如"毕业设计技术指导"] 的专属优惠,
原价 [原价] ,群友价 [优惠价] ,限量 [数量] 个名额。

这个服务主要解决 [核心痛点,如"课设技术方案选型 + 代码 review + 答辩问题预演"],
适合 [目标人群,如"正在准备毕业设计的同学"]。

【限时机制设计】
- 数量限制:本期仅 [N] 个名额,先到先得,售完即恢复原价。
- 时间限制:优惠有效期至 [具体日期,如本周日 24:00],逾期自动恢复原价。
- 双重机制建议二选一,避免规则过于复杂影响决策。

【引导私聊话术】
有需要的同学直接私聊我,备注"群优惠"即可享受专属价。
不确定是否适合自己的,也可以先私聊描述一下需求,我帮你判断一下。
```

**机制设计要点:**

| 机制类型 | 适用场景 | 优势 | 风险 |
|---------|---------|------|------|
| 数量限制 | 名额稀缺感强的高客单价服务 | 紧迫感强,决策快 | 售完后流失潜在客户 |
| 时间限制 | 低客单价、决策周期短的服务 | 覆盖面广 | 紧迫感较弱,易拖延 |
| 双重限制 | 促销活动节点 | 最强紧迫感 | 规则复杂,解释成本高 |

**注意事项:**

- 优惠价格需真实,不得虚构原价(合规要求)。
- 名额数量需真实可控,避免超卖后无法兑现。
- 同一群内同一服务的优惠活动间隔不少于 2 周,避免频繁促销导致信任贬值。

## 四、转介绍请求脚本

适用于交付完成、客户满意度较高的节点。转介绍是成本最低、转化率最高的获客方式,但请求时机和话术需把握分寸,避免给客户压力。

```
【交付后转介绍请求话术】
[客户姓名],这次 [服务名称] 的交付你觉得还满意吗?
[等待客户确认满意]

太好了。其实我这边主要就是靠大家口碑推荐,
如果你身边有同学/朋友也有类似 [需求类型,如"课设技术指导 / 项目代码 review"] 需求的,
方便的话帮我推荐一下,我会认真对待每一个转介绍来的客户。

【转介绍激励说明】
为了感谢你的推荐,这边有个小政策:
- 你推荐来的新客户,首单立减 50 元;
- 作为推荐人,你下次服务也减 50 元。
双方都有优惠,算是双赢。

如果暂时没有也没关系,后面有需要随时找我。
```

**话术要点:**

- 先确认客户满意度,不满意时绝不请求转介绍,否则会适得其反。
- 激励金额(双方各减 50)需与客单价匹配,低客单价场景可调整为优惠券或增值服务。
- 语气以"顺便提及"为主,不要强求,给客户留足拒绝空间。
- 转介绍来的新客户交付时,需主动提及"是 [推荐人] 推荐来的",形成闭环。

## 五、社群推广合规提醒

社群推广的核心是"长期主义",短期刷量换来的曝光会透支信任,得不偿失。以下为红线规则,务必遵守。

### 5.1 不刷屏

- 单个群内每天最多发布 1 条推广内容(含软植入)。
- 推广内容与日常技术分享交替进行,避免连续多天纯推广。
- 同一时段不在多个群复制粘贴相同推广文案,避免被识别为广告号。

### 5.2 不硬广

- 任何推广前必须先提供价值(技术分享、问题解答、资源分享)。
- 推广内容占比控制在总发言量的 20% 以内。
- 避免"价格 + 联系方式"式的纯广告,需结合场景自然引出。

### 5.3 不私加群成员

- 未经群成员主动咨询,不得私加好友推销服务。
- 被举报风险高,且可能被群主清退,影响在该群的长期运营。
- 如需主动触达,优先在群内互动建立熟悉度,等待对方主动添加。

### 5.4 不在其他人的推广下截流

- 其他同行在群内推广时,不得在评论区抢客户或贬低同行。
- 截流行为一旦被截图传播,将严重损害个人品牌。
- 正确做法:专注自身内容输出,用长期价值赢得客户。

## 六、社群运营周计划模板

按周制定内容计划,确保推广节奏稳定、内容类型均衡。以下模板可根据实际社群活跃时段调整。

```
=====================================
  社群运营周计划模板
=====================================

【周一】技术分享日
- 时段:20:00-20:30(群活跃高峰)
- 内容:5 分钟技术分享 + 15 分钟互动答疑
- 目标:强化技术人设,建立专业信任
- 投入:分享前 1 小时准备素材

【周二】问题解答日
- 时段:全天(重点关注晚间)
- 内容:主动回答群内技术问题
- 目标:提升存在感与好感度
- 投入:碎片时间,约 30 分钟

【周三】案例展示日
- 时段:21:00
- 内容:分享一个已完成项目案例(脱敏处理)
- 形式:问题描述 → 解决思路 → 最终效果
- 目标:展示服务能力,激发潜在需求

【周四】资源分享日
- 时段:12:00(午休时段)
- 内容:分享技术资源(电子书、工具、开源项目)
- 目标:提供纯价值,不带任何推广
- 投入:10 分钟整理资源链接

【周五】轻互动日
- 时段:晚间
- 内容:参与群内闲聊、技术话题讨论
- 目标:拉近关系,保持熟悉度
- 投入:碎片时间

【周六】促销活动日(每两周一次)
- 时段:20:00
- 内容:群内专属优惠投放(见限时优惠脚本)
- 目标:集中转化意向客户
- 投入:活动前 2 小时准备
- 注意:非活动周改为案例展示或休息

【周日】休息 / 复盘日
- 内容:不主动推广,复盘本周数据
- 复盘项:本周新增咨询数、转化数、内容互动情况
- 目标:优化下周计划
- 投入:30 分钟复盘

=====================================
  周计划执行检查清单
=====================================
[ ] 本周技术分享是否完成至少 1 次
[ ] 本周案例展示是否完成至少 1 次
[ ] 推广内容是否控制在每日 1 条以内
[ ] 是否有违规硬广 / 刷屏行为
[ ] 周日复盘是否完成
=====================================
```

**计划调整原则:**

- 冷启动期(前 4 周):以技术分享和问题解答为主,推广内容占比降至 10% 以内,优先建立信任。
- 稳定期:按模板执行,推广与价值输出比例约 2:8。
- 扩张期:可增加促销活动频次至每周 1 次,但需配合更多案例展示支撑。

## 八、合规提醒

> 本文档所有推广脚本均需在以下合规框架内使用:

1. **价格真实**:所有标注的原价、优惠价必须真实,不得虚构原价进行虚假促销。
2. **资质合规**:涉及技术服务交付的,需确保自身具备相应技术能力,不得虚假宣传。
3. **隐私保护**:案例展示需脱敏处理,不得泄露客户个人信息与项目敏感数据。
4. **平台规则**:遵守各社群平台(微信、QQ 等)的运营规则,避免被封号。
5. **广告标识**:商业推广内容应能让受众辨识为推广,不得以纯技术分享名义变相发布广告。
6. **合同留存**:通过社群转化的订单,需签订正规服务合同或留存聊天记录作为交付凭证。
