## 文档说明

本文档为 HOS 微商技术服务运营助手的订单管理系统主模板,用于支撑从需求确认到售后归档的订单全生命周期管理。所有字段均经过脱敏处理,仅记录运营所需的业务信息,不存储客户个人敏感数据(真实姓名、手机号、支付账号等),客户沟通与结算凭证应存储于平台侧或独立加密渠道。

本文档提供空白可复制模板与填写示例两部分,运营者可直接复用至飞书多维表格、Notion、Excel 或任意 Markdown 编辑器。

## 一、订单编号规则

### 1.1 编号格式

订单编号采用三段式结构,确保唯一性、可排序性与可读性:

```
ORD-YYYYMMDD-XXX
```

| 字段 | 说明 | 示例 |
|------|------|------|
| `ORD` | 固定前缀,标识订单类记录 | ORD |
| `YYYYMMDD` | 订单创建日期(客户首次咨询确认需求的日期) | 20260726 |
| `XXX` | 当日顺序号,三位数字,从 001 开始递增 | 001 |

**完整示例**: `ORD-20260726-001` 表示 2026 年 7 月 26 日创建的第 1 个订单。

### 1.2 编号生成规则

```
1. 每日 00:00 顺序号重置为 001
2. 顺序号跨日不复用,即使前一日订单取消也不回填
3. 订单编号一经生成不可修改,即使订单取消或退款
4. 跨平台订单(闲鱼/小红书/私域)统一编号,通过"客户来源"字段区分
5. 复购订单生成新编号,通过"客户编号"字段关联历史订单
```

### 1.3 客户隐私化处理规则

| 字段类型 | 处理方式 | 示例 |
|---------|---------|------|
| 客户姓名 | 保留姓氏 + 星号遮罩 | 张**、李*、王** |
| 客户编号 | 独立编号,与真实身份解耦 | CUST-202607-003 |
| 联系方式 | 不记录,仅存平台会话 ID | XY-session-7891 |
| 支付账号 | 不记录,以平台订单号代替 | XY-ord-2026xxx |
| 学校/单位 | 保留类型,脱敏具体名称 | 某985高校、某互联网公司 |
| 项目内容 | 技术描述,不含个人敏感信息 | Python 数据可视化课设 |

### 1.4 客户编号规则

```
CUST-YYYYMM-XXX
```

- 同一客户多次复购使用同一客户编号
- 新客户首次成单时分配编号
- 仅成单客户分配编号,咨询未成单不分配

## 三、订单状态流转图

### 3.1 状态定义

订单共设 7 种状态,覆盖完整生命周期。

| 状态码 | 状态名称 | 简述 |
|--------|---------|------|
| S1 | 需求确认 | 客户咨询中,需求与报价待敲定 |
| S2 | 已收定金 | 定金到账,正式排期 |
| S3 | 进行中 | 开发/服务执行中 |
| S4 | 待验收 | 交付物已提交,等待客户验收 |
| S5 | 已完成 | 验收通过,尾款结清 |
| S6 | 售后中 | 售后保障期内,处理返修/答疑 |
| S7 | 已取消 | 订单终止,已退款或协商关闭 |

### 3.3 状态进入与退出条件

```
[S1 需求确认]
  进入条件: 客户首次咨询并表达明确需求
  退出条件: 客户支付定金 → S2
           客户明确放弃  → S7
  预警: 停留 > 3 天未推进,触发跟进提醒

[S2 已收定金]
  进入条件: 定金到账(以平台流水为准)
  退出条件: 开发环境就绪,开始执行 → S3
  预警: 停留 > 2 天未启动,触发排期提醒

[S3 进行中]
  进入条件: 正式开始开发/服务执行
  退出条件: 交付物完成并提交客户 → S4
  预警: 距截止日 ≤ 1 天且进度 < 80%,触发加急预警

[S4 待验收]
  进入条件: 交付物提交客户
  退出条件: 客户验收通过 + 尾款到账 → S5
           客户提出返修           → 回到 S3
  预警: 停留 > 3 天客户未反馈,触发催验收

[S5 已完成]
  进入条件: 验收通过且尾款结清
  退出条件: 自动进入售后期 → S6
  预警: 无(终态之一,但需回填工时实际与满意度)

[S6 售后中]
  进入条件: 已完成订单自动转入,售后期默认 14 天
  退出条件: 售后到期日已过 → 归档
  预警: 临近到期 3 天提醒售后回访

[S7 已取消]
  进入条件: 任一阶段客户放弃 / 不可抗力 / 违规拒单
  退出条件: 终态,退款协商完成后归档
  预警: 需记录取消原因,用于复盘
```

## 四、订单状态管理细则

### 4.1 各状态停留时长预警

| 状态 | 正常停留时长 | 预警阈值 | 预警动作 |
|------|------------|---------|---------|
| S1 需求确认 | 1-2 天 | > 3 天 | 主动跟进客户,确认意向 |
| S2 已收定金 | 0-1 天 | > 2 天 | 立即排期,避免占用档期 |
| S3 进行中 | 按工时预估 | 距截止日 ≤ 1 天且进度 < 80% | 加急或协商延期 |
| S4 待验收 | 1-2 天 | > 3 天 | 催验收,必要时提供演示 |
| S5 已完成 | 即时 | 未回填工时/满意度 > 3 天 | 回填数据提醒 |
| S6 售后中 | 14 天 | 到期前 3 天 | 售后回访 + 满意度收集 |
| S7 已取消 | 即时 | 退款未闭环 > 3 天 | 推进退款/协商关闭 |

### 4.2 异常状态处理

```
异常1: 客户长期失联(S1/S4 停留超预警且联系无回应)
  处理: 平台站内信 + 微信双渠道触达,留痕 3 次未回应则转 S7,按平台规则处理定金

异常2: 范围蔓延(S3 中客户持续追加需求)
  处理: 启用《需求变更确认单》,明确新增需求与补价,书面确认后再执行

异常3: 逾期交付(S3 超过截止日)
  处理: 立即与客户沟通,协商新截止日,必要时部分退款或赠送售后延长

异常4: 验收争议(S4 客户拒收但已按需求交付)
  处理: 出具需求确认记录与交付物对照表,平台介入仲裁,保留全部沟通凭证

异常5: 售后纠纷(S6 客户提出超范围售后要求)
  处理: 核对原始需求与售后条款,超范围部分单独报价,不强行免费兜底

异常6: 违规订单(任一阶段发现需求触及红线)
  处理: 立即转 S7,按《合规决策流》执行,定金按平台规则退还
```

## 七、订单归档规范

### 7.1 归档节奏

| 订单状态 | 归档时机 | 归档动作 |
|---------|---------|---------|

| 数据类型 | 保留期限 | 说明 |

| 客户表记录 | 永久 | 支持复购识别与等级计算 |
