# SRC 项目 100 分制评分体系

## 总览

本评分体系用于对各 SRC（Security Response Center）漏洞赏金项目进行多维度量化评估，帮助安全研究者合理分配时间与精力，优先投入回报率最高的目标。

**满分：100 分**

| 维度 | 分值 | 权重说明 |
|------|------|----------|
| 奖励（Reward） | 20 | 现金奖励 + 赏金等级 |
| 范围（Scope） | 20 | 资产范围广度 |
| 活跃度（Activity） | 20 | 项目活跃程度 |
| 攻击面（Attack Surface） | 15 | 可攻击面大小 |
| 技术栈（Tech Stack） | 10 | 技术复杂度 |
| 竞争（Competition） | 10 | 研究者竞争程度 |
| 自动化（Automation） | 5 | 是否支持自动化测试 |

---

## 各维度详细说明

### 1. 奖励（Reward）— 20 分

由两部分组成：

#### 1.1 现金奖励（cash_bounty）— 10 分

根据项目公开的现金奖励上限进行评分：

| 分值 | 标准 |
|------|------|
| 10 | 奖励丰厚，处于行业前列 |
| 7 | 奖励水平较高 |
| 5 | 奖励水平中等 |
| 3 | 奖励偏低 |
| 1 | 奖励极少或无现金奖励 |

#### 1.2 赏金等级（bounty_level）— 10 分

SRC 平台对项目的赏金等级评定（通常为 1-5 级）：

| 等级 | 分值 | 说明 |
|------|------|------|
| 5 级 | 10 | 最高赏金等级 |
| 4 级 | 8 | 次高赏金等级 |
| 3 级 | 6 | 中等赏金等级 |
| 2 级 | 4 | 基础赏金等级 |
| 1 级 | 2 | 最低赏金等级 |

### 2. 范围（Scope）— 20 分

评估项目纳入 SRC 计划的资产范围大小：

| 分值 | 说明 |
|------|------|
| 20 | 范围极广，包含大量域名、IP、应用 |
| 15 | 范围较大，覆盖多个业务线 |
| 10 | 范围适中，覆盖核心业务 |
| 5 | 范围较窄，仅涉及少量资产 |
| 1 | 范围极小，仅单一场景 |

### 3. 活跃度（Activity）— 20 分

评估项目的活跃程度，包括修复速度、响应质量、研究者沟通等：

| 分值 | 说明 |
|------|------|
| 20 | 响应极快，修复及时，沟通顺畅 |
| 15 | 响应较快，修复较及时 |
| 10 | 响应一般，修复有一定延迟 |
| 5 | 响应较慢，修复延迟明显 |
| 1 | 响应极差或已停用 |

### 4. 攻击面（Attack Surface）— 15 分

评估目标资产的攻击面大小，攻击面越大，潜在漏洞数量越多：

| 分值 | 说明 |
|------|------|
| 15 | 攻击面极大，包含 Web、API、移动端、云等多种形态 |
| 11 | 攻击面较大，覆盖多种技术形态 |
| 7 | 攻击面适中，有一定可挖掘空间 |
| 4 | 攻击面有限，可挖掘空间较小 |
| 1 | 攻击面极小 |

### 5. 技术栈（Tech Stack）— 10 分

评估目标所使用的技术栈复杂度，复杂技术栈往往意味着更多漏洞机会：

| 分值 | 说明 |
|------|------|
| 10 | 技术栈复杂多样，涉及新兴技术与老旧系统并存 |
| 7 | 技术栈较为复杂 |
| 5 | 技术栈中等复杂度 |
| 3 | 技术栈相对简单 |
| 1 | 技术栈非常简单 |

### 6. 竞争（Competition）— 10 分

评估研究者竞争程度。**竞争越低，得分越高**：

| 分值 | 说明 |
|------|------|
| 10 | 新项目或低竞争项目，蓝海机会 |
| 7 | 竞争较低，有先发优势 |
| 5 | 竞争中等 |
| 3 | 竞争较高 |
| 1 | 竞争非常激烈，红海 |

### 7. 自动化（Automation）— 5 分

评估是否支持自动化漏洞扫描与测试：

| 分值 | 说明 |
|------|------|
| 5 | 明确支持自动化测试，无需事先审批 |
| 0 | 不支持或需额外审批 |

## 使用示例

### 单项目评分

假设某项目参数如下：
- 现金奖励：丰厚 → cash_bounty = 10 分
- 赏金等级：4 级 → bounty_level = 8 分
- 范围：较大 → scope = 15 分
- 活跃度：响应较快 → activity = 15 分
- 攻击面：多种技术形态 → attack_surface = 11 分
- 技术栈：中等复杂度 → tech_stack = 5 分
- 竞争：中等 → competition = 5 分
- 自动化：支持 → automation = 5 分

**总分：10 + 8 + 15 + 15 + 11 + 5 + 5 + 5 = 74 分**

### 评分解读

| 分数区间 | 建议 |
|----------|------|
| 80-100 | 优先投入，高回报项目 |
| 60-79 | 值得投入，中等回报项目 |
| 40-59 | 可选投入，低优先级 |
| 0-39 | 暂不投入，回报极低 |

### 批量评分

使用 `target_score.py --input programs.csv --output scored.csv` 可以对整个项目库进行批量评分，输出按得分降序排列的完整列表，便于筛选最优目标。
