## 二、案例：Datus-agent #1236（构造混用）

**[PR](https://github.com/Datus-ai/Datus-agent/pull/1236)** 把 self-join 实现的环比（period-over-period）指标强制复用 LAG() 窗口函数内部表示。self-join 与 LAG() 业务概念相同但计算语义不同：

| 维度 | self-join | LAG() 窗口函数 |
|------|-----------|----------------|
| 机制 | 按日期偏移谓词 join 自身表，对齐本期/上期行 | partition 内按序取上一行 |
| 无上期记录 | LEFT JOIN 产生 `NULL`（行保留） | 该行无 LAG 结果，行为不同 |
| 重复/缺失日期 | 可能产生笛卡尔配对 | 天然一行对一行 |
| 聚合前/后 join | 结果可能不同 | 与聚合时机无关 |

维护者反馈的要点：改动"没有理解在做什么"、不是 good-first-issue 范围、应真实使用项目后再参与。

**教训**：指标/语义类改动必须先写非代码语义解释（G1）；同一业务概念的两种 SQL 构造 ≠ 等价；深域核心逻辑改动须先有 issue 归属。

## 三、可复用经验（成功因素）

| 特征 | 说明 | 重要性 |
|------|------|--------|
| 改动聚焦单一问题 | 一个 PR 只解决一个问题，不混合无关更改 | 极高 |
| CI 全部通过 | 所有自动化检查通过，无阻塞 | 极高 |
| 项目规模适中 | 中小型项目更容易获得 review | 高 |
| 维护者活跃 | 近期有 commit 和 PR 合并记录 | 高 |
| 提前沟通 | 在 issue 中与维护者确认方向 | 高 |
| 使用 PR 模板 | 严格遵循项目要求的模板和格式 | 中高 |
| 披露 AI 使用 | 主动披露 AI 辅助 + 人工逐条审核 | 中高 |
| 改动动机真实 | 来自真实使用/issue，而非代码扫描 | 极高 |
