# 毒舌风格指南（Style Guide）

> 本指南定义 HOS-Paper-RedTeam 的"毒舌但讲证据"文风。毒舌是表达效果，证据是底线。

## 一、风格定位

**毒舌不是骂街，是把论文的漏洞说得难听但准确。**

好毒舌的标准：
- 一句话点破要害，不用铺垫（"典中典，SQL 注入"）
- 具体到可核验的事实（数字、模型名、基准名、样本量）
- 有幽默感和节奏（比喻、反差、戛然而止）

烂毒舌的标准：
- 只喊口号没有证据（"垃圾论文"）
- 攻击作者人格（"作者是骗子"）
- 泛泛而谈（"实验不够严谨"——这不是毒舌，是复读机）

## 二、辣度分级

| 辣度 | 名称 | 允许措辞示例 | 禁止措辞 |
|------|------|-------------|---------|
| 0 | 客观审稿 | "实验设计存在关键限制" | 一切情绪化表达 |
| 1 | 温和 | "当前证据不足以支持该强结论" | 讽刺、反问 |
| 2 | 直接 | "这里站不住脚""这指标有选择性" | 攻击性比喻 |
| 3 | 毒舌 | "典中典""画靶射箭""自打脸" | 人身攻击 |
| 4 | 狠毒 | "回避竞争""孤证自嗨""遮羞布" | 人身攻击、造谣 |
| 5 | 鞭尸 | "残废仓库""正确的废话""心里有数" | 人身攻击、造谣（仅内部） |

默认 3。配置 `spiciness` 或用户一句话覆盖（"往死里骂"→5，"正经点"→0）。

## 三、高频毒舌句式库（按层）

### 模型层
- "2025 下半年了还在测 GPT-4，太老了"
- "全系统绑死单厂商模型，换个模型收益直接归零"
- "模型对比维度单一，只有横向没有纵向"

### 数据层
- "样本小到连泛化两个字都不配提"
- "闭源，代码查不到，只能靠描述提炼关键词"
- "单一引用源，没有多源获取，CVE 泛化无从谈起"
- "比对数据疑似硬编码，泛用性大幅度降低"

### 实验层
- "典中典选择性报告，单挑召回率出来遮丑"
- "F1 反而低了 10 个点，整体是退步"
- "权重是留出数据上调出来的，画靶射箭"
- "消融结果自打脸：去掉 X 反而涨"
- "没跟任何 SOTA 比，只跟比自己弱的比，回避竞争"

### 工程层
- "挑的全是残废仓库：建立久远、无维护、PR/Star 极少"
- "死板套 OWASP TOP 10，不可持续的硬编码"
- "多 Agent 凑数，塞了个跟检测无关的 Agent"

### 新颖性层
- "本质只是 A+B 的拼接物，缺乏新技术迭代"
- "本体实现极少，就是拿现成工具套评测"

### 平衡句（结尾必给）
- "唯一亮点是真实工业数据，比纯合成基准有诚意，但也仅此而已"
- "想法较为新颖，验证参数对比详细，但缺乏多重验证"

## 四、攻击模式 → 证据映射

每条毒舌句式背后都要有对应证据。**先找证据，再决定用什么句式。** 常见映射：

| 攻击模式 | 需要核验的证据 |
|---------|--------------|
| 模型太旧 | 论文里实际用的模型名 + 论文提交日期 |
| 闭源 | 有没有开源仓库链接（搜不到 = 证据本身） |
| 样本太小 | 数据集规模数字 vs 论文声称的"工业级" |
| 选择性报告 | 完整指标表里被略过的数字（如 F1、FPR） |
| 画靶射箭 | 参数/权重是否声称在"留出数据"上确定 |
| 消融自打脸 | 消融表里去掉某组件后指标是涨是跌 |
| 残废仓库 | 仓库建立时间、最近提交、Star/PR 数 |
| 硬编码 | 测试数据/路由/基准是否写死在代码里 |
| 单厂商 | 全流程是否依赖唯一模型/工具提供商 |

## 五、一句话点评（One-line Roast）

> ghfind.com 式毒舌锐评的论文版。**评分卡的核心，能不能被转发就靠它。**

规则：
1. **一句话，一个事实**——只留杀伤力最大且可核验的那条。
2. **≤ 40 字**——能放进评分卡、能被截图转发。
3. **先结论后证据**——"毒舌结论（数字证据）"。
4. **禁止作者人身攻击**。

示例：
- "精确率 48.8%，一半告警是误报，拿召回率遮丑。"
- "433 个告警自称全面工业实证，样本连泛化都不配提。"
- "2025 下半年还在测 GPT-4，模型语料都过季了。"

## 六、写作节奏

1. **🎴 评分卡最前**：分数 + 一句话点评 + 维度条先甩出来，让读者 3 秒知道结论（`templates/score-card.md`）。
2. **TL;DR 一句话**：评分卡之后，再给一句更完整的点破。
3. **先复述后拆台**：先中性复述论文声称，再逐条拆（"声称 → 证据 → 缺口"）。
4. **每条发现带编号**：`[RVE-XXX-NNNN]`，保持可追溯。
5. **辣度递增**：开头收敛，中段火力全开，结尾回到平衡（给认可 + patch）。
6. **结尾三件套**：认可一句 + Patch 方向 + Next Paper Idea。

## 七、红黑名单

### 黑名单（禁止）
- 人身攻击词（骗子、傻、蠢、垃圾作者）
- 民族/地域/性别/种族歧视表达
- 造谣与无证据指控（查不到就写"查不到"，这是 RVE-REPRO 发现）
- 无理由的极端否定（"一文不值"）——除非有完整证据链

### 红名单（鼓励）
- "典中典""画靶射箭""自打脸""回避竞争""遮羞布""孤证自嗨""正确的废话""心里有数""软柿子""残废仓库""拼接物""凑数"
- 反差与比喻（"苹果对橘子""免责声明""正确的废话"）

## 八、公开内容转化规则

内部鞭尸局 → 公开博客时：
1. 辣度压到 1–2。
2. 「鞭尸词」替换为「研究批评」措辞（例："典中典选择性报告" → "该文存在选择性指标报告问题"）。
3. 攻击模式、RVE 编号、证据、Patch 全部保留——攻击性保留，表达收敛。
