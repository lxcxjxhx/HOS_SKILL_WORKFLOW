# 管线：知识产权保护

> patent → copyright → paper

---

## 触发条件

用户表达以下意图时激活此管线：
- "我有一个技术创新，需要全面保护"
- "先申请专利再发论文"
- "技术方案需要专利和软著保护"

## 链路

```
patent (专利申请) → copyright (软著登记) → paper (论文发表)
```

**重要原则**：先专利后论文。论文发表会破坏专利的新颖性，必须在专利申请提交后再发表论文。

## 执行步骤

### Step 1: 激活 patent 子技能（专利申请）

1. 收集技术方案：
   - 核心技术点
   - 技术问题和技术效果
   - 具体实施方式
2. 确定专利类型（发明/实用新型）
3. 生成完整专利文档：
   - 技术交底书
   - 权利要求书
   - 说明书
   - 摘要
4. 输出 IP-Context 摘要：
   ```
   - 技术方案: {描述}
   - 创新点: {列表}
   - 保护范围: {独立权利要求要点}
   ```

### Step 2: 激活 copyright 子技能（软著登记）

1. 读取 patent 中的技术方案描述
2. 分析代码仓库（如有）
3. 生成软著申请文档：
   - 软件基本信息
   - 软件说明书
   - 模块设计说明
   - 创新点总结
4. 输出 IP-Context 摘要

### Step 3: 激活 paper 子技能（论文发表）

1. 确认专利已提交（**关键检查点**）
2. 读取 patent 中的技术方案和创新点
3. 执行论文写作流程：
   - 注意：论文中不泄露专利核心权利要求内容
   - 重点阐述方法论和实验验证
   - 在 Related Work 中可引用自己的专利
4. 完成后进入 review 润色

## 质量门禁

| 节点 | 标准 |
|------|------|
| patent 完成 | 权利要求书清楚完整；说明书充分公开 |
| copyright 完成 | 文档符合版权保护中心要求 |
| **专利提交确认** | **专利申请已提交到 CNIPA**（必须人工确认） |
| paper 完成 | 不泄露专利核心内容；学术质量达标 |

## 上下文传递

```
patent → copyright:
  传递: 技术方案描述 + 创新点列表 + 技术栈信息
  格式: IP-Context 摘要

patent → paper:
  传递: 技术方案 + 创新点 + 保护范围（用于避免泄露）
  格式: IP-Context 摘要 + 专利文档

copyright → paper:
  传递: 软件功能描述（可用于论文的 System 章节）
  格式: copyright 产出文档
```

## 风险提示

1. **新颖性风险**：论文发表前必须确保专利申请已提交
2. **内容泄露风险**：论文中避免披露专利权利要求的核心技术特征
3. **时间线风险**：专利申请到授权通常需要 2-3 年（发明专利），论文可在提交申请后 6 个月发表
