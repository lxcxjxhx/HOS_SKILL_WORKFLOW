# 专利写作工作流

## 概述

本工作流定义了从技术方案到完整专利文档的标准化写作流程。适用于发明专利和实用新型专利的撰写。

---

## 工作流程总览

```
步骤 1 → 技术方案收集与分析
步骤 2 → 专利类型确认
步骤 3 → 发明交底书整理
步骤 4 → 权利要求书撰写
步骤 5 → 说明书撰写
步骤 6 → 摘要撰写
步骤 7 → 附图说明撰写
步骤 8 → 全文审查与优化
```

---

## 步骤 1：技术方案收集与分析

### 输入
- 用户提供的技术方案描述
- 相关技术背景资料

### 处理

1. **理解核心技术**
   - 识别发明创造的核心技术点
   - 明确技术方案属于产品还是方法
   - 提取关键技术特征

2. **识别技术问题**
   - 现有技术存在什么问题？
   - 本发明要解决什么技术问题？
   - 本发明带来了什么技术效果？

3. **分析技术方案**
   - 技术方案的具体组成
   - 各组成部分之间的关系
   - 关键参数和条件

4. **确定创新点**
   - 与现有技术相比，区别特征是什么？
   - 哪些特征是核心创新点？
   - 哪些特征是优选特征？

### 输出
- 技术方案分析报告
- 核心创新点清单
- 技术问题和技术效果列表

---

## 步骤 2：专利类型确认

### 输入
- 步骤 1 的分析结果

### 处理

根据技术方案特征，判断适合的专利类型：

| 特征 | 发明专利 | 实用新型专利 | 外观设计专利 |
|------|---------|------------|------------|
| 保护对象 | 产品/方法 | 产品形状/构造 | 产品外观 |
| 创新程度 | 高 | 中 | - |
| 审查周期 | 长（2-3 年） | 短（6-12 月） | 短（4-8 月） |
| 保护期限 | 20 年 | 10 年 | 15 年 |
| 费用 | 高 | 低 | 低 |

**判断规则：**
- 涉及方法/工艺 → 发明专利
- 涉及产品结构改进，创新程度一般 → 实用新型专利
- 涉及产品外观设计 → 外观设计专利
- 创新程度高，需要长期保护 → 发明专利
- 需要快速获得授权 → 实用新型专利

### 输出
- 推荐的专利类型
- 推荐理由

---

## 步骤 3：发明交底书整理

### 输入
- 步骤 1 的分析结果
- 步骤 2 的专利类型

### 处理

使用 `templates/invention-disclosure.md` 模板，整理以下内容：

1. 基本信息（发明名称、发明人、技术领域）
2. 背景技术（现有技术及其不足）
3. 发明内容（技术问题、技术方案、有益效果）
4. 具体实施方式
5. 附图说明
6. 创新点总结

### 输出
- 完整的发明交底书

---

## 步骤 4：权利要求书撰写

### 输入
- 步骤 3 的发明交底书

### 处理

使用 `templates/claims-template.md` 模板，按照以下顺序撰写：

#### 4.1 撰写独立权利要求

1. **确定主题名称**
   - 简明、准确地反映技术主题
   - 一般不超过 25 个字

2. **确定必要技术特征**
   - 从技术方案中提取实现发明目的必不可少的特征
   - 区分前序特征（与现有技术共有）和特征特征（创新点）

3. **撰写独立权利要求**
   - 前序部分：主题名称 + 必要技术特征
   - 特征部分：以"其特征在于"引导

4. **检查保护范围**
   - 是否过宽（可能缺乏新颖性/创造性）
   - 是否过窄（保护力度不够）

#### 4.2 撰写从属权利要求

1. **确定附加技术特征**
   - 从发明交底书中提取优选特征
   - 按照重要性排序

2. **撰写从属权利要求**
   - 引用在前权利要求
   - 描述附加技术特征

3. **构建层次体系**
   - 形成多层次的保护体系
   - 最重要的特征放在靠前的从属权利要求

#### 4.3 权利要求审查

- 检查清楚性：用语是否清楚、明确
- 检查支持性：是否得到说明书支持
- 检查层次性：是否形成合理的保护层次
- 检查单一性：是否满足单一性要求

### 输出
- 完整的权利要求书

---

## 步骤 5：说明书撰写

### 输入
- 步骤 3 的发明交底书
- 步骤 4 的权利要求书

### 处理

使用 `templates/description-template.md` 模板，按照以下顺序撰写：

#### 5.1 技术领域
- 一句话说明所属技术领域
- 格式：本发明涉及 [大领域]，特别涉及 [具体方向]。

#### 5.2 背景技术
- 描述最接近的现有技术
- 客观指出现有技术的问题和不足
- 不贬低现有技术

#### 5.3 发明内容
- 阐述要解决的技术问题
- 描述技术方案（与权利要求书对应）
- 说明有益效果（有数据支撑）

#### 5.4 附图说明
- 列出各附图的名称和类型
- 说明附图标记

#### 5.5 具体实施方式
- 结合附图详细描述实施方式
- 提供多个实施例
- 提供对比例和性能测试数据（如有）
- 确保充分公开，使本领域技术人员能够实现

### 输出
- 完整的说明书

---

## 步骤 6：摘要撰写

### 输入
- 步骤 4 的权利要求书
- 步骤 5 的说明书

### 处理

使用 `templates/abstract-template.md` 模板：

1. 从独立权利要求提取技术方案要点
2. 从说明书提取技术问题和有益效果
3. 组织为"问题-方案-效果"结构
4. 控制字数在 300 字以内
5. 选择摘要附图

### 输出
- 完整的摘要
- 摘要附图

---

## 步骤 7：附图说明撰写

### 输入
- 步骤 5 的说明书
- 附图文件

### 处理

使用 `templates/drawings-description.md` 模板：

1. 编写附图清单
2. 编写附图标记说明
3. 编写各附图的详细描述

### 输出
- 完整的附图说明

---

## 步骤 8：全文审查与优化

### 输入
- 所有已完成的文档

### 处理

#### 8.1 一致性检查
- 发明名称在各文档中是否一致
- 技术术语是否统一
- 附图标记是否一致
- 权利要求书中的技术特征是否在说明书中有记载

#### 8.2 格式检查
- 权利要求书格式是否符合规范
- 说明书五个部分是否完整
- 摘要字数是否在 300 字以内
- 段落编号是否连续

#### 8.3 法律检查
- 权利要求是否清楚、简明
- 权利要求是否得到说明书支持
- 说明书是否充分公开
- 是否满足新颖性、创造性、实用性要求

#### 8.4 语言优化
- 用语是否规范
- 是否存在模糊用语
- 语句是否通顺
- 逻辑是否清晰

### 输出
- 审查报告
- 修改建议
- 最终版专利文档

## 质量控制检查点

### 检查点 1：技术方案确认
- [ ] 核心技术点已识别
- [ ] 技术问题已明确
- [ ] 技术效果已确认
- [ ] 创新点已提取

### 检查点 2：权利要求书确认
- [ ] 独立权利要求保护范围合理
- [ ] 从属权利要求层次分明
- [ ] 用语清楚、准确
- [ ] 得到说明书支持

### 检查点 3：说明书确认
- [ ] 五个部分完整
- [ ] 充分公开技术方案
- [ ] 实施例足够
- [ ] 有益效果有数据支撑

### 检查点 4：摘要确认
- [ ] 字数不超过 300 字
- [ ] 包含技术问题、方案、效果
- [ ] 未使用宣传用语
- [ ] 已选择摘要附图

### 检查点 5：全文确认
- [ ] 各文档一致性
- [ ] 格式符合规范
- [ ] 法律要求满足
- [ ] 语言规范

## 常见问题处理

### 问题 1：技术方案描述不充分

**处理：**
- 向用户提出具体问题
- 引导用户补充技术细节
- 提供技术方案描述的参考示例

### 问题 2：创新点不明确

**处理：**
- 分析技术方案与现有技术的区别
- 帮助用户识别核心创新点
- 建议进行专利检索

### 问题 3：权利要求保护范围难以确定

**处理：**
- 分析技术方案的核心特征
- 评估不同保护范围的利弊
- 建议合理的保护范围

### 问题 4：实施例不足

**处理：**
- 分析权利要求的范围
- 确定需要补充的实施例
- 提供实施例撰写的参考示例

## 时间估算

| 步骤 | 预计时间 |
|------|---------|
| 步骤 1：技术方案收集与分析 | 30-60 分钟 |
| 步骤 2：专利类型确认 | 10-15 分钟 |
| 步骤 3：发明交底书整理 | 30-60 分钟 |
| 步骤 4：权利要求书撰写 | 60-120 分钟 |
| 步骤 5：说明书撰写 | 120-240 分钟 |
| 步骤 6：摘要撰写 | 15-30 分钟 |
| 步骤 7：附图说明撰写 | 30-60 分钟 |
| 步骤 8：全文审查与优化 | 30-60 分钟 |
| **总计** | **约 5-10 小时** |

注：以上时间为参考值，实际时间取决于技术方案的复杂程度。
