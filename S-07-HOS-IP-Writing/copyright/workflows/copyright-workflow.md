# 软著申请工作流

## 工作流概述

本工作流描述了从 GitHub 代码仓库到完成软件著作权登记的完整流程，包括代码分析、文档生成、材料准备和申请提交等步骤。

## 详细步骤说明

### 阶段一：准备阶段

#### 步骤 1.1：需求确认

**目标**：明确软著申请的具体需求和目标

**操作内容**：
1. 确认申请主体
   - 个人申请 / 企业申请
   - 著作权人信息

2. 确认软件信息
   - 软件名称（全称、简称）
   - 版本号
   - 开发完成日期
   - 首次发表日期

3. 确认申请类型
   - 原创申请
   - 修改版申请
   - 升级版申请

**输出物**：
- 需求确认清单
- 申请基本信息表

**检查点**：
- [ ] 申请主体明确
- [ ] 软件名称符合规范
- [ ] 日期逻辑正确
- [ ] 版本号格式正确

---

#### 步骤 1.2：信息收集

**目标**：收集软著申请所需的全部信息

**操作内容**：
1. 收集 GitHub 仓库信息
   - 仓库 URL
   - 仓库访问权限
   - 代码结构

2. 收集软件基本信息
   - 软件用途
   - 技术领域
   - 运行环境
   - 开发环境

3. 收集著作权人信息
   - 身份证明
   - 联系方式
   - 地址信息

**输出物**：
- 信息收集清单
- 待确认事项列表

**检查点**：
- [ ] 仓库信息完整
- [ ] 软件信息完整
- [ ] 著作权人信息完整

---

#### 步骤 1.3：环境准备

**目标**：准备文档生成所需的环境和工具

**操作内容**：
1. 准备代码分析工具
   - 代码统计工具（cloc、wc 等）
   - 代码结构分析工具

2. 准备文档生成环境
   - Markdown 编辑器
   - 文档模板

3. 准备截图工具
   - 截图软件
   - 图片编辑工具

**输出物**：
- 环境准备清单
- 工具使用说明

**检查点**：
- [ ] 代码分析工具可用
- [ ] 文档生成环境就绪
- [ ] 截图工具准备完成

---

### 阶段二：分析阶段

#### 步骤 2.1：仓库分析

**目标**：深入分析 GitHub 仓库的结构和内容

**操作内容**：
1. 分析仓库结构
   - 目录结构
   - 文件组织
   - 模块划分

2. 分析 README 文档
   - 项目介绍
   - 功能说明
   - 安装使用

3. 分析依赖文件
   - package.json / requirements.txt / pom.xml
   - 技术栈识别
   - 版本信息

**输出物**：
- 仓库结构分析报告
- 技术栈清单
- 模块划分说明

**检查点**：
- [ ] 仓库结构分析完成
- [ ] 技术栈识别准确
- [ ] 模块划分清晰

---

#### 步骤 2.2：代码提取

**目标**：提取用于软著申请的代码材料

**操作内容**：
1. 统计代码行数
   - 总代码行数
   - 各语言代码行数
   - 有效代码行数

2. 提取代码内容
   - 前 1500 行代码
   - 后 1500 行代码
   - 代码格式化

3. 代码质量检查
   - 代码完整性
   - 代码连续性
   - 去除敏感信息

**输出物**：
- 代码统计报告
- 代码文档（前后各 30 页）
- 代码质量检查报告

**检查点**：
- [ ] 代码统计准确
- [ ] 代码提取完整
- [ ] 代码格式符合要求
- [ ] 无敏感信息泄露

---

#### 步骤 2.3：技术识别

**目标**：识别软件的核心技术和创新点

**操作内容**：
1. 识别核心功能
   - 主要功能模块
   - 关键业务流程
   - 核心算法

2. 识别技术特点
   - 技术架构
   - 技术栈
   - 技术优势

3. 识别创新点
   - 算法创新
   - 架构创新
   - 应用创新

**输出物**：
- 核心功能清单
- 技术特点说明
- 创新点总结

**检查点**：
- [ ] 核心功能识别完整
- [ ] 技术特点总结准确
- [ ] 创新点提炼到位

---

### 阶段三：生成阶段

#### 步骤 3.1：文档生成

**目标**：生成软著申请所需的全部文档

**操作内容**：
1. 生成软件基本信息表
   - 使用 software-info.md 模板
   - 填写软件基本信息
   - 填写著作权人信息

2. 生成软件说明书
   - 使用 software-description.md 模板
   - 生成引言和概述
   - 生成运行环境说明
   - 生成功能说明
   - 生成使用说明

3. 生成辅助文档
   - 模块设计说明（module-design.md）
   - 功能说明（function-description.md）
   - 关键算法描述（algorithm-description.md）
   - 数据库设计说明（database-design.md）
   - 流程图描述（flowchart-description.md）
   - 创新点总结（innovation-points.md）

**输出物**：
- 软件基本信息表
- 软件说明书
- 各辅助文档

**检查点**：
- [ ] 所有文档生成完成
- [ ] 文档内容完整
- [ ] 文档格式规范
- [ ] 信息一致性检查通过

---

#### 步骤 3.2：代码整理

**目标**：整理代码文档，使其符合软著申请要求

**操作内容**：
1. 代码格式化
   - 按 50 行/页排版
   - 设置页边距
   - 设置字体字号

2. 代码分页
   - 前 30 页提取
   - 后 30 页提取
   - 页码标注

3. 代码封面
   - 添加软件名称
   - 添加版本号
   - 添加著作权人信息

**输出物**：
- 代码文档（PDF/Word 格式）
- 代码统计报告

**检查点**：
- [ ] 代码格式符合要求
- [ ] 每页不少于 50 行
- [ ] 前后各 30 页完整
- [ ] 封面信息正确

---

#### 步骤 3.3：截图准备

**目标**：准备软件界面截图

**操作内容**：
1. 确定截图清单
   - 登录界面
   - 主界面
   - 核心功能界面
   - 辅助功能界面

2. 执行截图
   - 按截图指南操作
   - 保证截图质量
   - 规范命名

3. 截图整理
   - 图片格式转换
   - 图片尺寸调整
   - 添加标注说明

**输出物**：
- 截图文件集
- 截图清单
- 截图说明文档

**检查点**：
- [ ] 截图数量符合要求
- [ ] 截图质量清晰
- [ ] 截图命名规范
- [ ] 包含软件标识

## 时间规划

### 总体时间安排

| 阶段 | 预计时间 | 关键节点 |
|------|---------|---------|
| 阶段一：准备阶段 | 1 天 | 需求确认完成 |
| 阶段二：分析阶段 | 1-2 天 | 代码分析完成 |
| 阶段三：生成阶段 | 2-3 天 | 文档生成完成 |
| 阶段四：审核阶段 | 1 天 | 审核通过 |
| 阶段五：提交阶段 | 0.5-1 天 | 材料提交完成 |
| **总计** | **5.5-7.5 天** | - |

### 详细时间计划

**第 1 天：准备阶段**
- 上午：需求确认、信息收集
- 下午：环境准备、工具安装

**第 2-3 天：分析阶段**
- 第 2 天：仓库分析、代码提取
- 第 3 天：技术识别、创新点提炼

**第 4-6 天：生成阶段**
- 第 4 天：文档生成
- 第 5 天：代码整理、截图准备
- 第 6 天：补充完善

**第 7 天：审核阶段**
- 上午：内容审核
- 下午：格式检查、材料整合

**第 8 天：提交阶段**
- 上午：填写申请、提交材料
- 下午：进度跟踪设置

## 风险控制

### 常见风险及应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 仓库访问受限 | 无法分析代码 | 提前申请访问权限 |
| 代码量不足 | 无法满足页数要求 | 调整代码提取策略 |
| 文档内容不完整 | 审核不通过 | 补充完善文档内容 |
| 格式不符合要求 | 需要重新提交 | 严格按照要求排版 |
| 信息不一致 | 审核不通过 | 统一核对所有信息 |
