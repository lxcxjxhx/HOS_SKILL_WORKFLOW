# 代码仓库分析工作流

## 工作流概述

本工作流用于分析 GitHub 代码仓库，提取软件的技术特征、功能模块、核心算法等信息，为软著文档生成提供基础数据。

## 详细步骤说明

### 步骤 1：仓库获取

#### 1.1 获取仓库信息

**目标**：获取 GitHub 仓库的基本信息和访问权限

**操作内容**：
1. 获取仓库 URL
   - 格式：https://github.com/username/repo
   - 验证 URL 有效性
   - 检查访问权限

2. 获取仓库元数据
   - 仓库名称
   - 仓库描述
   - 主要编程语言
   - 开源协议
   - Star/Fork 数量

3. 获取 README 内容
   - 项目介绍
   - 功能说明
   - 安装使用指南
   - 技术栈说明

**输出物**：
- 仓库基本信息表
- README 内容文档

**检查点**：
- [ ] 仓库 URL 有效
- [ ] 有访问权限
- [ ] README 内容完整

---

#### 1.2 克隆/下载仓库

**目标**：获取仓库的完整代码

**操作内容**：
1. 克隆仓库（如权限允许）
   ```bash
   git clone [repository_url]
   ```

2. 或下载 ZIP 包
   - 访问仓库页面
   - 下载 ZIP 文件
   - 解压到本地

3. 验证代码完整性
   - 检查文件数量
   - 检查目录结构
   - 确认代码完整

**输出物**：
- 本地代码仓库
- 代码完整性报告

**检查点**：
- [ ] 代码下载完整
- [ ] 目录结构正确
- [ ] 文件数量正常

---

### 步骤 2：结构分析

#### 2.1 目录结构分析

**目标**：分析代码仓库的目录结构

**操作内容**：
1. 生成目录树
   ```bash
   tree -L 3 -I 'node_modules|dist|build|.git' > tree.txt
   ```

2. 识别主要目录
   - 源代码目录（src/、lib/、app/）
   - 测试目录（test/、tests/）
   - 配置目录（config/）
   - 文档目录（docs/）
   - 资源目录（assets/、public/）

3. 分析目录组织
   - 按功能划分
   - 按层次划分
   - 按模块划分

**输出物**：
- 目录树文档
- 目录结构分析报告

**检查点**：
- [ ] 目录树生成完整
- [ ] 主要目录识别准确
- [ ] 组织结构分析清晰

---

#### 2.2 文件类型分析

**目标**：分析仓库中的文件类型和分布

**操作内容**：
1. 统计文件类型
   ```bash
   # 统计各类型文件数量
   find . -type f | sed 's/.*\.//' | sort | uniq -c | sort -rn
   ```

2. 识别主要文件类型
   - 源代码文件（.js、.py、.java、.ts 等）
   - 配置文件（.json、.yaml、.xml、.ini 等）
   - 文档文件（.md、.txt、.doc 等）
   - 资源文件（.png、.jpg、.css 等）

3. 分析文件分布
   - 各目录文件分布
   - 主要文件类型占比
   - 关键文件识别

**输出物**：
- 文件类型统计表
- 文件分布分析报告

**检查点**：
- [ ] 文件类型统计准确
- [ ] 主要文件类型识别正确
- [ ] 关键文件标记完成

---

#### 2.3 依赖分析

**目标**：分析项目的依赖关系

**操作内容**：
1. 识别依赖管理文件
   - Node.js：package.json
   - Python：requirements.txt、Pipfile、pyproject.toml
   - Java：pom.xml、build.gradle
   - PHP：composer.json
   - Ruby：Gemfile
   - Go：go.mod

2. 提取依赖信息
   - 依赖包名称
   - 依赖版本号
   - 依赖类型（生产/开发）

3. 分析技术栈
   - 前端框架（React、Vue、Angular 等）
   - 后端框架（Express、Django、Spring 等）
   - 数据库（MySQL、PostgreSQL、MongoDB 等）
   - 其他工具库

**输出物**：
- 依赖清单
- 技术栈分析报告

**检查点**：
- [ ] 依赖文件识别正确
- [ ] 依赖信息提取完整
- [ ] 技术栈分析准确

---

### 步骤 3：技术识别

#### 3.1 编程语言识别

**目标**：识别项目使用的编程语言

**操作内容**：
1. 统计代码行数
   ```bash
   # 使用 cloc 工具
   cloc . --exclude-dir=node_modules,dist,build,.git
   
   # 或使用 tokei
   tokei .
   ```

2. 识别主要语言
   - 主要编程语言
   - 各语言代码行数
   - 各语言占比

3. 识别语言版本
   - 从配置文件识别（如 .nvmrc、.python-version）
   - 从依赖文件识别
   - 从代码特征识别

**输出物**：
- 编程语言统计表
- 语言版本清单

**检查点**：
- [ ] 代码行数统计准确
- [ ] 主要语言识别正确
- [ ] 语言版本确认

## 注意事项

### 分析注意事项

1. **权限问题**
   - 确保有仓库访问权限
   - 私有仓库需要授权
   - 遵守开源协议

2. **数据准确性**
   - 多次验证统计数据
   - 交叉核对分析结果
   - 人工复核关键信息

3. **信息安全**
   - 不泄露敏感信息
   - 不提交密钥密码
   - 保护个人隐私

### 常见问题

1. **仓库过大**
   - 问题：分析时间过长
   - 解决：选择性分析核心目录

2. **代码混淆**
   - 问题：难以理解代码逻辑
   - 解决：结合文档和注释分析

3. **依赖复杂**
   - 问题：依赖关系复杂
   - 解决：使用专业工具分析
