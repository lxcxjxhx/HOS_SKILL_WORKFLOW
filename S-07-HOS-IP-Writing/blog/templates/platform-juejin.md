# 掘金格式指南

> 掘金使用 Markdown 编辑器，支持标准 Markdown 语法和部分扩展语法。掘金对内容质量要求较高，审核较严格。

---

## 一、文章结构规范

### 1.1 标题层级
- **H1**（`#`）：文章标题，每篇仅一个
- **H2**（`##`）：主要章节（建议 3-8 个）
- **H3**（`###`）：子章节
- 避免过深的标题层级（最多到 H4）

### 1.2 文章长度建议
- 技术文章：2000-6000 字
- 掘金偏好**深度原创**内容
- 避免水文和纯搬运

---

## 二、代码块

### 2.1 标准代码块
````markdown
```javascript
const greeting = 'Hello, Juejin!';
console.log(greeting);
```
````

### 2.2 支持的语言
与 CSDN 类似，支持主流编程语言。常用：
`javascript`, `typescript`, `python`, `java`, `go`, `rust`, `sql`, `bash`, `json`, `yaml`, `css`, `html`

### 2.3 代码规范
- 代码块必须标注语言
- 保持代码简洁，突出关键部分
- 长代码配合文字说明分段讲解

---

## 三、图片

### 3.1 插入方式
```markdown
![图片描述](图片URL)
```

### 3.2 重要限制
- ⚠️ **仅支持上传到掘金图床**
- ⚠️ **不支持外部图片链接**（会被过滤或显示失败）
- 使用掘金编辑器自带的图片上传功能
- 或使用掘金 API 上传图片获取链接

### 3.3 最佳实践
- 图片宽度建议 800-1200px
- 使用有意义的文件名
- 截图类推荐 PNG，照片类推荐 JPG

---

## 四、标签系统

### 4.1 分类标签
- 发布时选择 **1 个**主分类标签
- 分类标签为掘金预设体系

### 4.2 常用分类
- `前端`、`后端`、`Android`、`iOS`、`人工智能`、`开发工具`、`代码人生`、`阅读`

### 4.3 标签建议
- 选择最匹配的分类
- 分类选择准确有助于推荐算法

---

## 五、专栏管理

### 5.1 创建专栏
- 在掘金个人中心创建专栏
- 设置专栏名称、描述、图标
- 发布文章时选择加入专栏

### 5.2 专栏建议
- 同一主题的文章归入同一专栏
- 专栏名称简洁明了
- 专栏描述说明内容方向

## 六、特殊语法

### 6.1 高亮标记
```markdown
==高亮文本==
```

### 6.2 下划线
```markdown
<u>下划线文本</u>
```

### 6.3 表格
```markdown
| 列1 | 列2 | 列3 |
|:----|:---:|----:|
| 左对齐 | 居中 | 右对齐 |
| 数据 | 数据 | 数据 |
```

### 6.4 折叠内容
```markdown
<details>
<summary>点击展开</summary>

折叠内容在这里

</details>
```

## 七、内容规范

### 7.1 掘金审核要点
- ✅ 原创内容优先
- ✅ 有深度的技术分析
- ✅ 配有代码示例
- ✅ 结构清晰，排版整洁
- ❌ 避免营销推广内容
- ❌ 避免纯搬运（翻译需注明出处）
- ❌ 避免标题党

### 7.2 推荐算法友好
- 发布后 1 小时内的互动数据很关键
- 分享到相关技术群获取初始互动
- 标题和封面图影响点击率

---

## 八、发布检查清单

- [ ] 标题准确描述内容，不标题党
- [ ] 文章为原创或有注明出处
- [ ] 代码块标注了语言
- [ ] 图片已上传到掘金图床（非外部链接）
- [ ] 选择了正确的分类标签
- [ ] 文章已加入专栏（如适用）
- [ ] 无营销或引流内容
- [ ] 排版整洁，段落分明
- [ ] 封面图已设置（提升点击率）
