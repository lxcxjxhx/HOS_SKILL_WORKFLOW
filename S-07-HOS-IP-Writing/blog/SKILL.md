# 多平台技术博客写作系统

> 一篇内容，多平台适配。支持 CSDN、掘金、知乎、Medium、Dev.to 的格式自动转换与 SEO 优化。

---

## 触发条件

| 触发场景 | 示例表达 |
|---------|---------|
| 写博客 | "写一篇博客"、"写一篇技术文章" |
| 写教程 | "写一篇教程"、"写一篇案例" |
| 平台适配 | "写一篇 CSDN 文章"、"发布到掘金" |
| 多平台分发 | "把这篇文章适配到多个平台" |
| SEO 优化 | "优化这篇文章的 SEO" |
| 系列文章 | "规划一个系列教程" |

**不触发**：学术论文（→ `paper`），书籍写作（→ `book`）。

---

## 执行流程

### Phase 1: 选题定位

**操作步骤**：
1. 确认目标平台（单平台/多平台）
2. 确认文章类型：博客 / 教程 / 案例研究
3. 确认目标读者和技术水平
4. 确认核心主题和 1-3 个关键论点

**质量门禁**：目标平台确定；文章类型明确；核心论点 1-3 个。

### Phase 2: 大纲生成

**操作步骤**：
1. 根据文章类型选择结构：
   - **博客**：引言（问题引入）→ 正文（方案讲解）→ 总结（收获与建议）
   - **教程**：前置条件 → 步骤 1..N → 常见问题 → 扩展阅读
   - **案例研究**：背景 → 方案选型 → 实施过程 → 效果对比 → 经验总结
2. 生成候选标题（3-5 个，包含核心关键词）
3. 等待用户确认或调整

**质量门禁**：结构清晰（引言/正文/总结）；标题包含关键词。

### Phase 3: 正文撰写

**操作步骤**：
1. 按大纲逐节生成内容
2. 插入代码示例（确保可运行）
3. 添加 Mermaid/ASCII 图表
4. 确保技术准确性

**质量门禁**：代码示例可运行；图文配合；字数符合平台要求。

### Phase 4: 发布准备

**操作步骤**：
1. 根据目标平台转换格式
2. 生成文章元数据（标题、摘要、标签）
3. 执行 SEO 检查（关键词密度、标题层级、meta description）
4. 输出最终文件

**质量门禁**：平台格式适配完成；SEO 检查通过；标签/分类已设置。

## 平台特性速查

| 平台 | 编辑器 | 代码高亮 | 公式 | 标签限制 | 特殊注意 |
|------|--------|---------|------|---------|---------|
| CSDN | Markdown | ` ```lang ` | LaTeX `$...$` | <= 5 个 | 避免过多外部链接 |
| 掘金 | Markdown | ` ```lang ` | 支持 | 1 个分类 | 质量审核严，避免营销 |
| 知乎 | 富文本 | 支持 | LaTeX | 3-5 个话题 | 偏好深度内容 |
| Medium | 专有编辑器 | 有限（用 Gist） | 不支持 | <= 5 个 | 面向英文读者 |
| Dev.to | Markdown | ` ```lang ` | 不支持 | <= 4 个 | 支持 Liquid 标签和 series |

## 输出规范

遵循 `shared/output-conventions.md` 中的 blog 部分：
- 输出目录：`blog/output/`
- 文件命名：`{date}-{slug}.md`
- 文件头（front matter）：

```yaml
---
title: "{标题}"
date: {YYYY-MM-DD}
tags: [{标签1}, {标签2}]
platform: {目标平台}
---
```

多平台适配时：`{date}-{slug}-{platform}.md`

---

## 约束

1. **技术准确性**：所有代码示例必须可运行
2. **平台规则**：严格遵守各平台内容规范
3. **原创性**：生成内容应为原创，避免抄袭
4. **图片版权**：建议使用原创图片或开源图片
5. **SEO 适度**：不影响可读性，避免关键词堆砌
