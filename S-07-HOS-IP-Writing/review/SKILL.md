# 文本润色与去 AI 味系统

> 去除 AI 写作痕迹，让文本更自然、更专业。支持学术论文、技术博客、商业文档等多种语境。

---

## 触发条件

| 触发场景 | 示例表达 |
|---------|---------|
| 基础润色 | "润色一下"、"帮我润色"、"polish" |
| 去 AI 味 | "去 AI 味"、"去除 AI 痕迹"、"deslop" |
| 学术润色 | "学术润色"、"论文润色" |
| 表达优化 | "改写得更自然"、"优化表达" |
| 引用规范 | "规范引用格式" |

**不触发**：从零写作（→ `paper` / `blog` / `book`），本技能专注于**已有文本的润色**。

---

## 核心能力

### 去 AI 写作模式

| 问题类型 | 示例 | 处理方式 |
|---------|------|---------|
| 填充短语 | "值得注意的是"、"需要指出的是"、"众所周知" | 直接删除 |
| 公式化结构 | "首先...其次...最后..." | 打破机械结构，自然过渡 |
| AI 偏好表达 | "从本质上来说"、"从根本上说" | 改写为具体描述 |
| 被动语态 | "It is proposed that..." | 转为主动："We propose..." |
| 模糊量词 | "很多"、"一些"、"相关" | 替换为具体数据或明确描述 |

### 语境匹配策略

| 语境 | 策略 |
|------|------|
| 学术论文 | 保持严谨性，去除口语化，规范引用格式 |
| 技术博客 | 保持专业性，增加可读性，适度口语化 |
| 商业文档 | 保持简洁性，行动导向，避免学术化 |
| 创意写作 | 保持个性，增强表现力 |

### 学术写作优化（HOS 扩展）

- 口语化 → 学术用语（"用" → "采用"，"做" → "实施"）
- 引用格式规范（APA / MLA / Chicago / GB/T 7714）
- 段落结构改进（主题句 → 支撑句 → 结论句）
- 论证逻辑强化

## 执行流程

### Phase 1: 文本分析

**操作步骤**：
1. 识别文本类型（学术/技术/商业/创意）
2. 扫描并标记 AI 写作模式
3. 评估当前质量

**质量门禁**：文本类型识别正确。

### Phase 2: 问题诊断

**操作步骤**：
1. 标记填充短语
2. 识别公式化结构
3. 检测被动语态
4. 找出模糊表达

**质量门禁**：AI 填充词标记完成；被动语态标记完成。

### Phase 3: 润色执行

**操作步骤**：
1. 去除 AI 套路
2. 转换主动语态
3. 具体化表达
4. 优化句式节奏（混合长短句，避免单调）

**质量门禁**：所有标记问题已处理；无新增 AI 套路。

### Phase 4: 质量验证

**操作步骤**：
1. 检查连贯性
2. 验证专业性
3. 确认自然度
4. 确认原意保留

**质量门禁**：润色后文本通过自然度检查；原意保留。

---

## 输出格式

每次润色输出包含三部分：
1. **润色后文本**：完整输出
2. **修改说明**：逐条列出修改内容及理由
3. **质量评分**：1-10 分，含评分依据

---

## 约束

1. **保留原意**：润色不改变原文核心观点
2. **适度改写**：避免过度润色导致失去作者风格
3. **语境一致**：保持全文语体风格统一
4. **渐进改进**：优先处理最明显的 AI 痕迹

---

## 上下文接口

**读取**：直接操作文本输入（不依赖共享上下文）

**写入**（供下游技能使用）：
- `review.polished`：润色后的文本

## 生态集成

| 集成模块 | 触发条件 | 集成方式 |
|---------|---------|---------|
| `paper` | 论文初稿完成后 | 接收 paper.draft 进行学术润色 |
| `blog` | 博文完成后 | 接收 blog.articles 进行润色 |
| `book` | 全书完成后 | 接收 book.chapters 统一润色 |
| HOS-Silly-Mock | 润色包含代码的文本时 | 检测代码是否为 Mock/伪代码 |
