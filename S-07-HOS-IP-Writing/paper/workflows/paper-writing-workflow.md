# 📝 论文写作完整工作流

> 从项目启动到投稿准备的全流程指南。每个阶段都有明确的输入、产出和检查点。

---

## 🎯 工作流概览

```
Stage 1: Brainstorm（头脑风暴）
    ↓
Stage 2: Architecture（架构设计）
    ↓
Stage 3: Draft（初稿撰写）
    ↓
Stage 4: Integration（整合审查）
    ↓
Stage 5: Compression（压缩精炼）
    ↓
投稿准备
```

**预计总时长**：4-12 周（取决于论文类型和作者经验）

---

## 📋 阶段详解

### Stage 1: Brainstorm（头脑风暴）

**目标**：明确研究问题、贡献点、目标读者

**时长**：3-7 天

**输入**：
- 研究主题与核心问题
- 实验数据/结果（如有）
- 目标投稿类型

**产出**：
- 研究问题陈述（1-2 句话）
- 核心贡献列表（3-5 点）
- 目标读者画像
- 初步 Related Work 方向
- 项目初始化文档（使用 `templates/paper-project-init.md`）

**操作步骤**：

#### 步骤 1.1：明确研究问题

```
引导问题：
1. 你要解决什么问题？（用一句话描述）
2. 为什么这个问题重要？
3. 现有的解决方案有什么不足？
4. 你的方法与现有方法有什么不同？
5. 读者读完论文后应该记住什么？

输出：
- 研究问题陈述（1-2 句话）
- 研究背景概述（3-5 句话）
```

#### 步骤 1.2：梳理核心贡献

```
引导问题：
1. 你的方法/系统有什么创新点？
2. 每个创新点解决了什么问题？
3. 每个贡献可以量化吗？（例如：提升了 X%）
4. 最重要的 3-5 个贡献是什么？

输出：
- 核心贡献列表（3-5 点，每点包含：贡献描述 + 解决的问题 + 量化结果）
```

#### 步骤 1.3：定义目标读者

```
引导问题：
1. 你的目标读者是谁？（例如：NLP 研究者、系统架构师）
2. 读者需要了解哪些前置知识？
3. 读者读完后能做什么？

输出：
- 目标读者画像（包含：读者身份、前置知识、读后收获）
```

#### 步骤 1.4：初步文献调研

```
操作：
1. 列出 3-5 个 Related Work 方向
2. 每个方向找 2-3 篇代表性文献
3. 简要说明每篇文献与本文的关系

输出：
- Related Work 方向列表
- 初步参考文献列表（10-15 篇）
```

#### 步骤 1.5：确认投稿类型

```
引导问题：
1. 你想投哪个会议/期刊？
2. 截止日期是什么时候？
3. 篇幅限制是多少？
4. 有什么特殊要求？

输出：
- 投稿目标确认
- 加载对应的投稿类型配置（见 SKILL.md 中的投稿类型适配表）
```

#### 步骤 1.6：创建项目初始化文档

```
操作：
1. 复制 templates/paper-project-init.md
2. 填写所有字段
3. 保存到项目目录

输出：
- paper-project-init.md（已填写）
```

**检查点**：
- [ ] 研究问题陈述清晰
- [ ] 核心贡献列表具体、可量化
- [ ] 目标读者画像明确
- [ ] 投稿类型已确认
- [ ] 项目初始化文档已完成

**下一步**：进入 Stage 2: Architecture

---

### Stage 2: Architecture（架构设计）

**目标**：设计论文整体结构与各章节逻辑链

**时长**：3-5 天

**输入**：Stage 1 产出（项目初始化文档）

**产出**：
- 论文大纲（使用 `templates/paper-outline.md`）
- 章节间逻辑链
- 图表规划
- 篇幅分配

**操作步骤**：

#### 步骤 2.1：设计章节结构

```
操作：
1. 复制 templates/paper-outline.md
2. 根据投稿类型调整章节结构
3. 为每个章节写出 2-3 句要点摘要

输出：
- 章节标题列表
- 每个章节的要点摘要
```

#### 步骤 2.2：设计逻辑链

```
检查：
1. Introduction 的 gap → Methods 的方案
2. Methods 的方案 → Results 的验证
3. Results 的结果 → Discussion 的解读
4. Introduction 的问题 → Conclusion 的回答

输出：
- 每个章节的过渡句
- 章节间逻辑关系图（可选）
```

#### 步骤 2.3：规划图表

```
引导问题：
1. 每张图/表要传达什么信息？
2. 图表在哪个章节被引用？
3. 图表的类型是什么？（架构图、流程图、对比图、表格等）

输出：
- 图表清单（编号、类型、标题、内容说明、位置）
```

#### 步骤 2.4：分配篇幅

```
操作：
1. 根据投稿类型确定总篇幅
2. 按目标占比分配各章节篇幅（见大纲模板）
3. 检查篇幅分配是否合理

输出：
- 各章节目标篇幅
- 篇幅分配表
```

#### 步骤 2.5：制定时间计划

```
操作：
1. 根据截止日期倒推
2. 为每个阶段分配时间
3. 设置里程碑

输出：
- 项目时间线（见项目初始化文档）
```

**检查点**：
- [ ] 章节结构完整
- [ ] 逻辑链清晰
- [ ] 图表规划合理
- [ ] 篇幅分配符合要求
- [ ] 时间计划可行

**下一步**：进入 Stage 3: Draft

---

### Stage 3: Draft（初稿撰写）

**目标**：完成各章节初稿

**时长**：2-6 周

**输入**：Stage 2 产出（论文大纲）

**产出**：
- 各章节初稿文本
- 图表占位符与说明
- 参考文献列表（初版）

**操作步骤**：

#### 步骤 3.1：撰写 Methods

```
操作：
1. 参考 templates/paper-section-templates.md 中的 Methods 模板
2. 描述整体架构（Figure 1）
3. 定义问题与符号
4. 详细描述每个组件
5. 提供算法流程（如适用）
6. 描述训练目标（如适用）

检查：
- [ ] 有足够的细节支持复现
- [ ] 所有符号都有定义
- [ ] 每个组件说明了设计理由
```

#### 步骤 3.2：撰写 Results

```
操作：
1. 描述实验设置（数据集、基线、指标、实现细节）
2. 展示主要结果
3. 展示消融实验
4. 参数敏感性分析（如适用）
5. 案例分析（如适用）

检查：
- [ ] 所有声明都有数据支撑
- [ ] 包含置信区间或标准差
- [ ] 没有解读 "为什么"（留给 Discussion）
```

#### 步骤 3.3：撰写 Discussion

```
操作：
1. 解读实验结果
2. 与 Related Work 对比
3. 分析局限性
4. 讨论威胁有效性（如适用）

检查：
- [ ] 解释了 "为什么" 方法有效
- [ ] 诚实讨论了局限性
- [ ] 提出了未来改进方向
```

#### 步骤 3.4：撰写 Introduction

```
操作：
1. 介绍研究背景与重要性
2. 定义研究问题
3. 分析现有方法的不足
4. 列出本文贡献
5. 简述论文结构（可选）

检查：
- [ ] 第一段吸引读者兴趣
- [ ] 贡献列表具体、可量化
- [ ] 没有过度承诺
```

#### 步骤 3.5：撰写 Related Work

```
操作：
1. 按主题分类组织
2. 每个分类描述 2-3 篇代表性文献
3. 每个分类有小结，指出与本文的关系
4. 结尾段总结本文定位

检查：
- [ ] 按主题分类（非按时间）
- [ ] 每个分类有小结
- [ ] 没有贬低相关工作
```

#### 步骤 3.6：撰写 Conclusion

```
操作：
1. 总结工作和贡献
2. 总结主要发现
3. 提出未来工作方向

检查：
- [ ] 呼应了 Introduction
- [ ] 没有引入新信息
- [ ] 没有过度夸大
```

#### 步骤 3.7：撰写 Abstract

```
操作：
1. 背景（1 句）
2. 问题（1 句）
3. 方法（1-2 句）
4. 结果（1-2 句，包含具体数字）
5. 意义（1 句）

检查：
- [ ] 包含五要素
- [ ] 结果包含量化数据
- [ ] 没有引用、公式、图表引用
```

#### 步骤 3.8：整理参考文献

```
操作：
1. 检查所有引用都有对应条目
2. 检查格式统一
3. 检查文献质量（覆盖主要工作、包含最新文献）

检查：
- [ ] 没有虚构的参考文献
- [ ] 格式符合投稿要求
```

**检查点**：
- [ ] 所有章节初稿完成
- [ ] 图表占位符已放置
- [ ] 参考文献列表完整
- [ ] 总篇幅在目标范围内

**下一步**：进入 Stage 4: Integration

---

### Stage 4: Integration（整合审查）

**目标**：确保论文整体连贯、逻辑自洽

**时长**：3-7 天

**输入**：Stage 3 产出（各章节初稿）

**产出**：
- 整合审查报告
- 修改建议列表
- 修订后的稿件

**操作步骤**：

#### 步骤 4.1：通读全文

```
操作：
1. 从头到尾通读全文
2. 记录发现的问题
3. 标注需要修改的段落

检查：
- [ ] Abstract 是否准确概括全文？
- [ ] Introduction 的 promise 是否被 Conclusion 兑现？
- [ ] 各章节过渡是否自然？
- [ ] 图表是否在正文中被引用和解读？
```

#### 步骤 4.2：检查术语一致性

```
操作：
1. 列出所有专业术语
2. 检查同一概念是否使用同一名称
3. 检查缩写是否一致

输出：
- 术语列表
- 需要统一的术语
```

#### 步骤 4.3：检查数学符号一致性

```
操作：
1. 列出所有数学符号
2. 检查同一概念是否使用同一符号
3. 检查符号是否在首次出现时定义

输出：
- 符号列表
- 需要统一的符号
```

#### 步骤 4.4：运行质量检查清单

```
操作：
1. 使用 templates/paper-quality-checklist.md
2. 逐项检查
3. 记录未通过的项目

输出：
- 质量检查报告
- 需要修改的项目列表
```

#### 步骤 4.5：修改稿件

```
操作：
1. 根据审查报告修改稿件
2. 优先处理 "未通过" 项目
3. 然后处理 "需要改进" 项目

检查：
- [ ] 所有 "未通过" 项目已修复
- [ ] 大部分 "需要改进" 项目已处理
```

**检查点**：
- [ ] 质量检查清单通过（总体评分 ≥ 4.0）
- [ ] 术语一致性已确认
- [ ] 符号一致性已确认
- [ ] 逻辑连贯性已确认

**下一步**：进入 Stage 5: Compression

---

### Stage 5: Compression（压缩精炼）

**目标**：在不丢失关键信息的前提下精炼表达

**时长**：3-7 天

**输入**：Stage 4 产出（修订后的稿件）

**产出**：
- 精炼后的终稿
- 篇幅对比报告
- 最终质量检查通过确认

**操作步骤**：

#### 步骤 5.1：逐段精炼

```
操作：
1. 逐段检查
2. 删除不增加信息量的文字
3. 合并重复表达
4. 将被动语态改为主动语态
5. 删除冗余副词（very, quite, rather, basically）

检查：
- [ ] 每句话都有信息量
- [ ] 没有重复表达
- [ ] 使用主动语态
```

#### 步骤 5.2：句子精炼

```
操作：
1. 检查句子长度（目标：每句 ≤ 25 词）
2. 长句拆短句
3. 删除冗余词汇

检查：
- [ ] 句子简洁明了
- [ ] 没有过长的句子
```

#### 步骤 5.3：检查篇幅

```
操作：
1. 统计总篇幅
2. 与投稿要求对比
3. 如超出，继续压缩

输出：
- 篇幅对比报告（当前篇幅 vs 目标篇幅）
```

#### 步骤 5.4：最终质量检查

```
操作：
1. 再次运行 templates/paper-quality-checklist.md
2. 确保所有项目通过

输出：
- 最终质量检查报告
```

**检查点**：
- [ ] 篇幅符合要求
- [ ] 质量检查清单通过
- [ ] 语言表达精炼
- [ ] 终稿完成

**下一步**：投稿准备

## 📤 投稿准备

**时长**：1-3 天

**操作步骤**：

#### 步骤 1：格式转换

```
操作：
1. 将 Markdown 转换为 LaTeX/Word
2. 使用投稿模板
3. 调整格式（页边距、字体、行距等）

检查：
- [ ] 格式符合投稿要求
- [ ] 图表清晰度足够
```

#### 步骤 2：最终检查

```
操作：
1. 通读最终版本
2. 检查所有细节（标题、作者、单位、页码等）
3. 生成 PDF

检查：
- [ ] PDF 可正常打开
- [ ] 文件大小符合要求
- [ ] 所有信息正确
```

#### 步骤 3：准备补充材料

```
操作：
1. 准备代码/数据（如承诺开源）
2. 准备补充材料（如需要）
3. 准备作者贡献声明、利益冲突声明等

检查：
- [ ] 所有补充材料已准备
```

#### 步骤 4：提交

```
操作：
1. 注册/登录投稿系统
2. 填写投稿信息
3. 上传论文和补充材料
4. 确认提交

检查：
- [ ] 提交成功
- [ ] 收到确认邮件
```

## ⚠️ 常见问题与解决方案

### 问题 1：写作过程中卡住

**解决方案**：
1. 回到大纲，检查逻辑链是否清晰
2. 先写最容易的部分（通常是 Methods 或 Results）
3. 不要追求完美，先完成再完善

### 问题 2：篇幅超出限制

**解决方案**：
1. 压缩 Related Work（保留最相关的）
2. 将细节移到补充材料
3. 精炼语言表达（见 Stage 5）

### 问题 3：实验结果不理想

**解决方案**：
1. 诚实报告结果
2. 在 Discussion 中分析原因
3. 将其转化为 "insight" 而非 "failure"

### 问题 4：时间不够

**解决方案**：
1. 优先保证核心章节（Methods, Results）
2. 简化非核心章节（Related Work, Discussion）
3. 考虑投稿到要求较低的会议/期刊
