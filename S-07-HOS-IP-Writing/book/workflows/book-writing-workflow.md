# 书籍写作工作流（Book Writing Workflow）

> 完整的书籍写作流程指南，从需求分析到最终出版。

---

## 一、工作流总览

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  需求分析   │───▶│  书籍提案   │───▶│  目录生成   │───▶│  用户确认   │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
                                                                  │
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌───────▼─────┐
│  出版准备   │◀───│  审校优化   │◀───│  前言附录   │◀───│  章节撰写   │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
```

---

## 二、阶段详解

### 阶段 1：需求分析（1-2 天）

**输入**：用户的写作意图

**任务清单**：
- [ ] 确认书籍类型（技术书 / 教程 / 博客合集 / 系列教程）
- [ ] 确认目标读者（初学者 / 中级 / 高级）
- [ ] 确认核心主题和技术栈
- [ ] 确认预计篇幅（章节数、字数）
- [ ] 确认出版方式（传统出版 / 自出版 / 待定）
- [ ] 确认交稿时间要求
- [ ] 调研同类书籍（至少 5 本），找出差异化定位

**输出**：需求分析文档

**决策点**：
- 如果主题范围过大 → 建议缩小范围或拆分为多本
- 如果同类书籍过多 → 重新定位差异化角度
- 如果用户目标不明确 → 提供书籍类型对比表帮助决策

---

### 阶段 2：书籍提案（2-3 天）

**输入**：需求分析文档

**任务清单**：
- [ ] 加载模板 `templates/book-proposal.md`
- [ ] 撰写书籍简介（200-300 字）
- [ ] 明确目标读者画像
- [ ] 撰写作者介绍
- [ ] 完成市场分析（同类书籍对比）
- [ ] 生成初步目录大纲（Part 级别）
- [ ] 预估全书篇幅和交稿计划

**输出**：书籍提案文档

**决策点**：
- 用户确认提案 → 进入阶段 3
- 用户要求修改 → 根据反馈调整后重新确认

---

### 阶段 3：目录生成（2-3 天）

**输入**：确认后的书籍提案

**任务清单**：
- [ ] 加载模板 `templates/toc-template.md`
- [ ] 生成完整目录结构（Part → Chapter → Section）
- [ ] 为每章标注：学习目标、主要内容、预计篇幅
- [ ] 生成章节依赖关系图（Mermaid）
- [ ] 标注每章所需代码示例数量
- [ ] 标注每章所需插图数量
- [ ] 计算全书总篇幅预估

**输出**：完整目录文档 + 章节依赖图

**决策点**：
- 用户确认目录 → 进入阶段 4
- 用户要求调整章节顺序 / 增删章节 → 修改后重新确认

---

### 阶段 4：章节撰写（核心阶段）

**输入**：确认后的目录

**执行方式**：逐章撰写，每章遵循以下子流程

#### 4.1 章节准备
- [ ] 加载模板 `templates/chapter-template.md`
- [ ] 创建章节文件
- [ ] 确认本章前置依赖章节已完成
- [ ] 收集本章所需素材（代码、图表、案例）

#### 4.2 内容撰写
- [ ] 撰写章节引言（问题引入 + 学习目标）
- [ ] 撰写理论讲解部分
- [ ] 编写代码示例（加载 `templates/code-example-template.md`）
- [ ] 编写实战案例
- [ ] 整理常见问题（FAQ）
- [ ] 撰写本章小结
- [ ] 生成练习题（加载 `templates/exercise-template.md`）
- [ ] 撰写下一章预告

#### 4.3 章节审校
- [ ] 技术准确性检查
- [ ] 代码示例运行验证
- [ ] 交叉引用检查（确认引用的章节编号正确）
- [ ] 术语一致性检查
- [ ] 语言风格统一检查

**输出**：完整章节文档

**决策点**：
- 本章审校通过 → 进入下一章
- 发现问题 → 修正后重新审校

---

### 阶段 5：代码示例与插图（与阶段 4 并行）

**输入**：各章节的代码需求和插图需求

**任务清单**：
- [ ] 整理所有代码示例到统一目录
- [ ] 验证所有代码示例可运行
- [ ] 生成插图描述文档（加载 `templates/illustration-guide.md`）
- [ ] 为每个插图提供 Mermaid / Draw.io 代码
- [ ] 确认插图位置与正文对应

**输出**：代码仓库 + 插图描述文档

---

### 阶段 6：前言与附录（1-2 天）

**输入**：完成的全部章节内容

**任务清单**：
- [ ] 加载模板 `templates/preface-template.md`
- [ ] 撰写前言（写作背景、目标读者、如何使用本书）
- [ ] 撰写作者简介
- [ ] 加载模板 `templates/appendix-template.md`
- [ ] 生成参考文献列表
- [ ] 生成术语表
- [ ] 生成工具清单（如适用）
- [ ] 生成索引

**输出**：前言文档 + 附录文档

---

### 阶段 7：审校优化（3-5 天）

**输入**：完整的书籍初稿

**任务清单**：
- [ ] 全书技术准确性审查
- [ ] 全书代码示例验证
- [ ] 语言风格统一审查
- [ ] 交叉引用完整性检查
- [ ] 术语一致性检查
- [ ] 目录与正文对应关系检查
- [ ] 插图与正文对应关系检查
- [ ] 生成审校报告

**输出**：审校报告 + 修订后的书稿

**决策点**：
- 审校通过 → 进入阶段 8
- 存在重大问题 → 返回相关章节修改

---

### 阶段 8：出版准备（1-3 天）

**输入**：审校通过的书稿

**任务清单**：
- [ ] 加载工作流 `workflows/publishing-workflow.md`
- [ ] 确定出版方式（传统出版 / 自出版）
- [ ] 如传统出版：生成书籍提案，联系出版社
- [ ] 如自出版：选择平台（GitBook / Leanpub / 其他）
- [ ] 格式转换（Markdown → PDF / ePub / HTML）
- [ ] 生成最终版本
- [ ] 建立读者反馈渠道

**输出**：可出版的完整书籍

## 四、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 主题范围过大 | 写作周期过长 | 拆分为多本或缩小范围 |
| 技术更新快 | 内容过时 | 聚焦稳定技术，预留更新机制 |
| 代码示例不可运行 | 影响读者信任 | 每个示例必须测试验证 |
| 写作动力不足 | 进度拖延 | 设定每日写作目标，定期回顾 |
| 同类书籍竞争 | 市场饱和 | 强化差异化定位 |
