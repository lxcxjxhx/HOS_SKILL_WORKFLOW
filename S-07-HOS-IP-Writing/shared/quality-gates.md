# 质量门禁标准

> 每个子技能的每个执行阶段必须通过对应的质量门禁，才能进入下一阶段。

---

## 通用门禁（适用所有子技能）

| 检查项 | 标准 | 验证方式 |
|--------|------|---------|
| 触发条件匹配 | 用户意图明确匹配至少一个触发场景 | AI 自判 |
| 输入完整性 | 所有必需输入字段已提供 | 逐项检查 |
| 输出完整性 | 所有必需输出部分已生成 | 结构检查 |
| 格式合规 | 输出符合目标格式规范 | 规则比对 |
| 无虚构内容 | 不包含虚构的数据、引用、代码 | AI 自判 |

---

## 子技能特定门禁

### paper（论文写作）

| 阶段 | 门禁标准 |
|------|---------|
| Stage 1 Brainstorm | 研究问题可用一句话表述；贡献点 3-5 个；目标投稿类型已确定 |
| Stage 2 Architecture | 大纲覆盖 IMRAD 所有章节；逻辑链完整（gap → method → result → interpretation） |
| Stage 3 Draft | 每章节初稿完成；引用列表非空；Methods 可复现 |
| Stage 4 Integration | 术语一致性 100%；图表全部在正文中引用；Abstract 准确概括全文 |
| Stage 5 Compression | 篇幅在目标范围 ±10%；每句 ≤ 25 词（英文）；无冗余副词 |

### patent（专利写作）

| 阶段 | 门禁标准 |
|------|---------|
| Phase 1 技术方案收集 | 技术问题、技术方案、技术效果三要素完整 |
| Phase 2 权利要求书 | 独立权利要求包含所有必要技术特征；从属权利要求层次分明 |
| Phase 3 说明书 | 五部分（领域/背景/内容/附图/实施方式）完整；充分公开 |
| Phase 4 摘要 | 摘要 ≤ 300 字；包含技术问题+方案+效果 |

### copyright（软著写作）

| 阶段 | 门禁标准 |
|------|---------|
| Phase 1 信息收集 | 技术栈识别完成；核心模块列表非空（≥ 3 个） |
| Phase 2 文档生成 | 软件说明书包含所有必需章节（引言/概述/环境/使用说明） |
| Phase 3 输出调整 | 文档符合版权保护中心格式要求；软件名称规范 |

### book（书籍写作）

| 阶段 | 门禁标准 |
|------|---------|
| Phase 1 需求分析 | 书籍类型确定；目标读者明确；核心主题列表完成 |
| Phase 2 目录生成 | 目录覆盖所有核心主题；章节间有逻辑递进关系 |
| Phase 3 章节撰写 | 每章包含理论+代码示例+练习题；代码可运行 |
| Phase 4 审校优化 | 全书术语一致；交叉引用正确；风格统一 |

### blog（博客写作）

| 阶段 | 门禁标准 |
|------|---------|
| Phase 1 选题定位 | 目标平台确定；文章类型明确；核心论点 1-3 个 |
| Phase 2 大纲生成 | 结构清晰（引言/正文/总结）；标题包含关键词 |
| Phase 3 正文撰写 | 代码示例可运行；图文配合；字数符合平台要求 |
| Phase 4 发布准备 | 平台格式适配完成；SEO 检查通过；标签/分类已设置 |

### review（文本润色）

| 阶段 | 门禁标准 |
|------|---------|
| Phase 1 文本分析 | 文本类型识别正确（学术/技术/商业/创意） |
| Phase 2 问题诊断 | AI 填充词标记完成；被动语态标记完成 |
| Phase 3 润色执行 | 所有标记问题已处理；无新增 AI 套路 |
| Phase 4 质量验证 | 润色后文本通过自然度检查；原意保留 |
