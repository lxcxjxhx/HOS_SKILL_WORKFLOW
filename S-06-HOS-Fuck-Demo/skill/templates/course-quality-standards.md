# Course Quality Standards — 课程质量标准体系

> **核心问题**：当前内容包 + PPT 的页面密度不足以支撑"一门可学的课程"。
> **目标**：定义"什么是够好的课程内容"，确保每页有实质内容、每个数据有来源、每集有学习价值。

---

## 1. 课程质量层次模型

```
观众感知质量
  │
  ├─ 表层（第一印象） ← 字体、配色、排版
  │   └─ ppt-visual-spec.md 覆盖
  │
  ├─ 结构层（叙事组织） ← 目录、过渡、节奏
  │   └─ 本文件 + ppt-6page.md 覆盖
  │
  ├─ 内容层（信息密度） ← 每页字数、数据深度、案例真实
  │   └─ ← 本文件定义 ← 这是当前最短板
  │
  └─ 价值层（学习效果） ← 学完能做什么、记忆留存率
      └─ ← 本文件定义
```

## 2. 内容页密度标准

### 2.1 每页最低内容量

**当前问题**：一页只有 2~3 行标题 + 正文，观众 10 秒读完，页面却停留 100+ 秒。

| 页面类型 | 建议字数下限 | 信息密度标准 | 举例 |
|---------|------------|------------|------|
| **标题页** | 15~30 字 | 主标题+副标题 | "AI模型的后门攻击 | 一种你从未想过的安全威胁" |
| **问题/数据页** | **80~150 字** | 核心数据+解释+来源 | 见下方示例 |
| **误区页** | 100~200 字 | 3组误区→真相+分析 | 每组不少于 25 字解释 |
| **核心观点页** | **120~250 字** | 观点+原理+例证+小结 | 见下方示例 |
| **行动步骤页** | 100~200 字 | 步骤+操作说明+预期效果 | 每步不少于 30 字 |
| **总结页** | 80~150 字 | 3个takeaway+金句+CTA | 每点不少于 20 字 |

### 2.2 信息密度检查清单

```
每页必检:
  □ 标题有信息量（不笼统），如"AI安全威胁"→"模型后门攻击：当你的AI被植入暗门"
  □ 正文有具体数据/案例（非空泛陈述）
  □ 每个数据有来源机构/报告名
  □ 页面不只有文字——有视觉锚点（图表/图标/对比框）
  □ 文字量足够填充该页对应的视频时长（~60秒 = 读约150字）

不合格页面的典型特征:
  ❌ 标题笼统："数据安全现状" → 应改为："90%的AI模型存在安全隐患"
  ❌ 正文空洞："AI安全很重要" → 应改为具体事实+数据+案例
  ❌ 无引用："研究表明..." → 应改为"Gartner 2024年报告显示..."
  ❌ 字数太少：一页只有30字，视频停留60秒 → 观众会关掉
```

## 3. 数据引用真实化标准

### 3.1 引用层级

| 层级 | 描述 | 示例 | 可信度 |
|------|------|------|--------|
| L1 | 具体机构+报告名+时间 | "Gartner 2024年企业AI采用报告显示..." | 高 |
| L2 | 知名机构+领域 | "据麦肯锡全球研究院2024年研究..." | 中高 |
| L3 | 行业共识 | "行业普遍认为..." | 中 |
| L4 | 模糊引用 | "研究表明..." / "据统计..." | **低，避免** |

**规则**：课程内容中的数据和引用**必须 ≥ L2**，禁止 L4 模糊引用。

### 3.2 AI 安全领域可引用的权威来源

```
研究机构:
  • Gartner — AI安全市场预测、企业AI采用率
  • 麦肯锡全球研究院 — AI对就业和经济的影响
  • Stanford HAI — AI指数年度报告
  • MIT Technology Review — AI安全前沿研究
  • OWASP — LLM Top 10 安全风险（权威）
  • NIST — AI风险管理框架
  • 中国信通院 — 人工智能安全白皮书

安全事件（可实名提及）:
  • 2023.03 ChatGPT 数据泄露 — Redis 开源库漏洞，部分用户对话标题暴露
  • 2023.11 微软 Copilot 提示注入 — 研究人员发现 prompt injection 漏洞
  • 2024.01 Midjourney 测试版泄露 — 绕过审核机制生成不当内容
  • 2024.02 某大模型训练数据泄露 — 包含用户隐私信息
```

### 3.3 引用格式化规则

```markdown
✅ 正确: "根据 Gartner 2025 年预测，到 2026 年全球 AI 安全市场规模将突破 500 亿美元。"
        └─ 机构 + 时间 + 预测对象 + 数据

❌ 错误: "据统计，AI安全市场规模巨大，远超之前预期。"
        └─ 无机构、无时间、无具体数据

✅ 正确: "2023年3月，ChatGPT 因 Redis 开源库的漏洞，导致约 1.2% 的用户的对话标题被意外泄露。"
        └─ 事件 + 时间 + 平台 + 根因 + 影响范围

❌ 错误: "某知名AI平台就发生过一起严重的数据泄露事件。"
        └─ 模糊化 → 反而让人怀疑真实性
```

## 4. 页面内容结构与"扎实感"设计

### 4.1 每一页的"四段结构"

让页面内容扎实的核心方法：**每页=标题+展开+例证+小结**

```
┌─────────────────────────────────────┐
│ 标题: 一句话精准概括                  │  ← 有信息量，不是笼统标题
│                                     │
│ 展开: 2~3 句解释                     │  ← 有逻辑链（原因→结果）
│  "这是因为...导致..., 具体而言..."    │
│                                     │
│ 例证: 1~2 个数据/案例                 │  ← 有具体来源
│  "2023年一项针对2000家企业的调查显示"  │
│                                     │
│ 小结: 1 句归纳                       │  ← 可带走的核心
│  "所以，关键不在于是否使用AI，           │
│   而在于是否意识到了风险。"             │
└─────────────────────────────────────┘
```

### 4.2 示例：从 "空洞" 到 "扎实" 的改造

```markdown
❌ 空洞版（当前类似）:
  # AI安全的重要性
  AI安全在当今数字化时代变得越来越重要。随着人工智能技术的快速发展，
  相关的安全威胁也在不断增加。我们需要重视AI安全。

  → 观众读完: "所以呢？这谁不知道。"

✅ 扎实版:
  # 90%的AI模型存在安全隐患：你的模型可能正在裸奔
  
  2024年，HiddenLayer 对超过1000家企业的AI部署进行扫描后发现，
  超过90%的模型存在至少一种可被利用的安全漏洞。
  
  其中最常见的是模型劫持（Model Theft）和对抗性攻击（Adversarial Attack）。
  前者导致企业的AI能力被盗用，后者让模型在特定输入下产生错误输出。
  
  更关键的是，67%的企业没有建立AI安全事件的应急响应机制。
  这意味着一旦攻击发生，企业平均需要 200+ 天才能发现并响应。
  
  → 关键是：不是AI安不安全，而是你有没有能力发现"已经被攻破"。
```

### 4.3 一集课程的最小信息单元

单集 10 分钟课程，至少包含：

```
□ 1 个具体案例（真实事件，有年月和平台名）
□ 3~5 个数据点（每个有来源）
□ 2~3 个可操作建议（具体到用户明天能做什么）
□ 1 个金句（≤20字，可传播）
□ 1 个思考题（结尾留给观众）
```

## 5. 150 集课程的质量保证体系

### 5.1 课程结构规划

对于 150 集的大规模课程，不能逐集手工打磨，而需要**内容矩阵**：

```
课程: AI安全（150集）
│
├─ 模块1: 认知篇（30集）— 为什么AI安全重要
│   ├─ 1.1 AI安全全景（5集）
│   ├─ 1.2 真实案例（10集）← 每集拆解一个安全事件
│   ├─ 1.3 威胁分类（10集）
│   └─ 1.4 行业影响（5集）
│
├─ 模块2: 技术篇（50集）— 攻击与防御
│   ├─ 2.1 对抗性攻击（15集）
│   ├─ 2.2 数据投毒（10集）
│   ├─ 2.3 模型后门（10集）
│   ├─ 2.4 提示注入（10集）
│   └─ 2.5 防御体系（5集）
│
├─ 模块3: 实践篇（40集）— 工具与流程
│   ├─ 3.1 安全评估工具（15集）
│   ├─ 3.2 安全开发生命周期（15集）
│   └─ 3.3 应急响应（10集）
│
└─ 模块4: 治理篇（30集）— 法规与合规
    ├─ 4.1 全球法规（10集）
    ├─ 4.2 行业标准（10集）
    └─ 4.3 企业治理（10集）
```

### 5.2 每集内容模板

```yaml
episode_template:
  id: "XXX-{seq:03d}"
  title: "<有信息量的标题>"
  hook: "<30s 开场吸引>"
  data_points:
    - "<数据1>（来源）"
    - "<数据2>（来源）"
    - "<数据3>（来源）"
  case_study: "<真实案例，含时间/平台/影响>"
  key_learnings:
    - "<可带走的知识点1>"
    - "<可带走的知识点2>"
    - "<可带走的知识点3>"
  actionable_tips:
    - "<明天就能做的行动1>"
    - "<明天就能做的行动2>"
  golden_sentence: "<金句≤20字>"
  thinking_question: "<留给观众的思考题>"
  references:
    - "<来源1>"
    - "<来源2>"
```

### 5.3 批量质量门禁

批量生成时，每集自动验证：

```python
def validate_episode(episode):
    checks = []
    # 内容密度
    checks.append(("数据点≥3", len(episode.get("data_points", [])) >= 3))
    checks.append(("案例真实", "202" in episode.get("case_study", "")))  # 有年份
    checks.append(("可操作建议≥2", len(episode.get("actionable_tips", [])) >= 2))
    checks.append(("金句≤20字", len(episode.get("golden_sentence", "")) <= 20))
    # 引用质量
    for ref in episode.get("references", []):
        checks.append(("引用≥L2", _is_l2_or_above(ref)))
    return checks
```

### 5.4 模板化 vs 个性化的平衡

对于 150 集体量：

```
80% 模板化 (结构一致):
  └─ 标题格式、内容结构、数据密度、引用规范
  └─ 交给流水线批量生成

20% 个性化 (每集差异):
  └─ 案例选择、数据组合、话术风格、思考题角度
  └─ 在 STEP2 观点生成阶段控制差异
```

## 6. 评委/MVP 吸引力设计

### 6.1 评委评审维度

```
评委看什么:
  ┌─────────────────────────────────────┐
  │ 1. 视觉专业度（30%）                  │
  │    ← 字体、配色、排版、图表           │
  │                                       │
  │ 2. 内容扎实度（30%）                  │
  │    ← 数据来源、案例真实、引用规范       │
  │                                       │
  │ 3. 教学效果（20%）                    │
  │    ← 听完能记住什么、能做什么          │
  │                                       │
  │ 4. 制作完整度（20%）                   │
  │    ← 视频、字幕、PPT、配套材料完整       │
  └─────────────────────────────────────┘
```

### 6.2 MVP Demo 的"评委瞬间"

在 10 分钟 demo 中，安排以下"评委记忆点"：

```
时间线:
  0:00~0:30  开场钩子: 一个让人倒吸一口凉气的真实事件
              → 评委第一印象: 这内容有料

  2:00~4:00  数据展示: 3个有来源的冲击性数据 + 可视化图表
              → 评委印象: 不是空洞说教

  4:00~6:00  原理揭示: 解释"为什么"，不是"是什么"
              → 评委印象: 有深度，不是表面文章

  6:00~8:00  案例拆解: 完整的真实事件分析
              → 评委印象: 有研究，有根据

  8:00~10:00 行动指南 + 金句收尾
              → 评委印象: 可落地，有收获
```

### 6.3 MVP 演示视频的检查清单

```
提交前的自我检查:
  □ 视觉: 字体统一、配色专业、无宋体
  □ 内容: 每页有具体数据/案例，无空泛陈述
  □ 引用: 每个数据有机构+时间，无"据统计"
  □ 音频: 无机械失真、自然语速、合适的voice
  □ 视频: 有进度提示、非纯静态帧、简洁转场
  □ 完整: 有目录页、有过渡页、有总结页
  □ 配套: PPT 可导出、字幕已生成、有课程大纲
```

## 7. PDF 输出策略

### 7.1 决策树

```
需要PDF?
│
├─ 课程资料/讲义/学员手册
│   └─ ✅ PPT原生 → PDF（pptx → LibreOffice CLI）
│      → 字体嵌入、矢量保留、备注可导出
│
├─ 讲师手册（含备注）
│   └─ ✅ PPT原生 → PDF（Notes Pages布局）
│      → soffice --headless --convert-to pdf --outdir ./output/ file.pptx
│
├─ 在线手册/交互式文档
│   └─ ✅ HTML → PDF（puppeteer/pdfkit）
│
└─ 快速预览/分享链接
    └─ ✅ HTML 在线浏览（不转PDF）
```

### 7.2 推荐实现

```javascript
// 方案A: PPT→PDF（课程材料首选）
// 1. 生成 pptx
pptx.writeFile({ fileName: "course.pptx" });
// 2. LibreOffice 转 PDF（需安装 LibreOffice）
// 命令行: soffice --headless --convert-to pdf --outdir output/ course.pptx
// 优点: 字体嵌入、矢量保留、文件小、打印级质量

// 方案B: HTML→PDF（仅在线手册时使用）
// 使用 puppeteer 或 playwright
const browser = await puppeteer.launch();
const page = await browser.newPage();
await page.goto('file:///presentation.html');
await page.pdf({ path: 'output.pdf', format: 'A4' });
```
