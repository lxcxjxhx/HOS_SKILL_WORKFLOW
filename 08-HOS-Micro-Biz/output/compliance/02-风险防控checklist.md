# 风险防控 Checklist

> **模块**: compliance
> **文档编号**: CMP-0002
> **版本**: 1.0.0 | **最后更新**: 2026-07-26
> **适用阶段**: 冷启动 / 稳定期 / 扩张期

---

## 文档说明

本 Checklist 基于 SKILL.md 风险防控核心条款扩展,覆盖微商技术服务订单从接单到售后的全生命周期风险点。所有检查项均可勾选,建议每单执行一次完整扫描,关键节点(接单前、交付前)强制执行。

**使用方式**: 复制本 Checklist 至订单工作区,逐项核对并标注 `[x]` 已完成 / `[!]` 存在风险 / `[ ]` 未执行。任何 `[!]` 项必须在解决后方可推进下一阶段。

## 一、接单前风险防控

### 1.1 客户身份与意图核验

```
[ ] 1. 确认客户真实身份(实名 / 平台账号注册时长 / 历史交易记录)
[ ] 2. 核验客户所在平台(QQ / 微信 / 闲鱼 / 其他)信誉等级
[ ] 3. 询问项目用途,判断是否属于红线服务(参见 01-红线清单)
[ ] 4. 确认客户是否为最终使用方,是否存在代发 / 转包嫌疑
[ ] 5. 对匿名咨询、新号咨询保持警惕,大额订单要求提供身份佐证
[ ] 6. 搜索客户历史评价,排查"跑单""白嫖""纠纷"标签
[ ] 7. 对学生客户群体,确认付款能力与决策权
[ ] 8. 记录客户咨询全渠道来源,便于后续追溯
```

### 1.2 需求合规性扫描

```
[ ] 1. 需求是否涉及考试作弊 / 代写论文 / 抢课刷课 → 红线,直接拒绝
[ ] 2. 需求是否涉及未授权渗透测试 / 漏洞利用 → 红线,要求授权书
[ ] 3. 需求是否涉及刷单 / 黑产 / 灰产工具 → 红线,直接拒绝
[ ] 4. 需求是否涉及破解 / 盗版 / 侵权复刻 → 红线,直接拒绝
[ ] 5. 需求是否涉及竞品数据爬取 → 灰色,评估数据来源合法性
[ ] 6. 需求是否涉及他人知识产权(开源项目 / 商业软件) → 核查许可证
[ ] 7. 需求是否涉及个人隐私数据处理 → 核查数据获取授权
[ ] 8. 需求是否存在"帮忙看一下""随便弄一下"等模糊表述 → 要求明确化
[ ] 9. 需求技术可行性评估,是否存在无法交付的技术风险
[ ] 10. 需求工期合理性评估,警惕"加急""今晚就要"陷阱
```

### 1.3 报价与定金风控

```
[ ] 1. 报价单已书面发出,包含明确的服务范围与边界
[ ] 2. 定金比例符合金额区间规则(见第六章 财务风险防控)
[ ] 3. 定金已实际到账后再启动实质性工作
[ ] 4. 报价单已注明"定金不退"条款(除我方违约外)
[ ] 5. 报价单已注明需求变更的重新报价机制
[ ] 6. 报价单已注明售后范围与期限(默认 7 天免费修改)
[ ] 7. 大额订单(>¥2000)已规划分阶段交付与分阶段付款节点
[ ] 8. 已向客户明确"口头承诺无效,以书面为准"原则
```

## 二、执行中风险防控

### 2.1 需求变更管控

```
[ ] 1. 任何需求变更必须书面确认(聊天记录明确回复"确认")
[ ] 2. 需求变更导致工作量增加的,必须重新报价并获客户确认
[ ] 3. 需求变更导致工期延长的,必须重新约定交付时间
[ ] 4. 变更记录已归档,标注变更日期、变更内容、影响评估
[ ] 5. 拒绝"顺手帮我改一下""不就是个小事吗"式口头变更
[ ] 6. 对频繁变更的客户,启动需求冻结机制(阶段性锁定)
[ ] 7. 变更超出原定服务范围的,视为新订单处理
[ ] 8. 变更涉及合规风险的,重新执行红线扫描
```

### 2.2 进度与沟通管控

```
[ ] 1. 关键节点向客户同步进度(立项 / 中期 / 验收前)
[ ] 2. 保留所有沟通记录,不在电话中做任何承诺
[ ] 3. 电话沟通后立即以文字形式复述要点并存档
[ ] 4. 客户失联超过 48 小时,发送书面催告并暂停推进
[ ] 5. 客户失联超过 7 天,按定金条款处理,保留终止权
[ ] 6. 进度滞后风险已提前告知客户,不隐瞒
[ ] 7. 技术难题导致风险升级的,及时与客户协商方案
[ ] 8. 所有阶段性交付物已留存快照与时间戳
```

### 2.3 技术合规执行

```
[ ] 1. 使用的开源组件许可证已核查(GPL / MIT / Apache 等)
[ ] 2. 未在商业项目中违规使用 GPL 传染性许可证代码
[ ] 3. 引用的第三方 API 已确认授权范围与商用许可
[ ] 4. 涉及数据库操作的,已做防注入与数据保护
[ ] 5. 涉及用户数据的,已遵循最小必要原则
[ ] 6. 代码中未硬编码任何客户敏感信息(密钥 / 密码 / Token)
[ ] 7. 交付物中未残留测试数据 / 后门 / 调试接口
[ ] 8. 技术方案文档已归档,便于售后与交接
```

## 三、交付验收风险防控

### 3.1 交付前自检

```
[ ] 1. 交付物已通过完整功能测试,非"能跑就行"
[ ] 2. 交付物已留存快照(代码版本 / 文件包 / 运行截图)
[ ] 3. 交付物已编写使用说明 / 部署文档
[ ] 4. 交付物已移除所有客户无关的测试代码与注释
[ ] 5. 交付物已确认无版权侵权素材(图片 / 字体 / 文案)
[ ] 6. 交付物已确认无敏感信息泄露
[ ] 7. 交付物已确认符合客户明确约定的验收标准
[ ] 8. 大额订单已准备阶段性交付演示
```

### 3.2 验收流程管控

```
[ ] 1. 明确验收标准(以需求确认单为准,非"客户满意")
[ ] 2. 验收期限已书面约定(默认交付后 3 天内提出异议)
[ ] 3. 验收通过后要求客户书面确认"验收合格"
[ ] 4. 验收期间客户提出的修改属于需求变更,需重新报价
[ ] 5. 客户拖延验收超过约定期限的,视为自动验收合格
[ ] 6. 验收异议必须具体化,拒绝"感觉不对""再改改"
[ ] 7. 验收通过后立即启动尾款催收流程
[ ] 8. 验收记录(截图 / 确认消息)已归档
```

### 3.3 尾款收取管控

```
[ ] 1. 验收合格后立即发出尾款催收通知
[ ] 2. 尾款催收设定明确期限(默认 3 个工作日内)
[ ] 3. 尾款未到账前,不交付源码 / 完整文件 / 部署权限
[ ] 4. 大额订单尾款可分批,但最后一笔到账前保留控制权
[ ] 5. 尾款逾期超过 7 天,启动正式催收话术
[ ] 6. 尾款逾期超过 30 天,评估是否纳入黑名单与法律途径
[ ] 7. 尾款到账后开具交付确认凭证
[ ] 8. 尾款到账前不提供任何售后承诺
```

## 四、售后阶段风险防控

### 4.1 售后范围界定

```
[ ] 1. 售后范围已书面明确(默认 7 天免费修改 Bug)
[ ] 2. 售后范围明确排除:需求变更 / 新功能 / 环境迁移 / 三方故障
[ ] 3. 售后期满后的服务按新订单或时薪计费
[ ] 4. 售后响应时效已约定(默认 24 小时内首次响应)
[ ] 5. 售后问题必须区分 Bug 修复 vs 需求变更
[ ] 6. 售后不覆盖客户自行修改导致的故障
[ ] 7. 售后不覆盖第三方服务变更导致的故障
[ ] 8. 售后记录归档,避免同一问题反复纠缠
```

### 4.2 纠纷预防与处理

```
[ ] 1. 所有售后沟通保留完整记录
[ ] 2. 售后争议先内部复盘,确认责任归属
[ ] 3. 属于我方责任的,主动补救并道歉
[ ] 4. 属于客户责任的,耐心解释并提供有偿方案
[ ] 5. 属于需求变更的,引导走新订单流程
[ ] 6. 拒绝"不给退款就差评"式威胁,保留证据维权
[ ] 7. 纠纷升级前尝试第三方调解(平台客服)
[ ] 8. 纠纷处理全过程留痕,便于平台申诉
```

### 4.3 退款风险管控

```
[ ] 1. 退款政策已在接单前明示
[ ] 2. 未启动工作的,定金可退(扣除沟通成本)
[ ] 3. 已启动工作的,按已完成工作量结算,余款可退
[ ] 4. 已交付验收的,原则上不退款,走售后流程
[ ] 5. 退款必须书面确认退款原因与金额,避免二次纠纷
[ ] 6. 退款到账后要求客户撤销所有差评 / 投诉
[ ] 7. 恶意退款客户纳入黑名单
[ ] 8. 退款决策参考 04-退款策略与纠纷处理
```

## 五、财务风险防控

### 5.1 定金与付款规则

**不同金额区间的定金比例与付款节点**:

| 订单金额区间 | 定金比例 | 付款节点 | 风控说明 |
|---|---|---|---|
| < ¥200 | 100% 预付 | 一次性付清 | 小额不赊账,降低催收成本 |
| ¥200 - ¥500 | 50% 定金 | 验收后付尾款 | 标准小额订单模式 |
| ¥500 - ¥2000 | 50% 定金 | 验收后付尾款 | 建议分阶段交付演示 |
| ¥2000 - ¥5000 | 40% 定金 | 中期 30% + 验收 30% | 强制分阶段交付 |
| ¥5000 - ¥10000 | 30% 定金 | 中期 40% + 验收 30% | 强制分阶段交付 + 书面合同 |
| > ¥10000 | 30% 定金 | 按里程碑分期 | 强制书面合同 + 分阶段验收 |

```
[ ] 1. 定金比例已按上表执行
[ ] 2. 定金到账后再启动工作(截图留存到账凭证)
[ ] 3. 大额订单(>¥2000)已规划分阶段付款节点
[ ] 4. 每阶段付款节点与交付物挂钩,不见款不交付下一阶段
[ ] 5. 尾款到账前保留交付物控制权(源码 / 部署权限)
[ ] 6. 客户要求"先做后付"的,原则上拒绝,特殊客户需评估
[ ] 7. 客户要求"分期免定金"的,拒绝
[ ] 8. 付款方式优先选择可追溯渠道(支付宝 / 微信转账 / 平台担保)
```

### 5.2 资金安全管控

```
[ ] 1. 不接受来路不明的付款(非客户本人账户)
[ ] 2. 不接受"多付一点你帮我转给XX"式代付(涉嫌洗钱)
[ ] 3. 大额收款注意税务合规,必要时申报
[ ] 4. 收款账户定期核对,避免错收漏收
[ ] 5. 退款必须原路退回,不转向第三方账户
[ ] 6. 付款凭证(截图 / 转账记录)归档保存至少 6 个月
[ ] 7. 定期盘点应收账款,逾期款项及时催收
[ ] 8. 不为客户垫付任何第三方费用(服务器 / 域名 / API)
```

### 5.3 定价风险管控

```
[ ] 1. 报价不低于成本底线(时薪 × 预估工时 + 缓冲)
[ ] 2. 不参与恶性价格战,低于成本的订单直接拒绝
[ ] 3. 报价含合理利润,预留售后成本(约 10%-15%)
[ ] 4. 加急订单加收加急费(建议 30%-50%)
[ ] 5. 复杂需求报价留足缓冲,警惕"看着简单实则复杂"
[ ] 6. 长期合作客户可适度优惠,但不低于成本线
[ ] 7. 报价单注明有效期,避免客户事后压价
[ ] 8. 不免费做"试稿""样例",已展示的作品集即能力证明
```

## 六、平台合规风险防控

### 6.1 平台规则合规

```
[ ] 1. 熟悉所在平台的交易规则与禁售清单
[ ] 2. 不在平台上发布红线服务商品(考试作弊 / 黑产等)
[ ] 3. 商品描述不夸大宣传,不承诺"包过""100%"
[ ] 4. 不引导线下交易规避平台担保(平台允许的除外)
[ ] 5. 遵守平台引流规则,不刷量不刷评
[ ] 6. 客户纠纷优先通过平台官方渠道解决
[ ] 7. 定期自查店铺违规记录,及时整改
[ ] 8. 平台规则更新及时跟进,调整经营策略
```

### 6.2 账号安全防控

```
[ ] 1. 账号密码强度足够,定期更换
[ ] 2. 开启二步验证(平台支持的话)
[ ] 3. 不在公共设备登录交易账号
[ ] 4. 不将账号借给他人使用
[ ] 5. 警惕钓鱼链接,不点击来路不明的"客户发来的链接"
[ ] 6. 多平台运营的,账号隔离,避免连带封禁风险
[ ] 7. 账号异常(异地登录 / 频繁验证)立即排查
[ ] 8. 主账号封禁预案:备用账号 / 客户迁移方案
```

### 6.3 内容合规防控

```
[ ] 1. 朋友圈 / 商品图不使用侵权素材
[ ] 2. 宣传文案不使用绝对化用语(最 / 第一 / 唯一)
[ ] 3. 不虚假宣传(虚构案例 / 盗用他人作品)
[ ] 4. 客户案例展示需获客户授权(或脱敏处理)
[ ] 5. 不发布涉及政治 / 色情 / 暴力的内容
[ ] 6. 技术文章 / 教程不包含可被滥用的攻击代码
[ ] 7. 涉及他人商标 / 品牌的内容已获授权或合理使用
[ ] 8. 定期清理历史内容,下架过期或违规内容
```

## 七、风险等级评估矩阵

**风险概率 × 影响程度 = 风险等级**

| 风险概率 \ 影响程度 | 低(小损失) | 中(中度损失) | 高(重大损失) |
|---|---|---|---|
| 高(频繁发生) | 中风险 | 高风险 | 极高风险 |
| 中(偶发) | 低风险 | 中风险 | 高风险 |
| 低(罕见) | 可接受 | 低风险 | 中风险 |

**风险等级对应行动**:

| 风险等级 | 行动策略 | 处置时限 |
|---|---|---|
| 极高风险 | 立即停止 / 拒绝接单 | 即时 |
| 高风险 | 必须制定缓释方案后方可推进 | 24 小时内 |
| 中风险 | 制定应对预案,执行中监控 | 48 小时内 |
| 低风险 | 常规执行,留意动态 | 订单周期内 |
| 可接受 | 无需特殊处置 | - |

**常见风险评估示例**:

| 风险场景 | 概率 | 影响 | 等级 | 处置建议 |
|---|---|---|---|---|
| 客户跑单(尾款不付) | 中 | 高 | 高风险 | 定金 + 阶段付款 + 控制交付物 |
| 需求蔓延(范围失控) | 高 | 中 | 高风险 | 书面确认 + 需求冻结 + 重新报价 |
| 版权纠纷(侵权索赔) | 低 | 高 | 中风险 | 许可证核查 + 素材溯源 |
| 平台封号(经营中断) | 低 | 高 | 中风险 | 合规经营 + 多平台 + 备用账号 |
| 技术交付失败(无法完成) | 中 | 高 | 高风险 | 可行性评估 + 阶段验证 + 及时止损 |
| 客户恶意退款(白嫖) | 中 | 中 | 中风险 | 证据留存 + 验收确认 + 平台申诉 |

## 八、典型风险场景应对预案

### 8.1 客户跑单(尾款不付)

```
预防:
- 定金必收到账再启动
- 大额订单分阶段付款
- 尾款到账前不交付源码 / 完整文件

处置:
1. 验收合格后立即催收尾款(书面通知)
2. 逾期 3 天:友好提醒,询问原因
3. 逾期 7 天:正式催收,提示违约后果
4. 逾期 15 天:平台申诉 / 发律师函
5. 逾期 30 天:纳入黑名单,评估诉讼成本

话术参考:
"您好,订单已于 X 月 X 日验收通过,尾款 ¥XXX 待支付。
 请在 3 个工作日内完成支付,逾期将按约定处理。
 如有特殊情况请提前沟通,我们可以协商。"
```

### 8.2 需求蔓延(范围失控)

```
预防:
- 接单前书面确认需求范围与边界
- 报价单注明"超出范围按新需求计费"
- 阶段性锁定需求,拒绝无序变更

处置:
1. 识别需求变更(超出原定范围)
2. 暂停执行,书面列出变更内容
3. 重新报价,获客户确认后推进
4. 客户拒绝加价的,按原范围交付,变更部分不执行
5. 客户纠缠的,启动需求冻结或终止合作

话术参考:
"您提到的 XX 功能不在原需求确认单范围内,属于新增需求。
 我已评估工作量,需追加 ¥XXX / X 天。
 请确认是否接受,确认后我会立即推进。
 如不需新增,我将按原计划在 X 日交付。"
```

### 8.3 版权纠纷(侵权索赔)

```
预防:
- 开源组件核查许可证(GPL 传染性 / MIT 宽松 / Apache 专利)
- 素材(图片 / 字体 / 文案)溯源,使用免费商用或已授权
- 不复刻他人商业软件界面与功能逻辑

处置:
1. 收到侵权指控,立即下架相关交付物
2. 内部核查侵权事实(是否确实使用了涉诉素材 / 代码)
3. 确认侵权的,联系权利人协商授权或赔偿
4. 非侵权的,提供权属证明,拒绝无理索赔
5. 涉及客户的,及时告知并共担责任(合同约定)

话术参考:
"收到您关于 XX 素材的侵权通知,我们已立即下架相关内容。
 正在核查素材来源,如确属侵权将立即整改并协商解决方案。
 请提供您的权属证明,便于我们核实处理。"
```

### 8.4 平台封号(经营中断)

```
预防:
- 严格遵守平台规则,不触碰红线
- 多平台布局,不依赖单一渠道
- 主账号与备用账号隔离运营
- 定期备份客户资源(合规范围内)

处置:
1. 收到封号通知,立即查看违规原因
2. 可申诉的,准备证据材料提交申诉
3. 不可申诉的,启用备用账号迁移业务
4. 通知存量客户新的联系渠道
5. 复盘封号原因,整改后重新经营

话术参考(致客户):
"因平台规则调整,原账号暂时无法使用。
 我们已启用新账号继续为您服务,联系方式:XXX。
 售后服务不受影响,有问题随时联系。"
```

### 8.5 技术交付失败(无法完成)

```
预防:
- 接单前充分评估技术可行性
- 复杂需求先做技术验证(PoC)
- 大额订单分阶段交付,早期发现问题
- 保留止损权(合同约定)

处置:
1. 发现无法按时 / 按质交付,立即告知客户
2. 提供替代方案(降级交付 / 部分交付 / 转介)
3. 协商调整交付物与价格
4. 确需终止的,按已完成工作量结算,退还余款
5. 总结教训,纳入技术评估清单

话术参考:
"在执行过程中发现 XX 技术方案存在不可控风险,
 可能影响交付质量与工期。现提供以下方案供您选择:
 A. 调整技术方案,工期延长 X 天;
 B. 降级交付核心功能,减少 XX 部分,价格调整为 ¥XXX;
 C. 终止合作,按已完成工作结算,退还余款。
 请您选择,我们将全力配合。"
```

### 8.6 客户恶意退款(白嫖)

```
预防:
- 定金制度(已启动工作不退全额定金)
- 验收确认书面化(验收合格后不退款)
- 交付物控制(尾款到账前不交源码)
- 全程证据留存

处置:
1. 拒绝无理退款要求,出示交付与验收证据
2. 引导走平台官方纠纷处理
3. 平台判定不公的,补充证据申诉
4. 必要时公开聊天记录自证(注意隐私脱敏)
5. 确认恶意的,纳入黑名单并警示同行

话术参考:
"订单已于 X 月 X 日交付并经您验收确认,符合约定要求。
 售后范围内的问题我们会持续支持。
 退款要求超出退款政策(已验收交付不支持退款),
 如有异议可通过平台官方渠道处理,我们将提供完整证据。"
```

## 九、证据留存规范

### 9.1 聊天记录留存

```
规范:
1. 所有客户沟通保留原始记录,不删除不篡改
2. 关键承诺(报价 / 需求 / 变更 / 验收)必须文字化
3. 电话沟通后立即以文字复述要点,请客户确认
4. 多平台沟通的,各平台记录均保留
5. 聊天记录导出存档(截图 + 文本),命名规则:
   [订单编号]-[平台]-[日期]-[内容摘要]

留存期限:
- 订单完成后至少保存 6 个月
- 涉及纠纷的,保存至纠纷解决后 1 年
- 大额订单(>¥2000),保存至少 2 年
```

### 9.2 转账记录留存

```
规范:
1. 每笔收款 / 退款截图留存(含金额 / 时间 / 对方账号)
2. 截图标注订单编号与款项性质(定金 / 尾款 / 中期款)
3. 平台担保交易的,保存订单详情页截图
4. 转账记录与聊天记录关联存档(同一文件夹)
5. 定期导出收款流水,与订单台账核对

命名规则:
[订单编号]-[款项类型]-[金额]-[日期].png
示例:
ORD-20260715-001-定金-500-20260715.png
```

### 9.3 交付物快照留存

```
规范:
1. 每次交付(含阶段性)留存交付物快照
2. 代码交付:Git commit hash + 压缩包
3. 文件交付:压缩包 + MD5 校验值
4. 设计交付:源文件 + 导出文件 + 预览图
5. 运行环境交付:部署文档 + 配置截图
6. 交付时附带交付清单(含文件列表与说明)

命名规则:
[订单编号]-[交付阶段]-[日期]-[版本号].zip
示例:
ORD-20260715-001-初稿-20260720-v1.0.zip

留存期限:
- 订单完成后至少保存 6 个月
- 涉及知识产权的,保存至权利期限届满
- 涉及纠纷的,保存至纠纷解决后 1 年
```

### 9.4 证据归档目录结构

```
orders/
└── [订单编号]/
    ├── 01-咨询记录/          # 客户咨询全渠道聊天记录
    ├── 02-需求文档/          # 需求确认单、报价单
    ├── 03-付款凭证/          # 定金、中期款、尾款截图
    ├── 04-执行过程/          # 进度同步、变更记录
    ├── 05-交付物/            # 各版本交付物快照
    ├── 06-验收记录/          # 验收确认、验收截图
    ├── 07-售后记录/          # 售后沟通、问题处理
    └── 08-纠纷处理/          # 纠纷沟通、平台申诉(如有)
```

## 十、Checklist 执行规范

### 10.1 执行节奏

| 阶段 | 执行章节 | 强制级别 |
|---|---|---|
| 接单前 | 一、接单前风险防控 | 强制全项 |
| 执行中 | 二、执行中风险防控 | 强制全项 |
| 交付前 | 三、交付验收风险防控 | 强制全项 |
| 售后阶段 | 四、售后阶段风险防控 | 按需执行 |
| 全周期 | 五、财务风险防控 | 强制全项 |
| 全周期 | 六、平台合规风险防控 | 定期自查(每周) |

### 10.2 异常处理

```
- 任何检查项标注 [!] 的,必须在解决后方可推进下一阶段
- 高风险及极高风险项未解决的,禁止推进订单
- 红线服务识别后,立即终止沟通并拒绝接单
- 无法判定风险等级的,升级至主理人决策
- Checklist 执行情况纳入订单复盘,持续优化
```
