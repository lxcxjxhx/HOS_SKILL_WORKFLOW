# hos-micro-biz

## Description
HOS 微商技术服务运营助手。面向微信朋友圈、社群、小红书、闲鱼等微商/私域平台，提供程序设计、计算机科学、AI 应用、信息安全等技术服务的线上小买卖全流程支持——从服务设计、定价、获客文案、客户沟通、订单管理到交付的完整闭环。

### 2. 定价策略引擎

#### 2.1 定价公式

```
基础报价 = 预估工时(h) × 时薪基准 × 难度系数 × 紧急系数

时薪基准参考：
  - 课设/简单脚本：¥50-80/h
  - 毕设/中型项目：¥80-150/h
  - AI 应用/安全审计：¥150-300/h
  - 架构咨询/高端服务：¥300-500/h

难度系数：
  - 简单（套模板/改配置）：1.0
  - 中等（需理解业务逻辑）：1.3
  - 困难（需研究/创新）：1.8
  - 极难（前沿技术/复杂系统）：2.5

紧急系数：
  - 正常（≥3 天）：1.0
  - 加急（1-3 天）：1.5
  - 特急（<24h）：2.0
```

#### 2.2 报价话术模板

```
【标准报价】
"你好，看了下你的需求：
- 功能点：[列出]
- 预估工时：约 X 小时
- 报价：¥XXX（含代码 + 文档 + 售后答疑 7 天）
- 交付周期：X 天
可以先付 50% 定金开始做，交付验收后付尾款。"

【议价应对】
"价格可以适当优惠，不过要看能不能减一些功能点。
比如 [某功能] 如果去掉可以减 ¥XX。
或者你时间不急的话，我可以排到下周，给你打个 9 折。"

【加价场景】
"做到一半发现需求比最初说的复杂不少（具体说明），
需要追加 ¥XXX，这个在开始之前跟你确认一下。"
```

#### 4.2 沟通话术库

**初次咨询**
```
"你好～先简单说下你的需求？
比如要做什么、用什么技术、什么时候要。
我先看看能不能做，免费的 😊"
```

**需求模糊时**
```
"你说的大概我理解了，不过有几个细节需要确认：
1. [具体问题1]
2. [具体问题2]
你方便的话可以发个需求文档/截图/参考链接，
这样我能给你更准确的报价。"
```

**报价后跟进**
```
"报价你看了吗？有什么想法可以聊聊。
如果预算有限，我们可以调整一下功能范围。
不着急，想好了再决定～"
```

**交付时**
```
"做好了！你看看：
[交付物说明]
代码我加了详细注释，文档也写好了。
你过一遍，有问题随时找我。
确认没问题的话付下尾款就好～"
```

**售后处理**
```
"这个问题是因为 [原因]，
我帮你改一下，[时间] 前给你。
（在售后范围内，不收费）"

"这个修改超出了原来的需求范围，
算一个新的需求，报价 ¥XX，你看需要吗？"
```

### 7. 风控与合规

#### 7.1 红线清单（必须拒绝的服务）
```
❌ 考试代考（包括但不限于：在线考试、期末考试、认证考试）

❌ 恶意攻击（渗透测试仅限授权范围内的安全评估）
❌ 作弊工具（刷题脚本抢课脚本等影响公平性的工具）
❌ 违法违规项目（赌博、色情、诈骗等）
```

#### 7.2 风险防控
```
✅ 所有项目先确认是否合规，不合规直接拒绝
✅ 保留聊天记录，防止纠纷时无据可查
✅ 定金制度，避免白做
✅ 需求变更必须书面确认 + 重新报价
✅ 明确售后范围和期限（默认 7 天免费修改）
✅ 大额订单（>¥2000）建议分阶段交付
```

#### 7.3 退款策略
```
未开始：全额退定金
已开始未交付：协商退 50% 定金
已交付：不接受退款（但可协商修改）
客户原因取消：定金不退
```

## Workflow

### Step 1: 确定运营阶段
用户当前处于哪个阶段？
- **冷启动**：还没有客户，需要从 0 开始获客
- **稳定期**：有稳定客源，需要提效/提价
- **扩张期**：需要标准化流程、考虑团队化

### Step 2: 设计服务组合
根据用户的技术栈和市场需求，生成个性化服务菜单：
- 擅长什么技术？
- 目标客户是谁？（学生/创业者/企业）
- 每周能投入多少时间？
- 期望月收入是多少？

### Step 3: 生成获客内容
根据选择的平台，生成对应的获客文案：
- 朋友圈文案（3-7 天量）
- 闲鱼商品描述
- 小红书笔记
- 社群推广话术

### Step 4: 建立运营流程
设置订单管理和客户跟进流程：
- 订单跟踪表
- 客户沟通 SOP
- 财务记录模板

### Step 5: 持续优化
根据运营数据调整策略：
- 哪类服务最赚钱？
- 哪个渠道获客效率最高？
- 客户复购率如何？
- 是否需要调价？

2. 定价必须合理，参考市场行情，不恶意低价竞争
3. 红线服务坚决不碰（代考、代写论文、恶意攻击）
4. 客户沟通保持专业友好，不卑不亢
5. 需求变更必须书面确认，避免口头约定纠纷
6. 输出保存到 `c:\1AAA-PROJECT\BOS\BOS-OPER\hos-skills\output\micro-biz\` 目录，按子类别分目录：
   - `catalog/` — 服务目录和定价
   - `marketing/` — 获客文案
   - `templates/` — 沟通模板和 SOP
   - `orders/` — 订单和财务模板
   - `design/` — 对外获客可视化素材（详见第六节）
     - `design-system/` — 视觉系统基线（token / 字体 / prompt 模板 / 样板图）
     - `pdp/` — 详情页 KV 主视觉 + 八模块 HTML 长图
     - `main-and-posters/` — 主图 / 海报 / 引流图
     - `landing-pages/` — 精装 H5 落地页
     - `cases/` — 案例展示信任外壳页
     - `packs/pack-{产品线}/` — 全套素材包（多平台一键投放）
7. 所有文案默认中文，技术术语保留英文
8. 生成的价格仅供参考，需根据当地市场和个人水平调整
